# 空间指标与现有数据清单

本文记录当前代码中已经存在的 POI、人口、路网、夜光和 H3 数据，不把规划中的字段写成已具备能力。机器可读的指标语义目录位于 `skills/spatial-business-analyst/references/metric-catalog.yaml`；本文用于让研究人员、报告编写者和 N8N 维护者看懂系统实际有什么、能够怎样查询，以及这些数据不能证明什么。

## 1. 盘点口径

- `原始/项目记录`：可以回溯到当前项目保存的数据记录或栅格单元，是事实层。
- `后端计算指标`：由 Python、depthmapX 或 ArcGIS 稳定计算并进入 API 结果。
- `前端派生指标`：浏览器根据后端结果和当前批次阈值计算；改变范围、分类或阈值后必须重算。
- `代理指标`：可以支持空间关系判断，但不能直接改写为真实需求、客流、消费、经营绩效或因果关系。
- `运行时可用`：支持的年份和字段不等于当前机器一定装有数据文件；人口以运行时文件检查为准，夜光以 `manifest.json` 和 `/meta` 返回为准，POI 以项目已保存年份为准。

## 2. 当前数据接入状态

| 数据 | 系统内部数据源 | 几何 | 当前 N8N `query_data` | 主要时间口径 |
| --- | --- | --- | --- | --- |
| POI | `current:dataset:poi` | Point | 可逐条查询和聚合 | 已保存年份；来源为 `gaode` 或 `local` |
| POI H3 | `current:dataset:h3` | Polygon | **不可逐格查询**；仅在已持久化时作为计算结果进入上下文 | 跟随 POI 年份和本次 H3 参数 |
| POI 规则栅格 | `current:dataset:poi_grid` | Polygon | **不可逐格查询** | 跟随 POI 年份 |
| 路网节点 | `current:dataset:road_nodes` | Point | 可逐条查询和聚合 | 当前路网模型，不是年度观测 |
| 路网线段 | `current:dataset:road_edges` | LineString | 可逐条查询和聚合 | 当前路网模型，不是年度观测 |
| 路网共享栅格 | `current:dataset:road_grid` | Polygon | **不可逐格查询** | 当前路网模型 |
| 人口 | `current:dataset:population` | Polygon | 可逐条查询和聚合 | 支持 2024、2025、2026；默认 2026，实际以文件检查为准 |
| 夜光 | `current:dataset:nightlight` | Polygon | 可逐条查询和聚合 | 由夜光 `manifest.json` 决定可用年份和默认年份 |

当前 N8N 的统一项目数据入口只暴露五个 `dataset_id`：`poi`、`road_nodes`、`road_edges`、`population`、`nightlight`。H3、POI 规则栅格和路网共享栅格虽然存在于范围数据层，但尚未加入 `ProjectDataContractService.DATASET_SOURCES`。报告不能声称章节模型已经读取了这些网格的完整逐格记录。

## 3. POI 数据

### 3.1 项目记录字段

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `poi_id` | POI 稳定标识 | 同一批数据内要求唯一 |
| `name` | 设施名称 | 可用于具名设施核查 |
| `category` | 中文主类 | 必须是命名类别，不能只存数字编码 |
| `subcategory` | 中文子类 | 用于细分供给结构 |
| `typecode` | 六位 POI 类型编码 | 由统一分类表归一化 |
| `address` | 地址 | 可能为空字符串，但字段必须存在 |
| `location` | `[lng, lat]` | 项目查询契约统一按 WGS84 输出 |
| `year` | 数据年份 | 跨年比较必须保持来源、范围和分类口径一致 |
| `source` | 数据来源 | 当前为 `gaode` 或 `local` |

### 3.2 已有 POI 汇总和网格字段

| 层级 | 已有数据或指标 | 计算口径 |
| --- | --- | --- |
| 范围总量 | `count`、`poi_count` | 当前范围内去重后的记录数 |
| 分类结构 | `category_counts`、`category_summary` | 按统一类型表或请求中的分类规则计数 |
| 多年份 | `results_by_year`、`summary_by_year.count`、`summary_by_year.category_counts` | 同一来源、范围和分类口径下按年份返回 |
| 规则栅格 | `cell_id`、`poi_count`、`area_km2`、`density_poi_per_km2`、`category_counts` | POI 点分配到人口/夜光共同规则栅格 |
| 栅格主类 | `dominant_category`、`dominant_category_name` | 单元内数量最多的 POI 类别 |
| 栅格汇总 | `grid_count`、`active_cell_count`、`assigned_poi_count`、`max_poi_count`、`avg_density_poi_per_km2`、`top_cells` | `assigned_poi_count` 只统计成功落入网格的 POI |
| 核密度 | 前端 POI 热力图 | 已实现可视化代理，不是后端保存的统一核密度数值字段 |

POI 密度公式为：

```text
density_poi_per_km2 = poi_count / area_km2
```

POI 可以支持设施供给、类别结构、具名节点和空间集聚判断；不能单独证明需求量、真实客流、营业状态、消费能力、入住率、饱和度或商业机会。

## 4. 人口数据

### 4.1 底层人口栅格

- 数据源标识：`WorldPop`。
- 文件命名口径：`CN_100m`，即 100 米人口栅格产品。
- 支持年份：2024、2025、2026；默认 2026。
- 性别：总人口、男性、女性。
- 年龄组：全年龄、0 岁、1-4、5-9、10-14、15-19、20-24、25-29、30-34、35-39、40-44、45-49、50-54、55-59、60-64、65-69、70-74、75-79、80-84、85-89、90 岁及以上。
- `total/all` 由男性总人口与女性总人口两层相加；全年龄主文件不可用时，代码可以按各年龄层求和恢复。

### 4.2 N8N 项目人口记录

为了控制 Agent 查询宽度，项目数据契约没有暴露每个五岁年龄层，而是暴露以下字段：

| 字段 | 含义 | 单位/口径 |
| --- | --- | --- |
| `cell_id` | 共同规则栅格标识 | 与 POI、夜光和路网共享栅格对齐 |
| `geometry` | 单元边界 | WGS84 Polygon |
| `year` | 人口年份 | 2024、2025 或 2026 |
| `population_total` | 单元总人口 | 人 |
| `age_5_19` | 5-19 岁人口 | 5-9、10-14、15-19 三层之和 |
| `age_30_39` | 30-39 岁人口 | 30-34、35-39 两层之和 |
| `age_50_64` | 50-64 岁人口 | 50-54、55-59、60-64 三层之和 |
| `source` | 数据源 | `WorldPop` |

### 4.3 已有计算结果

| 层级 | 已有数据或指标 |
| --- | --- |
| 范围概览 | `total_population`、`male_total`、`female_total`、`male_ratio`、`female_ratio` |
| 年龄结构 | 每个年龄组的 `total`、`male`、`female` |
| 指定图层 | `selected_population`、`selected_ratio_of_total`、`nonzero_pixel_count`、`max_pixel_value` |
| 网格 | `cell_count` 和逐格人口记录 |
| 图层视图 | 人口密度、男性/女性密度、指定年龄组比例或优势年龄组 |
| 时间序列 | 人口变化、人口密度变化、年龄结构变化；只在多个同口径年份均存在时成立 |

空间裁剪时可使用 `area_weighted_sum`：按单元与查询范围的重叠比例分配人口，前提是假设单元内部人口均匀分布。人口数据支持潜在人群规模和年龄结构代理，不能证明项目实际使用者、实际到访、就业身份、消费意愿或复访行为。

## 5. 路网数据

### 5.1 分析参数

- 交通方式：步行、骑行、驾车。
- 图模型：`segment` 或 `axial`。
- 道路过滤：按交通方式、全部道路或主要道路。
- 默认局部半径：600 米和 800 米，可传入其他米制半径。
- 主要计算引擎：`depthmapXcli`；专题渲染可选 ArcGIS bridge。

### 5.2 路网节点和线段字段

| 数据 | 字段 |
| --- | --- |
| 路网节点 | `node_id`、`location`、`geometry`、`degree` |
| 路网线段 | `edge_id`、`road_name`、`road_class`、`from_node`、`to_node`、`length_m`、`geometry`、`metrics` |
| 线段 `metrics` | `integration`、`choice`、`connectivity`、`depth`、`control` |

### 5.3 路网汇总和诊断指标

| 指标组 | 已有字段 |
| --- | --- |
| 网络规模 | `node_count`、`edge_count`、`rendered_edge_count`、`edge_merge_ratio`、`network_length_km` |
| 基础拓扑 | `avg_degree`、节点 `degree`、`degree_score` |
| 中心性 | `avg_closeness`、`avg_choice`、`avg_integration_global`、`avg_choice_global` |
| 局部句法 | `avg_integration_local`、`avg_choice_local`、`avg_integration_by_radius`、`avg_choice_by_radius` |
| 句法扩展 | `avg_connectivity`、`avg_control`、`avg_depth`、`avg_accessibility_global` |
| 可理解度 | `avg_intelligibility`、`avg_intelligibility_r2`；诊断中另有回归 `slope`、`intercept`、`r`、`r2`、`n` |
| 数据有效性 | `control_source_column`、`control_valid_count`、`depth_source_column`、`depth_valid_count` |
| 方向结构 | `road_orientation_analysis`，包括各方向的线段数、长度和占比 |

### 5.4 路网共享栅格

路网线段会按与人口、POI、夜光相同的规则栅格聚合，已有字段为：

`cell_id`、`road_has_data`、`road_length_km`、`road_length_km_per_km2`、`road_segment_count`、`road_choice`、`road_integration`、`road_connectivity`、`road_control`、`road_depth`。

其中五个句法指标按线段与单元相交长度加权平均。汇总另有 `cell_count`、`covered_cell_count`、`network_length_km` 和各指标 `metric_ranges`。当前 N8N 不能通过 `query_data` 逐格读取 `road_grid`，只能读取节点、线段和已持久化摘要。

路网句法可以支持潜在穿行性、网络中心性、连接结构和方向判断，不能直接证明人行环境质量、实际步行量、道路安全、入口可见性、遮阴、过街舒适度或无障碍条件。

## 6. 夜光数据

### 6.1 数据集与项目记录

- 可用年份、默认年份、文件、变量和单位由夜光目录下的 `manifest.json` 决定，不能在文档中硬编码为固定年份。
- 默认变量名：`NearNadir_Composite_Snow_Free`。
- 标准单位：`nWatts/(cm^2 sr)`；项目数据契约等价写为 `nW/(cm2 sr)`。

| 字段 | 含义 |
| --- | --- |
| `cell_id` | 共同规则栅格标识 |
| `geometry` | WGS84 Polygon |
| `year` | 夜光数据年份 |
| `radiance` | 单元内按像元重叠面积加权的平均辐亮度 |
| `unit` | 辐亮度单位 |
| `has_data` | 单元是否包含有效像元 |
| `source` | 数据源标识 |

### 6.2 已有夜光指标

| 指标组 | 已有字段 |
| --- | --- |
| 范围概览 | `total_radiance`、`mean_radiance`、`max_radiance`、`p90_radiance` |
| 覆盖情况 | `valid_pixel_count`、`lit_pixel_count`、`lit_pixel_ratio` |
| 热点分级 | 核心热点、高亮热点、次级热点、过渡区、低亮区及各类单元数量 |
| 热点汇总 | `hotspot_cell_ratio`、`peak_radiance`、`peak_cell_id` |
| 梯度结构 | `max_distance_km`、`core_band_count`、`middle_band_count`、`fringe_band_count`、`peak_to_edge_ratio` |
| 方向结构 | 八方向 `total_radiance`、`mean_radiance`、`cell_count`、`hotspot_count`、`radiance_share`，以及主方向、次方向和占比 |
| 活动强度代理 | `economic_activity_intensity_level`：`low`、`medium`、`medium_high`、`high` |
| 图层视图 | `radiance`、`hotspot`、`gradient` |
| 时间序列 | 夜光变化、热点迁移；只在多个同口径年份均存在时成立 |

夜光“经济活动强度等级”由平均值、P90、亮灯比例、热点比例和峰缘比的阈值规则合成，是相对代理，不是 GDP、营收、夜间客流、消费金额或营业时长。

## 7. H3 与空间统计数据

### 7.1 H3 网格参数和基础字段

- H3 分辨率允许 0-15；纯网格接口默认 9，H3 指标接口默认 10。
- 范围纳入方式：`intersects` 或 `inside`。
- `intersects` 可设置 `min_overlap_ratio`。
- 邻域圈数允许 1-3；ArcGIS KNN 映射为 6、18、36 个邻居。
- H3 计算在 WGS84 上进行；用于高德地图显示时可转为 GCJ-02。

每个 H3 单元已有以下后端字段：

| 字段 | 含义/公式 |
| --- | --- |
| `h3_id` | H3 单元标识 |
| `poi_count` | 分配到该单元的 POI 数量 |
| `density_poi_per_km2` | `poi_count / H3单元面积(km²)` |
| `category_counts` | 统一 POI 类别计数 |
| `subcategory_counts` | 原始类型文本计数 |
| `local_entropy` | 香农熵 `-Σ(p × ln p)` |
| `neighbor_mean_density` | 指定邻域圈内其他单元平均 POI 密度 |
| `neighbor_mean_entropy` | 指定邻域圈内其他单元平均熵 |
| `neighbor_count` | 实际参与邻域计算的单元数 |
| `lisa_i`、`lisa_z_score` | ArcGIS 局部 Moran 结果 |
| `gi_star_value`、`gi_star_z_score` | ArcGIS Getis-Ord Gi* 结果 |

### 7.2 H3 汇总和图表

| 类型 | 已有字段 |
| --- | --- |
| 总体 | `grid_count`、`poi_count`、`avg_density_poi_per_km2`、`avg_local_entropy` |
| 全局空间自相关 | `global_moran_i_density`、`global_moran_z_score` |
| 连续统计 | Gi* Z 和 LISA I 的 `count`、`mean`、`std`、`min`、`max`、`p10`、`p50`、`p90` |
| 渲染信息 | `gi_render_meta`、`lisa_render_meta`、`arcgis_report_maps` |
| 图表 | POI 类别分布、密度直方图 |

### 7.3 前端派生指标

以下结果已经实现，但不是后端稳定事实字段：

- 归一化熵：`local_entropy / ln(当前类别数)`，并限制到 0-1；POI 数不足时为无数据。
- 邻域密度差：`density_poi_per_km2 - neighbor_mean_density`。
- 四象限分型：以本次结果的密度 P70 和归一化熵 P70 为阈值，得到高密高混合、高密低混合、低密高混合、低密低混合。
- 机会标记：当前规则为“高密高混合且邻域密度差大于 0”。它只是筛选标记，不是商业机会事实。
- LQ：使用 0.5 平滑系数比较单元类别占比与全范围类别占比；POI 样本不足时不计算。
- 结构信号：取 `|Gi* Z|` 与标准化后的 LISA 偏离强度中的较大者；当前阈值大于 1。
- Gap 分数：先用交通、生活、教育、医疗类别密度加权形成需求代理，再计算需求代理百分位减目标供给密度百分位。该结果依赖当前类别映射和权重，只能用于相对排序。
- 置信提示：单元 POI 数小于 5 为低，5-9 为中，10 及以上为高；这是样本量提示，不是统计置信区间。

H3 可以识别相对密度、混合度、空间聚集和局部差异，不能证明需求、消费、真实客流、因果机制或项目经营可行性。

## 8. N8N 可执行的确定性聚合

`query_data` 支持 `records` 和 `aggregate` 两种操作，单次记录页最多 500 条；未读完时返回 `continue_token`。通用聚合包括 `count`、`sum`、`avg`、`min`、`max`，当前 N8N 数据契约还允许 `area_weighted_sum` 和 `area_weighted_avg`。底层范围数据服务另有道路相交长度求和，但它尚未加入 N8N 这一个语义入口。

工作流当前默认使用：

| 数据 | 默认聚合 |
| --- | --- |
| POI | 按 `category` 分组计数 `poi_count` |
| 路网线段 | 按 `road_class` 分组，计算 `edge_count` 和 `length_m_sum` |
| 人口 | 计算 `cell_count`、`population_total`、`age_5_19`、`age_30_39`、`age_50_64` |
| 夜光 | 计算 `cell_count`、`radiance_avg`、`radiance_min`、`radiance_max` |

每次查询还返回 `snapshot_id`、`dataset_checksum`、`result_checksum`、`total_count`、`complete`、空间诊断和警告，用于确认结果是否完整和可复现。这些是追溯字段，不是业务指标。

## 9. 当前没有的数据和结论边界

以下内容不属于上述数据库的现有事实，报告不得因为缺少它们而停止分析，也不得由模型补造：

- 建筑权属、文保法定身份、逐栋面积、结构安全、机电、消防、疏散和无障碍核验结果。
- 现场实际客流、进入率、停留时间、复访率、付费意愿和消费金额。
- 商户真实经营数据、租金、成本、合同、运营商承诺和资金批复。
- POI 对应设施的实时营业、空置、质量、容量和经营绩效。
- 路网对应的实际步行量、过街安全、遮阴、入口可见性和步行舒适度。
- 夜光对应的 GDP、营收、具体活动类型或单体项目夜间经营表现。
- POI 开闭店率已接入跨年 POI 实体匹配；只有存在至少两个同源年份快照时才计算，否则返回 `unavailable`。当前系统仍未提供步行绕行系数，因此不得用直线距离替代。

正确写法是基于现有数据给出条件性判断，例如：“现有 POI、人口和路网数据支持该方向具有较强的潜在服务联系，但不能由此推出实际到访量。”未知只降低结论强度，不自动生成“必须补齐证据”清单。

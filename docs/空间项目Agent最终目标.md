# 空间项目 Agent 最终目标

## 1. 文档目的

本文件定义项目要形成的产品、服务对象、核心能力、交付成果和完成标准。产品设计、能力取舍和成果验收都应以本文件为共同目标。

本文件聚焦产品目标、使用者价值、交付成果和验收标准，供产品、业务和项目团队共同使用。

## 2. 产品定位

项目要形成一套可供 Codex、ChatGPT 等 AI 调用的空间项目数据与决策系统。系统围绕一个明确的分析范围，统一管理空间数据、项目资料、分析结果、证据和成果版本。AI 可以按任务查询数据、开展专业分析，并取得可供人员审阅和交付的成果。

产品服务三类使用者：

- 策划、规划和商业分析人员使用数据与证据完成专业判断；
- 项目负责人和甲方决策者审阅方案、确认方向并使用交付成果；
- AI 助手调用项目数据和专业能力，完成查询、分析与成果生成。

系统需要保留分析过程中的证据、限制和待验证事项。使用者应当能够判断结论来自哪里、适用于什么范围，以及哪些条件会改变结论。

## 3. 数据主体

每个项目都应拥有一套经过确认的数据主体，覆盖分析范围内的 POI、人口、夜光、路网、分析格网、空间单元、项目资料和外部证据。项目可以按需要补充消费、客流、租金、经营、权属、规划条件和现场调查等资料。

每类数据都需要说明：

- 数据对应的空间范围和时间；
- 数据来源、口径和使用限制；
- 数据质量、覆盖情况和已知缺口；
- 数据与分析范围、空间单元及其他数据之间的关系。

系统保留项目锁定版本中的完整数据。AI 根据任务读取数据目录、统计结果、异常记录和具体对象，避免把大体量明细当作一段背景材料处理。

本文所称“全部数据”，指项目在某个锁定版本中已经收集、处理并登记的数据。这个概念不代表供应商数据库或现实世界中的绝对全集。数据采集出现截断、缺失或覆盖不足时，系统必须保留说明。

## 4. ESRI Business Analyst 风格商业报告

Agent 应能够围绕商圈范围、市场潜力、供需缺口、机会业态、竞争关系、客群匹配和选址适配形成商业分析报告。报告采用 Business Analyst 常见的分析问题和成果结构，使用项目已经获得的数据和证据。

报告需要说明各项分析的证据条件和结论等级。证据充足的部分可以形成方向性结论；证据不足的部分应标明受限、暂不适用或需要补充验证。只有接入并获得授权的官方数据时，报告才标注相应的官方来源。

商业报告必须遵守以下边界：

- 人口只能作为需求基础，不能直接代表消费能力；
- 夜光只能作为活动代理指标，不能直接代表销售额或客流；
- POI 数量只能说明供给存在和空间分布，不能直接代表经营表现；
- 未经校准的竞争分析不能表述为真实市场份额；
- 缺少租金、门面、可见性和现场条件时，选址结论只能作为前期筛选意见。

最终报告应让策划团队和甲方看清分析范围、主要判断、支持证据、数据缺口、风险及下一步验证工作。使用者可以阅读、复核、引用和继续讨论报告内容。

## 5. 全部空间单元策划

项目需要先建立一份经过确认的空间单元清单。空间单元可以是地块、建筑、庭院、街区、节点或其他由项目定义的空间对象。每个单元都需要稳定名称、明确边界和可追溯来源。

Agent 应为清单中的每个合格空间单元给出明确状态。系统必须登记已经完成策划的单元、因条件不成立而排除的单元，以及因资料不足而受阻的单元。任何单元都不能从成果中静默消失。

每个单元的策划成果应包括：

- 现状特征、问题和限制；
- 目标角色、服务人群和项目价值；
- 候选功能、首选方案和排除方向；
- 动线、运营、改造和实施时序要求；
- 风险、成立条件、证据和验证事项。

项目层面的策划成果还需要检查不同单元之间的功能分工、空间联系、公共价值、运营关系和整体组合。单元建议应共同服务项目定位，避免各单元独立生成后出现功能重复、动线冲突或实施顺序矛盾。

## 6. 甲方汇报 PPT

Agent 应根据经过人工审定的报告和策划成果生成甲方汇报 PPT。人工审定是正式成果进入汇报阶段的必要条件。Agent 不能把草稿、待验证假设或过期成果直接包装成甲方结论。

PPT 应围绕甲方需要理解、判断和批准的事项组织内容。每页需要承担明确的沟通任务，帮助甲方理解项目条件、分析依据、方案选择、空间安排、风险和行动要求。

最终交付包括可编辑的 PPTX、便于审阅的预览文件、证据附录和逐页来源。每个关键结论、指标、地图和图表都应能够追溯到项目数据或项目资料。使用者可以修改文字和页面，完成正式汇报，并在会后继续使用成果。

## 7. 统一成果链路

用户按照以下顺序形成项目成果：

1. 确定分析范围、任务要求、资料和空间单元；
2. 检查数据来源、时间、覆盖情况和缺口，确认本轮使用的数据版本；
3. 由 Agent 基于同一数据版本生成商业报告和全空间单元策划；
4. 由专业人员和项目负责人审定核心判断、推荐方向及待验证事项；
5. 由 Agent 使用审定成果生成甲方汇报 PPT，并保存报告、策划和汇报材料之间的来源关系。

上游数据发生变化时，系统保留已有成果及其依据，并提示使用者重新审查受影响的结论。新成果不能覆盖旧成果所代表的历史判断。

## 8. 成果质量与责任边界

系统应区分项目事实、计算结果、外部参考、专业推断和待验证假设。每项重要结论都需要对应证据、适用范围和限制条件。

数据缺失会降低结论等级。Agent 应说明缺少什么、缺口影响哪些判断，以及需要谁采用什么方式完成验证。Agent 不得用模型生成内容填补缺失的项目事实，也不得输出没有来源的营收、客流、销售、投资回报或市场份额。

Agent 为专业人员提供数据整理、分析和成果生成能力。专业人员和项目负责人负责审定项目判断，甲方负责作出最终决策。

## 9. 完成标准

项目达到以下条件后，才能视为实现本文件定义的产品目标：

- AI 可以在独立的项目上下文中识别项目并调用项目能力；
- 使用者可以查看本轮数据的范围、时间、来源、质量和缺口；
- Agent 可以分别生成商业报告、全空间单元策划和甲方汇报 PPT；
- 每个合格空间单元都有策划结果或明确的排除、受阻记录；
- 报告和 PPT 中的重要结论能够回溯到具体证据；
- 数据不足时，Agent 会降低结论等级并保留验证任务；
- 系统可以生成可下载、可审阅和可继续编辑的正式文件；
- 上游数据变化后，使用者可以识别需要重新审查的成果；
- 甲方拿到成果后，可以完成阅读、修改、汇报和后续决策。

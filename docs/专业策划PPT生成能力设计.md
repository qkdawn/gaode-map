# 专业策划 PPT 生成能力设计草案

## 1. 背景与目标

当前系统已经具备区域空间分析能力，能够围绕一个已选区域形成范围、POI、H3 网格、人口、夜光、路网、共享网格和 Agent 总结等结构化结果。

下一阶段希望基于这些区域结果，生成类似城市更新、概念策划、招商研判类项目中的专业 PPT 成果。目标不是生成普通数据报表，也不是把现有总结小卡片简单导出，而是形成一份有叙事、有证据、有图片、有地图、有章节节奏，并且能够经过人工多轮调整后再定稿的策划型汇报材料。

本能力的第一阶段重点是生成可编辑的“PPT 指令文件”和逐页生成指令，而不是直接生成最终 PPTX。前端如何从现有分析工作台过渡到 PPT 生成工作流尚未完全定稿，因此本文先沉淀输入、输出、流程和分阶段实现边界。

## 2. 核心原则

1. AI 不应在事实和结构未确认时直接跳到最终 PPTX。
2. AI 先生成可编辑的 PPT 指令文件和逐页页面脚本。
3. 用户确认指令文件后，再选择或生成“风格 Skill”，由 AI 根据指令文件和风格 Skill 生成页面。
4. 页数、主题、受众、深度都属于配置项。
5. 所有事实必须来自已选来源背后的 EvidenceNode，包括区域数据、文档、图片、网页、数据库或资料包。
6. 资料入口统一收敛到左侧来源区；PPT 生成流程只消费已选 Source，不直接消费附件、网页预览或临时 payload。
7. 联网资料必须带来源引用，不能作为无来源判断。
8. 前端承载方式待定，不在第一阶段强行改总结面板。

## 3. 用户流程

1. 用户选择一个已有分析区域。
2. 用户在来源区选择已有成果、背景文件、图片、网页、数据库或资料包，并配置策划主题、页数、汇报类型、目标受众和生成深度。
3. 系统整理输入包，包括等时圈区域数据、地图和图层快照、文档来源、图片来源、网页来源、数据库来源和资料包来源。
4. AI 生成第一版 PPT 指令文件，指令文件包含逐页主题、标题、核心文案、页面提示词和素材要求。
5. 用户和 AI 多轮沟通修改指令文件，包括改主题、改目录、改页数、改页面论点、指定图片来源、补充来源和调整引用。
6. 用户确认指令文件后，进入风格选择或风格生成阶段。
7. AI 根据指令文件和风格 Skill 生成 HTML 幻灯片页面，用户预览和修改后再导出 PPTX。

这个流程的关键点是：最终页面生成之前，先让用户确认指令文件；视觉风格作为独立层处理，不和资料理解、论点生成混在一起。AI 可以生成页面样式，但应在明确的指令文件和风格 Skill 约束下生成。

### 3.1 从背景文件到指令文件再到 PPT 的生成链路

本能力的核心链路应明确为：

```text
已选 Source + 等时圈区域数据
-> AI 生成 PPT 指令文件
-> 选择/生成风格 Skill
-> AI 根据指令文件和风格 Skill 生成页面
-> 预览与修改
-> 导出 PPTX
```

其中“PPT 指令文件”是核心中间产物。它不是最终 PPT，也不是普通报告文本，而是系统生成的逐页生成说明。每一页应说明：页码、页面主题、标题、核心文案、页面提示词、需要使用的证据和素材。

这样做的原因是：专业策划 PPT 的难点不只是排版，而是先把叙事顺序、页面论点、素材选择和视觉提示确定下来。指令文件先定稿，风格 Skill 再约束页面表达，最终 PPT 才有稳定的生成依据，同时保留 AI 生成专业视觉样式的空间。

### 3.2 三类输入来源

PPT 生成不应只消费用户上传文件，也不应只消费地图分析结果，而应合并三类输入。

1. 用户添加的文档 / 图片来源。
   包括项目基本情况、改造愿景、服务建议书、初步交流材料、已有成果 PPT、现场图片、规划图和其他材料。这类资料完成解析后必须成为 `document source` 或 `image source`，再提供项目事实、业主诉求、历史文化线索、空间策略和已有表达成果。

2. 系统区域数据。
   包括已选等时圈范围、地图快照、POI、人口、夜光、路网、共享网格、H3 分析、Agent 总结和前端结构化分析摘要。这是本产品区别于普通 PPT 生成工具的关键创新点：PPT 的判断不只来自文档，还来自用户已经在地图上选定的真实区域和对应数据。

3. 用户生成目标。
   包括页数、受众、汇报类型、汇报深度、是否需要联网来源、是否优先使用图片来源、是否需要导出 PPTX，以及后续选择或生成的风格 Skill。这些目标决定指令文件的叙事密度和最终 PPT 的表达方式。

### 3.3 正常输入资料映射

正常使用时，用户不会提供指令文件。PPT 指令文件是系统根据背景资料和等时圈区域数据生成的中间产物，而不是用户必须上传的输入文件。

以“长沙县政府原址城市更新”这组资料为例，正常用户输入应按以下方式理解：

| 样例资料 | 在系统中的作用 |
| --- | --- |
| 项目基本情况、改造愿景、服务建议书、初步交流材料 | 背景事实和策划依据，提供项目区位、历史属性、建筑规模、现状问题、空间结构和运营方向。 |
| 已有成果 PPT | 已有项目表达和阶段性成果，作为背景资料进入系统；不等同于固定版式或视觉参考。 |
| 当前等时圈区域数据 | 系统自产空间证据，包括范围、周边资源、客群、活力、交通、网格耦合和地图快照。 |

普通 PPT 生成工具通常只消费上传文件。本系统的创新点是同时消费已选来源和等时圈内的真实空间分析数据，因此生成的指令文件能够把项目叙事、来源事实和区域数据证据合在一起。

## 4. PPT 生成配置

PPT 生成配置应作为独立输入，而不是散落在提示词里。推荐字段如下：

| 字段 | 含义 | 默认建议 |
| --- | --- | --- |
| `theme` | 本次策划主题，由用户输入 | 空，由用户填写 |
| `deck_type` | 汇报类型，例如城市更新策划、商业选址研判、区域诊断报告 | `urban_renewal` |
| `page_count` | 目标页数，是配置项，不是固定值 | 15 |
| `depth` | 生成深度，例如快速简报、初步成果、完整汇报 | `brief` |
| `audience` | 目标受众，例如政府评审、招商方、内部研讨、课程展示 | `government_review` |
| `source_ids` | 本次使用的已选来源 ID | 空数组 |
| `web_source_policy` | 是否允许从来源区新增或使用联网来源 | `allow_selected` |
| `visual_policy` | 图片使用策略，例如优先图片来源、优先地图快照、缺图时输出图片需求提示 | `prefer_image_source` |

配置 schema 可以表达为：

```json
{
  "theme": "用户输入的策划主题",
  "deck_type": "urban_renewal | site_selection | area_diagnosis",
  "page_count": "number",
  "depth": "brief | preliminary | full",
  "audience": "government_review | investment | internal | education",
  "source_ids": ["source_id"],
  "web_source_policy": "disabled | allow_selected | allow_create_from_sources_panel",
  "visual_policy": "prefer_image_source | prefer_map_snapshot | prompt_when_missing"
}
```

其中 `page_count` 的默认值可以是 15，但实现和提示词都不能把 15 页写死。

## 5. 页数配置规则

页数影响目录深度和叙事密度，应由配置驱动。

| 页数范围 | 适用形态 | 叙事重点 |
| --- | --- | --- |
| 6-10 页 | 区域诊断简报 | 快速说明范围、关键数据、核心判断和下一步 |
| 11-18 页 | 策划简报 | 默认推荐形态，覆盖背景、研判、定位、策略和下一步 |
| 19-30 页 | 初步成果汇报 | 增加案例、竞品、功能分区、运营路径和阶段策略 |
| 30 页以上 | 完整成果汇报 | 需要用户先确认章节目录或参考目录 |

当 `page_count` 采用默认值 15 时，可以使用本文第 11 节的默认结构。若用户选择其他页数，系统应先根据配置动态生成目录，再进入逐页指令生成。

## 6. AI 输入包

AI 输入应被整理为稳定的证据包，而不是把所有原始数据直接塞进提示词。

### 6.1 区域数据

区域数据来自当前分析工作台已有结果，主要包括：

- 分析范围、等时圈或绘制区域。
- POI 总量、分类结构、主导业态和数据来源。
- H3 网格分析、热点、冷点、空间集聚和机会格。
- 人口总量、密度、年龄结构、性别结构和客群线索。
- 夜光总量、均值、P90、点亮率、热点和夜间活力判断。
- 路网节点、边、道路长度、空间句法指标和可达性判断。
- POI、人口、夜光等多维共享网格耦合结果。
- 前端结构化分析摘要。

### 6.2 视觉素材

视觉素材是专业 PPT 的关键输入，应与文本证据分开管理。

可用素材包括：

- 当前地图总览快照。
- POI 图层快照。
- H3 网格图层快照。
- 人口图层快照。
- 夜光图层快照。
- 路网图层快照。
- 图片来源中的现场图片、规划图、效果图、已有成果 PPT 页面、项目照片。

AI 不应在资料整理阶段直接决定最终排版，但可以在指令文件中声明某页需要使用哪个素材，或者说明缺少哪类素材。最终页面样式由后续风格 Skill 约束。

### 6.3 来源素材库

来源区是统一入口。PPT 生成流程只消费已添加、已构建并被用户选择的 Source。

文档、图片、网页、数据库或资料包完成构建后应整理为来源素材库，而不是作为聊天附件、临时搜索结果或右侧工作区 payload 并列存在。建议分为：

- `text_evidence`：政策、历史、定位、案例、说明文字。
- `visual_assets`：现场照片、效果图、地图、已有成果页截图。
- `data_tables`：人口、消费、租金、竞品、业态等表格。

每个素材至少记录：

- 素材 ID。
- `source_id`。
- 来源标题。
- 页码或图片编号。
- 素材类型。
- 简短摘要。
- 适用页面或适用章节。
- 来源可信度。
- 是否必须引用。

AI 在输出中引用素材 ID 和 `source_id`，例如“使用 `image:site-photo` 下的 `asset_012` 作为红砖建筑外立面图片”，最终页面生成阶段再由 AI 按风格 Skill 调用真实图片、地图和图表。

### 6.4 联网来源

联网来源默认可用，但必须可追溯，并最终沉淀为来源区中的 `web source`。

联网资料应包含：

- URL。
- 标题。
- 发布日期或访问日期。
- 摘要。
- 可支持的页面或论点。
- 证据用途。

联网内容主要用于：

- 城市背景。
- 政策背景。
- 商圈资料。
- 人口和消费资料。
- 城市更新、文旅、商业策划案例。
- 竞品或周边项目参考。

联网资料不能替代本地分析结果，也不能覆盖文档 / 图片来源中的明确项目事实。

## 7. 联网与来源的证据优先级

建议证据优先级如下：

1. 用户明确选择的项目文档 / 图片来源。
2. 当前区域分析产生的结构化数据。
3. 用户选择的已有成果文件和现场素材来源。
4. 带来源的联网资料。
5. AI 的归纳、类比和策划表达。

其中第 5 类只能用于组织表达和形成策略推演，不能作为事实来源。

## 8. AI 输出：PPT 指令文件

AI 第一阶段输出“PPT 指令文件”，不是 PPTX 文件。技术结构可以继续使用 `deck_brief` 或类似 JSON 字段承载，但面向用户的产品文案应使用“指令文件”“逐页指令”或“页面脚本”，避免直接显示技术字段名。

推荐输出结构：

```json
{
  "deck_config": {},
  "deck_outline": [
    {
      "section": "章节名称",
      "page_range": "页码范围",
      "purpose": "章节目的"
    }
  ],
  "pages": [
    {
      "page_no": 1,
      "section": "章节名称",
      "theme": "页面主题",
      "title": "页面标题",
      "core_copy": "本页核心文案",
      "page_prompt": "页面提示词，用于指导后续生成页面",
      "claim": "本页核心判断",
      "body_points": ["页面要点"],
      "evidence_refs": ["证据引用"],
      "asset_refs": ["素材引用"],
      "map_data_refs": ["等时圈、POI、人口、夜光、路网等区域数据引用"],
      "image_prompt": "缺少图片时需要补充的图片需求提示",
      "layout_hint": "建议版式",
      "missing_inputs": ["待补充资料"]
    }
  ],
  "source_bibliography": [
    {
      "source_id": "来源 ID",
      "title": "来源标题",
      "url": "来源链接",
      "used_for": "使用位置"
    }
  ],
  "revision_notes": ["本轮修改说明"]
}
```

其中关键字段含义如下：

| 字段 | 含义 |
| --- | --- |
| `page_no` | 页码。 |
| `theme` | 页面主题，例如文化主线、叙事空间、业态原则。 |
| `title` | 页面标题。 |
| `core_copy` | 页面核心文案，可直接进入 PPT 或作为标题下的主表达。 |
| `page_prompt` | 页面提示词，用于指导后续 HTML/PPT 页面生成。 |
| `evidence_refs` | 来自背景资料、联网资料或系统数据的文字证据引用。 |
| `asset_refs` | 需要使用的图片来源、已有成果页、现场图、规划图等素材引用。 |
| `map_data_refs` | 需要使用的等时圈、地图快照、POI、人口、夜光、路网、共享网格等区域数据引用。 |
| `missing_inputs` | 该页仍缺少的资料、图片或用户确认项。 |

`page_prompt` 和 `image_prompt` 的作用不是在第一阶段直接生成最终页面，而是告诉后续页面生成系统：这一页需要怎样的画面、地图、现场图、图表或效果图。

## 9. 人工迭代机制

第一阶段的交互对象是 PPT 指令文件和逐页页面脚本。

用户可以逐轮提出：

- 改主题。
- 改页数。
- 改目录。
- 删除某页。
- 增加某页。
- 强化某类证据。
- 指定使用某个图片来源。
- 要求联网补充某类资料。
- 调整汇报对象和表达口吻。

每轮 AI 应输出：

- 更新后的目录。
- 更新后的页面脚本。
- 修改摘要。
- 仍缺失的素材或资料。
- 需要用户确认的问题。

只有当用户确认“内容定稿”后，才进入最终页面渲染。

## 10. 风格 Skill 层

风格生成应从指令文件中解耦出来。指令文件负责回答“每一页讲什么、用什么证据、需要什么素材”，风格 Skill 负责回答“这一组页面如何被设计出来”。

风格 Skill 可以有两种来源：

1. 用户从后续的 Skill 市场中选择。
2. AI 根据项目类型、受众和用户偏好生成一个临时风格 Skill。

风格 Skill 不等同于一套固定版式。它更像一组可执行的视觉和排版规则，用来约束 AI 生成页面，避免每页风格散乱，同时保留 AI 自由设计专业页面的能力。

建议风格 Skill 包含：

- `style_name`：风格名称。
- `design_principles`：整体设计原则，例如政府汇报、城市更新、文化策划、招商路演等语气。
- `typography`：标题、正文、数字、注释的字号层级和字体倾向。
- `color_system`：主色、辅助色、风险色、地图和数据图表配色规则。
- `layout_rules`：封面、章节页、地图页、数据页、策略页、结论页的布局原则。
- `visual_asset_policy`：现场图、地图、效果图、图表和已有成果截图的使用规则。
- `map_rendering_policy`：地图快照、等时圈、POI、H3、路网等空间数据在 PPT 中的呈现方式。
- `slide_quality_rules`：文字密度、留白、对齐、可读性、引用展示和移动端预览约束。

后续页面生成时，AI 的输入应至少包含：

```text
PPT 指令文件 + 风格 Skill + 可用素材清单 + 等时圈区域数据快照
```

输出可以先是 HTML 幻灯片页面，便于预览、修改和浏览器内检查；确认后再导出 PPTX。

## 11. 默认 15 页结构

当 `page_count` 使用默认值 15 时，可以采用以下结构：

1. 封面：项目名、区域、策划主题、日期。
2. 破题：这个区域要解决什么更新命题。
3. 区位与范围：地图、等时圈、核心影响范围。
4. 历史与文化线索：来自文档来源和网页来源。
5. 当前空间格局：H3、路网和范围结构。
6. POI 与业态结构：供给、主导业态和缺口。
7. 人口与客群基础：常住、年龄和画像。
8. 夜光与活力：夜间经济活动和热点。
9. 商圈、竞品和外部环境：网页来源和文档来源补充。
10. 核心诊断：优势、短板和机会。
11. 策划定位：一句话定位和关键词。
12. 场景策略：文化、消费、社交、产业等场景。
13. 空间更新建议：功能分区、动线和节点。
14. 运营与招商方向：人群、业态、活动和节奏。
15. 结论与下一步：需要补充的数据和落地路径。

该结构只是默认建议。实际页数和章节应由 `page_count`、`deck_type`、`depth` 和 `theme` 动态决定。

## 12. 前端承载待定

当前不急着确定最终放在哪里。

可能方案包括：

1. 独立“PPT 策划生成”工作区。
2. Agent 总结面板中的新标签页。
3. 历史记录详情中的“生成策划 PPT”入口。
4. 先只生成文档，后续再接 HTML 幻灯片预览。

第一阶段建议先做文档生成和迭代，不强行改总结面板。这样可以避免在前端承载方式未定时，把能力耦合到现有总结面板里。

### 12.1 当前 PPT 工作台的两栏语义

当前 UI 先收敛为两栏工作台：左侧为来源区，右侧为指令文件工作区。当前阶段不单独设置“风格 Skill”右侧栏，也不在右侧另开 PPT 页面预览区；风格 Skill 作为指令文件工作区流程条中的“选择风格”步骤承载，页面预览属于后续阶段。

左侧来源区继续保持类似 NotebookLM 的资料库形态。它负责展示和选择本次指令文件会消费的资料来源，包括已生成的等时圈区域数据、POI、H3、人口、夜光、路网，以及接入后的文档、图片、网页、数据库和资料包来源。其他区域不保留独立资料入口。

右侧主区域应命名为“指令文件工作区”。它的职责不是展示普通配置项，而是承载“生成和编辑 PPT 指令文件”的核心流程。建议显示：

- 当前阶段：`资料整理 -> 生成指令 -> 选择/生成风格 Skill -> 生成页面 -> 导出 PPTX`。
- 当前生成目标：主题、页数、受众、汇报类型、是否联网。
- 指令文件结构：页码、页面主题、标题、核心文案、页面提示词、证据和素材要求。
- 指令未生成前：展示将生成的目录或逐页指令占位。
- 指令生成后：在同一区域展示每页指令摘要，方便用户逐页检查、修改和确认。
- “选择风格”作为该工作区内的流程步骤，不作为独立右侧栏。
- 主按钮文案：`生成指令文件`。

后续进入风格 Skill 和页面生成阶段时，应优先在指令文件工作区内切换到“选择风格”和“生成页面”视图；如后续确实需要更大的预览空间，再考虑新增独立区域。当前第一阶段不预留固定右侧栏，避免过早把前端形态锁死。

## 13. PPT AI 数据访问工具层

PPT AI 不应只依赖一次性塞入提示词的少量摘要。对于 POI 名称、坐标、H3 网格、人口网格、夜光像元、路网指标等明细数据，推荐采用“来源清单 + 按需检索工具”的方式。

第一版目录生成和指令生成时，可以在 prompt 中放入：

- 当前选择的来源 id 和来源状态。
- 每类来源的简短摘要，例如 POI 总量、H3 网格数量、人口/夜光/路网是否已生成。
- 当前等时圈范围、出行时间、地图范围等轻量上下文。
- 可用数据工具清单和调用规则。

明细数据不直接整体塞入 prompt，而是由 AI 在需要形成页面论点、引用具体地点、判断热点或生成地图页面时，通过工具搜索和读取。

### 13.1 应进入工具层的数据清单

#### 等时圈范围与空间边界

- 当前等时圈时长，例如 15 分钟、35 分钟等。
- 出行方式和分析中心点。
- 等时圈 polygon、绘制范围 polygon、地图 bounds。
- 范围边界点、中心点坐标和可用于截图的地图视口状态。
- 范围内外的行政区、道路、重要地标关系。
- 数据工具、AI 输入包和资料包统一使用 WGS84 坐标；GCJ02 只用于前端高德地图渲染时的显示转换。

#### POI 明细与分类数据

- 全部 POI 点的名称、经纬度、地址、类型、typecode、来源和年份。
- POI 原始字段中可解释的业务信息。
- POI 分类统计、Top 类别、主导业态、稀缺业态和缺口。
- POI 与等时圈边界、中心点、H3 网格的空间关系。
- 多年份 POI 变化数据，如当前分析链路已经生成。

#### H3 与共享网格数据

- H3 cell id、边界、中心点和分辨率。
- 每个 cell 内的 POI 数量、分类构成和密度。
- 热点 cell、低活跃 cell、功能混合度和空间连续性。
- 与人口、夜光、路网对齐后的共享空间单元。
- 可用于 PPT 地图页的网格色阶、图例、分级规则和统计摘要。

#### 人口数据

- 总人口、人口密度、性别比例、年龄结构等摘要指标。
- 网格级或 cell 级人口数值。
- 人口热点、低密度区、覆盖缺口和数据置信说明。
- 人口数据与 POI、夜光、路网之间的叠加关系。
- 适合进入 PPT 的人群画像和客群判断依据。

#### 夜光数据

- 总辐射、平均辐射、峰值、亮灯像元比例等摘要指标。
- 像元级、网格级或 cell 级夜光值。
- 夜间活力热点、冷点和异常区域。
- 夜光与 POI、人口、路网之间的叠加关系。
- 如有时序数据，应支持按年份或时间段查询变化。

#### 路网与路网句法数据

- 路网线段、节点、边和几何信息。
- 路网句法指标，例如整合度、选择度、可达性、连通性等。
- 高可达路段、低可达断点、交通组织问题和空间机会点。
- 路网指标与 POI 聚集、人口分布、夜光活力的叠加关系。
- 可用于 PPT 的道路骨架图、重要通道和节点识别结果。

#### 地图视觉与页面素材

- 当前地图截图、等时圈截图和关键图层截图。
- POI、H3、人口、夜光、路网等图层的显示状态。
- 图例、色阶、范围、比例尺和地图标题。
- 图片来源中的图片、规划图、现场照片和示意图。
- 可用于页面生成的素材 id、尺寸、来源和推荐用途。

#### 文档与图片来源

- 项目基本情况、愿景、服务建议书、初步交流材料等文档文本块。
- PDF、DOCX、PPTX 中提取出的章节、标题、表格、图片和关键段落。
- 文档 / 图片来源中的事实、诉求、约束、业主表达和已有成果。
- 证据节点的来源文件、页码、图片区域、`node_id` 和引用文本。

#### 联网来源资料

- 竞品、商圈、政策、城市更新案例、历史文化资料等网页来源结果。
- 来源标题、URL、发布时间、摘要和引用片段。
- 联网资料与当前等时圈区域的相关性说明。
- 需要人工确认或不确定的外部事实。

### 13.2 推荐数据工具

后续可以为 PPT 生成链路提供以下工具。工具返回结构化 JSON，避免 AI 直接读取数据库细节。

```text
list_ppt_sources(area_id)
列出当前区域可用于 PPT 的来源，包括等时圈、POI、H3、人口、夜光、路网、文档、图片、网页、数据库和资料包。

read_ppt_source_summary(area_id, source_id)
读取单个来源摘要，适合目录生成和页面主题判断。

search_ppt_analysis_data(area_id, query, domains, top_k)
在 POI、H3、人口、夜光、路网、地图素材中搜索证据。

read_evidence_node(node_id)
读取搜索命中的统一 EvidenceNode，用于生成页面论点和引用。

query_poi_points(area_id, filters, limit, offset)
分页读取 POI 明细，包含名称、坐标、地址、类型和年份。

query_h3_cells(area_id, filters, limit)
读取 H3 cell 明细和统计指标。

query_spatial_cells(area_id, filters, limit)
读取 POI、人口、夜光、路网对齐后的共享空间单元。

query_population_cells(area_id, filters, limit)
读取人口网格或 cell 明细。

query_nightlight_cells(area_id, filters, limit)
读取夜光像元、网格或 cell 明细。

query_road_segments(area_id, filters, limit)
读取路网线段和句法指标。

read_map_snapshot(area_id, layer_state)
生成或读取地图截图、图例和图层状态。

search_source_evidence(area_id, source_ids, query, top_k)
按已选来源检索统一 EvidenceNode。

read_evidence_node(node_id)
读取统一证据节点的完整内容和引用定位。

search_web_sources(area_id, source_ids, query, top_k)
在已构建的网页来源中检索证据。
```

### 13.3 生成目录和指令时的数据调用策略

生成目录时，AI 先读取来源摘要，不需要读取所有明细。目录阶段重点判断章节结构、页面顺序和每页主题。

生成指令文件时，AI 应按页面需要检索明细。例如：

- 区位和范围页需要读取等时圈边界、地图截图和核心地标。
- POI 业态页需要检索 Top 类别、代表性 POI 名称和坐标。
- 人口客群页需要读取人口热点、密度和画像证据。
- 夜光活力页需要读取夜光热点和异常区域。
- 路网组织页需要读取高可达路段、低可达断点和句法指标。
- 策略页需要综合 POI、人口、夜光、路网和文档 / 图片来源事实。

每页指令应记录使用过的 `evidence_refs`、`asset_refs` 和 `map_data_refs`，让后续页面生成和人工审核知道该页依据来自哪里。

### 13.4 与 prompt 输入的边界

prompt 中只放稳定、短小、必要的上下文。原始 POI 列表、网格明细、图片素材、文档全文和联网全文都不直接塞入 prompt。

这样做有三个原因：

1. 避免上下文过长导致模型忽略关键信息。
2. 避免一次性传入大量无关数据，降低生成目录和指令的噪声。
3. 让每页指令能够清楚记录自己实际读取过哪些证据，而不是泛泛声称“来自数据”。

最终目标是让 PPT AI 像 Agent 一样工作：先理解可用来源，再按页面任务搜索、读取、引用和生成。

## 14. 分阶段实现计划

### 第一阶段：资料整理与 PPT 指令文件生成

目标：

- 支持 PPT 生成配置。
- 支持当前区域数据输入。
- 支持选择已构建来源。
- 支持网页来源引用。
- 输出可编辑 PPT 指令文件和逐页生成指令。

不做：

- 不直接生成 PPTX。
- 不强行改总结面板。
- 不做复杂前端翻页。

### 第二阶段：指令确认与修改

目标：

- 用户可以逐页修改。
- 用户可以调整页数和目录。
- 用户可以指定图片和素材。
- 用户可以查看引用来源。

### 第三阶段：选择或生成风格 Skill

目标：

- 用户可以选择已有风格 Skill。
- AI 可以根据项目类型、受众和用户偏好生成临时风格 Skill。
- 风格 Skill 明确控制版式、字体、色彩、地图、图表、图片和质量规则。
- 模板可以作为某类风格 Skill 的实现方式之一，但不作为唯一生成路线。

### 第四阶段：AI 页面生成与预览

目标：

- AI 根据已确认的指令文件和风格 Skill 生成 HTML 幻灯片页面。
- 支持专业汇报风视觉。
- 支持地图、图片来源、已有成果页、数据图表和来源引用插入。
- 用户可以预览、修改页面和回退到指令文件继续调整。

### 第五阶段：PPTX 导出

目标：

- 将确认后的 HTML 或结构化页面导出为 PPTX。
- 保持风格 Skill 的一致性。
- 避免在没有指令文件和风格约束的情况下随机生成页面。

## 15. 验收要点

- 文档阶段可以在不生成 PPTX 的情况下完成。
- 页数由配置控制，不硬编码为 15。
- 文档、图片、网页、数据库和资料包都必须先成为来源；本流程只消费已选来源。
- 联网事实必须带来源引用。
- 指令文件中每页都有页码、页面主题、标题、核心文案、页面提示词、证据、素材需求和缺口提示。
- 等时圈区域数据是资料来源之一，包括范围、地图快照、POI、人口、夜光、路网和共享网格。
- 用户不需要上传指令文件；PPT 指令文件由系统生成，并在生成后供用户审核和修改。
- 当前工作台采用两栏形态：左侧来源区，右侧主区域按流程承载资料整理、生成指令、选择风格、生成页面和导出。
- 风格生成从指令文件中解耦，主流程包含选择或生成风格 Skill。
- 前端承载方式明确标注为待定。
- 第一阶段明确是生成指令文件和逐页页面脚本，不直接生成 PPTX。

## 16. 当前结论

专业 PPT 生成不应从“AI 直接做 PPT”开始。

更稳的路线是：

已有成果与背景文件 + 等时圈区域数据 -> 生成 PPT 指令文件 -> 选择/生成风格 Skill -> AI 根据指令文件和风格 Skill 生成页面 -> 预览与修改 -> 导出 PPTX。

这样既能保证事实和叙事可控，也保留 AI 在视觉风格和页面生成上的创造空间，避免一次性直接生成 PPTX 导致结构、证据和样式都难以修改。

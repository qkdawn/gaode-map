# 面向城市空间决策的多源空间证据驱动智能体：当前系统、方法增量与已完成工作

更新日期：2026-08-24

## 1. 研究对象

本项目研究的不是“让大模型自动写一份城市策划报告”，而是城市空间决策中的一个更基础问题：模型怎样在明确的项目范围内，正确读取项目材料，调用可复核的空间计算，区分事实、推断与待验证假设，并把前序判断稳定地传递给定位、产品、空间、运营和分期决策。

城市空间任务同时包含文档事实、地理对象、网络可达范围、栅格统计、具名设施和方案取舍。大模型可以写出语言流畅的文本，却可能在以下位置破坏决策链：

- 混用行政边界、直线半径和真实网络可达范围；
- 把 POI 数量写成市场需求，把人口结构写成已经发生的行为，把夜光写成客流或消费；
- 只输出设施类别，不读取真正影响判断的具名对象；
- 在章节之间重复分析同一事实，或者让人口总量、定位和客群口径互相冲突；
- 工具失败后继续生成，把运行错误改写成“证据不足”的正式结论；
- 正文看似有引用，但来源编号、文件位置和计算结果无法追溯。

因此，本项目的核心对象可定义为：

> **在项目空间语境约束下，通过受控领域工具按需取得多源证据，以可恢复的决策状态组织复杂任务，并交付可追溯城市空间判断的智能体方法。**

报告只是其中压力最大的交付形态。正常对话、空间取证、单项判断、图件和完整报告都属于同一研究对象。

## 2. 当前产品形态

系统的主工作区是 `/analysis`。地图不是回答旁边的插图，而是项目范围、数据状态、分析结果和后续任务的共同工作界面。用户可以在同一项目中完成：

- 选择项目锚点、出行方式、分析时间和空间范围；
- 生成 Valhalla 网络等时圈及互不重叠的时间环带；
- 获取并查看 POI、H3、共同规则网格、路网、人口和夜光数据；
- 检查具名设施、道路、空间高低值、邻域连续性和跨数据关系；
- 围绕当前地图和已保存材料连续提问；
- 启动空间策略任务，恢复失败运行，查看章节、图件、Markdown 和 DOCX。

当前 AI 交互分为两条链路。

### 2.1 正常对话

正常对话处理范围查询、结果解释、对象追问和连续分析。首轮请求创建 Codex thread，后续请求恢复同一 thread；回答和工具活动通过 SSE 返回。项目数据库只保存产品会话与 `codex_thread_id` 等必要元数据，消息历史、工具调用状态和模型内部轨迹由 Codex App Server 管理。

这条链路的意义是验证智能体能否在不预设报告章节的情况下，根据用户当前问题选择必要证据，并继承有效对话状态。它不运行完整报告工作流，也不生成 DOCX。

### 2.2 空间策略与行动方案

完整任务由 FastAPI 受理，n8n 负责任务触发、排队、租约、章节依赖、领域结果保存、失败恢复和最终交付。Codex Harness 负责模型上下文、工具通信和结构化输出，项目代码不重建通用 Agent runtime，也不使用 `codex_exec`。

这条链路的目标不是增加篇幅，而是让每个章节只新增一类会改变后续选择的判断，并使失败能够停在真实发生的位置。

```text
项目范围、项目材料与用户任务
→ 按需读取文档和空间证据
→ 形成 11 个有依赖关系的策略章节
→ 设计解释决策的图件
→ 统一编号引用并装配 Markdown / DOCX
→ 保存产物或从失败章节继续
```

## 3. 共同事实基础

系统只把能够回溯的原始材料或项目快照视为事实源。索引、摘要、缓存、模型回答和图表都是派生结果，不构成第二份事实。

| 证据 | 事实源 | 能支持的判断 | 不能直接证明 |
| --- | --- | --- | --- |
| 项目范围与锚点 | 已保存 history 项目 | 查询范围、网络可达边界 | 法定红线、真实入口或实际到访 |
| 项目 DOCX/PDF | 原始文件 | 建筑、权属、历史、现状和既有设想 | 设想已经获批或可以实施 |
| POI | 项目保存的高德或本地快照 | 供给结构、具名设施和空间分布 | 营业、容量、合作意愿、需求或客流 |
| 人口 | WorldPop 格网 | 人口底盘、年龄结构和空间分布 | 已发生的行为、使用时段或付费意愿 |
| 路网 | 项目保存的 OSM/Overpass 结果 | 道路骨架、句法指标、走向和连续性 | 实测通行量或真实客流 |
| 夜光 | 本地夜光快照 | 夜间亮度背景、热点和时序代理 | 消费、营业、安全或夜间需求 |
| 等时圈 | Valhalla 网络 contour | 给定起点、方式和时间下的潜在可达范围 | 客源转换、完整到达链或市场流向 |
| 公共文献 | 登记的原始 PDF | 可迁移方法、规范和机制 | 当前项目的本地事实 |
| 实时网页 | 已读取的公开页面 | 会影响判断的时效事实 | 项目内部状态或空间计算结果 |

项目材料不进入公共 GraphRAG。公共文献的 GraphRAG、向量索引和摘要均可由登记 PDF 重建。网页搜索只负责发现候选 URL；页面正文被读取后，才可以进入正式证据。

## 4. 空间证据方法

### 4.1 统一空间语境

所有空间查询绑定同一 `history_id` 和项目已保存范围。网络可达性使用 Valhalla contour，不使用圆形 buffer 或直线距离回退。POI 点按所在环带计数，面状总量按相交面积分配，线状总量按相交长度分配，均值按实际相交尺度加权。

等时圈解决的是“在给定网络和时间条件下哪里可能到达”，不是“谁会来”。方向分析解决的是“空间信号主要分布在哪些方位”，不是“客群从哪个方向流入”。这一区分直接排除了当前无法由数据证明的“市场流向、来源转换和八方向到达链”。

### 4.2 当前正式调用路径

决策章节不选择数据库字段、GIS 算法或底层指标，而是把完整问题提交给 `analyze_spatial_question`。但当前正式 MCP 路径并没有运行空间工具 Agent 的两轮 Harness：MCP 固定传入 `evidence_executor`，函数因此进入 `_deterministic_plan()`，用关键词规则选择操作和事实域，再批量调用确定性计算。

```text
章节中的完整空间问题
→ analyze_spatial_question
→ _deterministic_plan：按关键词映射事实域、语义维度和操作
→ compute_spatial_evidence_batch：并行执行确定性计算
→ spatial_evidence_result_store：保存 result_id
→ 章节按 computation_refs 回读结果并写判断
```

代码中仍保留另一条“两轮 Harness”分支：第一轮无工具拆分问题，第二轮只开放 `compute_spatial_evidence` 和批量入口，并校验实际调用与计划一致。但正式 MCP 不走该分支。因此，当前可以声称系统具有语义化空间问题入口和确定性空间计算，不能声称正式报告已经由空间工具 Agent 自主拆题、选择工具并综合。

### 4.3 MCP 工具及具体实现

| 工具 | 输入与实现 | 返回与边界 |
| --- | --- | --- |
| `project_context` | 读取 history 项目、WGS84 范围、文档目录和五类基础数据目录；当前还会加载各数据集全部公开记录以计算数量与 SHA-256，并扫描历史 spatial-business-analyst run 的持久化指标结果 | 返回项目身份、文档、数据集描述和人口确定性汇总，并在已有目录引用之外追加最近 16 个空间结果索引；不返回空间结果全文 |
| `read_project_document` | 读取 Docling 已解析的项目原文；可按页码和 block 窗口读取，默认 20 个 block、最多 40 个、单次约 10,000 字符 | 保持段落和表格 block 原子性；未读完时返回 `next_start_block`，不把项目材料送入公共 GraphRAG |
| `analyze_spatial_question` | 接收不超过 1,000 字符的完整空间问题；当前正式路径以少量关键词生成不超过 8 个子问题 | 返回子问题、简要 finding 和真实 `computation_refs`；当前不执行依赖式 `rank → inspect/neighborhood` 链 |
| `compute_spatial_evidence` | 接收一个七操作、最多 4 个事实域、最多 8 个语义维度和筛选参数；领域模块内部绑定具体数据、指标、空间分配与算法 | 返回一个确定性结果并持久化；工具本身不解释用户问题，也不决定项目定位 |
| `compute_spatial_evidence_batch` | 使用 `ThreadPoolExecutor` 并行执行 1 至 8 个相互独立请求；同批共享一次项目读取 | 保持输入顺序；全部成功为 `available`，部分成功为 `partial`；依赖前序 `record_ref` 的请求不能进入同批 |
| `read_spatial_evidence_result` | 以 `history_id + result_id` 只读查询持久化空间结果 | 只允许读取同一 history 的已有结果，不重新计算，也不接受不存在的 ID |
| `read_strategy_chapters` | 校验 UUID run，按请求的 `unit_id` 查询 `analysis_step_outputs` 中状态为 `completed` 的章节 | 只返回 `unit_id`、标题、正文和引用；任何请求章节缺失都会整体失败 |
| `search_literature_evidence` | 查询登记 PDF 语料；`focused` 返回快速原文证据，`synthesis` 用于跨文献机制比较；问题最长 2,000 字符，`top_k` 为 1 至 10 | 独立 GraphRAG Python 环境执行，150 秒超时；只能支持可迁移方法与机制，不能代替项目事实 |
| `search_public_web` | 通过 AnySearch 或 Exa 搜索，最多 10 条；provider 网络超时按配置归一化 | 搜索结果只用于发现 URL，不能直接进入报告证据 |
| `fetch_public_web_page` | 读取最多 5 个 HTTP(S) 页面，每页请求上限 500 至 20,000 字符 | 只有读取后的页面正文可以支持公开属性；当前 11 章报告没有开放这两个网页工具 |

### 4.4 四个空间事实域怎样实现

#### POI

POI 使用项目保存的高德或本地点记录，按 typecode 分类表解析主类和子类。范围画像统计点数、面积密度、类别占比、Shannon entropy 和归一化 entropy；如果存在 H3，继续计算单元局部 entropy。方向分析把保存等时圈切成八个扇区，统计各方向数量、密度和类别结构，并以设施等权计算空间中心与标准差椭圆。

两个明确 POI 类别的 `relationship` 使用方向性 Category Colocation Quotient：比较“A 类点最近邻属于 B 的观察比例”与范围内 B 的期望比例，分别返回 A→B 和 B→A。CLQ 不做显著性检验，也不证明因果、客流或协同。指定类别与人口共同做 `accessibility` 时，系统在保存路网上计算设施—人口格路径，把每个设施等权处理，输出每千人可达设施数；由于没有设施容量，这不是容量加权 2SFCA。

具名候选使用 `regional_anchor`、`daily_service` 和 `comparable_supply` 三种角色。前两者按不同类别与 typecode 范围保持候选多样性，后者必须同时指定明确 POI 类别。它们只产生现场核验清单，不自动认定锚点、合作方、客群来源或到访关系。

#### 人口

人口使用 WorldPop 面状格网。边界格人口按“相交面积 / 原格面积”分配，因而隐含格内均匀分布假设。范围画像包括总人口、男女总量与比例、20 个年龄带及 0-14、15-64、65 岁以上三组；选择年龄或性别后，计算对象切换为目标人群。

`accessibility` 返回各网络时间带的增量人口和累计人口；`direction` 按八扇区交叠面积分配目标人口，并计算人口加权中心与标准差椭圆；`rank` 可按人数、密度或所选人群占比排序；`neighborhood` 比较目标格与相邻格的总量、密度、差值和高值连通片；`inspect` 展开单格完整年龄、性别、年份和邻域差。人口变化只在至少两个可比年份存在时按稳定 record ID 比较快照，不做趋势显著性检验。

#### 夜光

夜光使用面状格网，并以实际相交面积加权。基础指标包括平均、中位、P90、最大辐亮度、亮灯面积比例、辐亮度总量指数和最高 20% 面积的亮度贡献；空间画像包括亮度加权中心、标准差椭圆和中心—边缘梯度。

七操作分别支持范围构成、网络时间带增量、八方向亮度差、邻格反差、明暗格排序、与其他事实域的共同高低值以及单格展开。年度变化以稳定 cell ID 对齐 2023-2025 范围内至少两个快照，描述首末值、差值、变化率和亮度中心迁移；不执行 Mann-Kendall 或新兴热点统计。`cf_cvg`、观察数、有效像元数和质量标记存在时自动进入诊断，不存在时明确无法识别低质量像元。

#### 路网

路网读取项目已保存的 OSM/Overpass 节点、线段、连续廊道和规则格网。depthmapX 在数据生产阶段计算句法指标，提问阶段不重复运行。NAIN 表示标准化角度整合度，在语义层解释为到达潜力；NACH 表示标准化角度选择度，解释为穿行潜力；二者不能互换。其他指标包括道路长度、网络密度、connectivity、control、mean depth 和 node degree。

`scope` 读取各半径的 NAIN/NACH 分布、P75 核心网络背景、连续廊道、总长度、道路自身走向和拓扑质量；`accessibility` 按 Valhalla 时间带汇总道路长度、密度和 connectivity；`direction` 表示道路指标相对项目锚点的八方向分布，与道路自身 orientation 不同；`neighborhood` 对线段使用共同端点拓扑，对 H3 使用 k-ring，对其他格网使用几何邻接；`rank` 可分别排列线段、廊道和格网。

### 4.5 七操作在各事实域中的落地

| 操作 | POI | 人口 | 夜光 | 路网 |
| --- | --- | --- | --- | --- |
| `scope` | 数量、密度、分类、entropy、具名候选 | 总量、性别、20 年龄带和目标人群 | 面积加权亮度、空间画像和质量 | 句法分布、长度、密度、走向和质量 |
| `accessibility` | 各时间带设施；指定类别可与人口做等权供需可达 | 时间带增量与累计人口 | 时间带增量与累计亮度画像 | 时间带道路长度、密度和连接度 |
| `direction` | 八扇区数量、密度、类别、等权中心和椭圆 | 八扇区目标人口、加权中心和椭圆 | 八扇区亮度贡献、亮度中心和椭圆 | 相对锚点的八方向道路指标 |
| `neighborhood` | 目标 H3/网格与相邻单元的数量、密度、混合和具名设施 | 目标格、相邻格和高值连通片 | 目标格与邻格面积加权亮度差 | 端点拓扑、k-ring 或几何邻接 |
| `rank` | 按供给、混合或类别专业化排列空间记录 | 按人数、密度或目标人群占比排列格网 | 按单格亮度或年度变化排列 | 按到达、穿行、连接等排列线段、廊道或格网 |
| `relationship` | 两类别用双向 CLQ；跨域时进入共同格网 | 与供给、夜光或路网形成相对高低和错位 | 与人口、POI、路网形成相对高低和错位 | 与其他域在共同格网比较 |
| `inspect` | 展开名称、类别、地址、距离和格内/邻近关系 | 展开单格完整人口结构与邻域差 | 展开单格年份、百分位、方向和邻域亮度 | 展开节点、线段、廊道、格网及相交对象 |

跨域 `relationship` 先把点、线、面分配到共同空间单元，只保留所有指标都有值的单元，当前至少需要 4 个；随后在当前保存范围内分别计算 P25/P75，形成共同高、共同低、信号冲突或中间类型。它不计算相关系数、综合机会分或因果关系。

### 4.6 参数、引用与模型安全投影

确定性请求由 Pydantic 在最接近工具入口的位置校验：`rank` 必须只有一个事实域；普通 `relationship` 必须有 2 至 4 个事实域且每域一个语义维度；`neighborhood` 和 `inspect` 必须使用真实 `record_ref`；时间带只允许用于 `accessibility`；邻域步数为 1 至 3；Top K 为 1 至 20；单次最多 20 个记录引用。

可继续检查的对象使用稳定引用：

```text
record_ref = source_id + "/" + record_id
```

Agent 可见投影会删除 geometry、coordinates、FeatureCollection、数据库连接和本地路径；`groups` 通常最多 12 项，`highlights`、具名对象和 evidence 各最多 20 项。确定性结果保存 `result_id`、实际事实域、语义维度、年份、方法和 provenance，使后续章节能够复核同一结果而不重复计算。

### 4.7 十一章的工具权限

所有章节都能调用 `project_context`；有依赖的章节必须且只能读取声明的前序章节。其他权限按章节固定：

| 章节 | 新增工具 | 当前用途 |
| --- | --- | --- |
| 项目材料与项目基础 | `read_project_document` | 读取场地、权属、历史、现状和既有设想 |
| 项目类型与区域角色 | `analyze_spatial_question`、`read_spatial_evidence_result` | 区域锚点、道路、公共服务和居住背景 |
| 具名供给与服务空位 | 同上 | 供给高低、人口错位和具名替代/协同对象 |
| 客群与使用 | 同上 | 统一人口底盘、年龄结构、日常服务环境和验证假设 |
| 地方资源与共同机制 | `read_project_document`、`search_literature_evidence` | 从项目原文与可迁移机制提炼主题 |
| 候选定位比较 | 同上 | 用前序判断和文献机制比较定位 |
| 场景与产品组合 | 同上 | 把地方机制、客群任务和定位转成产品 |
| 空间组织与具体落位 | `read_project_document`、两个空间工具 | 读取具名空间对象、连接、邻域和边界 |
| 运营组织与合作关系 | `read_project_document` | 从材料和前序产品/空间判断确定责任接口 |
| 投入与运营判断 | `read_project_document` | 使用已有工程、空间、产品和运营条件判断相对投入 |
| 首期闭环与后续分期 | `read_project_document` | 把已成立条件转成行动顺序与阶段门 |

`search_public_web` 和 `fetch_public_web_page` 已注册在 spatial-project MCP，但当前没有进入任何策略章节的 `enabled_tools`。因此，报告目前不能在运行中核验具名机构的最新开放状态、正式职能或公开活动；这些工具只能算基础设施能力，不能算当前 11 章已消费能力。

### 4.8 并行边界

相互独立的空间子问题可以通过批量入口并行执行，当前单批最多 8 个请求，返回顺序与输入顺序一致。以下情况必须串行：

- `rank → inspect`，因为后者需要前者返回的 `record_ref`；
- 当前文档块 → 下一文档块，因为后者依赖分页位置；
- 搜索网页 → 读取网页，因为后者依赖真实 URL；
- 任何需要上一个结果 ID 才能构造参数的请求。

章节之间的先后不是性能问题，而是决策依赖。没有形成客群、定位或产品判断时，后续空间、运营和投入章节不应提前生成。

## 5. 十一章决策链及其增量

当前报告不再使用动态决策单元，也不再经过 `decision_memo → report_blueprint → 二次写作`。11 个章节直接生成可交付 Markdown，每章只读取 `depends_on` 指定的已完成章节，并独占一类新增判断。

| 顺序 | 章节 | 本章必须新增的判断 | 不能重复承担的内容 |
| --- | --- | --- | --- |
| 1 | 项目材料与项目基础 | 项目对象、关键数字、空间骨架、材料冲突和前置条件 | 不提前给出定位和产品 |
| 2 | 项目类型与区域角色 | 项目与区域节点、道路、公共服务和居住片区的主次分工 | 不把邻近设施写成客流或合作 |
| 3 | 具名供给与服务空位 | 已有具名供给、应避免复制的业态和项目可补增量 | 不用单一类别或噪声 POI 代替供给结构 |
| 4 | 客群与使用 | 核心、次级和暂不选择客群；使用情境、时段、付费假设、阻碍和验证 | 不把人口结构写成已发生行为 |
| 5 | 地方资源与共同机制 | 自然、历史、日常生活和产业资源之间可持续的地方机制 | 不堆砌文化标签 |
| 6 | 候选定位比较 | 用同一标准比较至少三个候选定位，并给出唯一推荐及放弃理由 | 不重新复述全部基础资料 |
| 7 | 场景与产品组合 | 资源如何转成体验、服务、消费或社区产品，以及最小组合 | 不脱离客群、定位和运营条件罗列业态 |
| 8 | 空间组织与具体落位 | 入口、路径、节点、缓冲、居民、后勤和安全边界 | 不只输出抽象分区名称 |
| 9 | 运营组织与合作关系 | 业主、现场团队、社区、专业机构和合作方的责任接口 | 不把邻近单位默认视为伙伴 |
| 10 | 投入与运营判断 | 投入强度、实施难度、运营复杂度和资金承担 | 不输出无工程量和价格依据的伪精确收益 |
| 11 | 首期闭环与后续分期 | 首期项目包、执行顺序、责任主体和进入、调整、暂停、停止条件 | 不把远期愿景混入一期承诺 |

这套章节结构的增量不在“多写十一遍”，而在判断所有权。项目基础章确定共同事实；区域角色和供给章缩小可选空间；客群和地方机制章确定“为谁、在什么情境、依靠什么内容”；定位章完成取舍；产品、空间、运营和投入章检验推荐方案能否运行；分期章把前述判断转成首期行动与停止条件。

### 5.1 客群分析的位置

人口总量、年龄结构及其引用由“客群与使用”章节独占，避免不同章节各算一次并产生不同口径。年龄结构可以用于推导行为、时段和付费意愿的候选假设，因为它能改变需要测试的产品与服务设计；但年龄不能单独证明这些行为已经存在。

因此，正确链条是：

```text
年龄与人口结构
→ 候选客群及行为、时段、付费假设
→ 对应产品和运营原型
→ 访谈、预约、到场、停留、复访或价格测试
→ 决定扩大、调整或停止
```

客群分析不是人口图的图注，也不是独立附录，而是定位、产品、运营和分期共同依赖的前序判断。

### 5.2 不再设置“市场流向”结论

当前项目没有门禁、票务、信令、轨迹或来源调查，不能获得真实客流及来源转换。因此报告不再要求“市场流向、不同步行圈之间的客源转换、八方向到达链”闭合，也不会因为这些数据不存在就自动降低项目定位。

现有数据仍可支持人口背景、设施供给、网络可达范围、道路结构和空间方向判断。它们用于决定还需要验证什么，不能被包装成已经观测到的人群移动。

## 6. 从证据到交付

章节长期保存的领域结果只包括稳定 ID、标题、正文和引用。Codex 原始消息、工具名、调用 ID、响应 ID 和内部 thread 历史不进入章节契约。下游章节通过 `read_strategy_chapters` 读取明确依赖的已完成章节，不被动继承七份完整 memo 或模型执行轨迹。

11 章完成后，图件阶段读取全部章节，选择 3 至 5 张真正解释方案取舍的数据图或表。图件不是装饰，每张只回答一个决策问题，图中数据口径必须与正文一致。年龄结构图可以支持客群假设设计，但不能直接把某年龄段画成已经具有特定消费行为。

报告装配器完成以下工作：

1. 校验 11 章的 ID、顺序、标题、正文和引用；
2. 按稳定来源对章节局部引用去重；
3. 将 `[C1]`、`[S1]` 等章节局部标签转换为全报告连续数字标签 `[1]`、`[2]`；
4. 生成与正文编号一致的文末“参考来源”；
5. 生成 Markdown 和 DOCX，并保存文件类型、路径和 SHA-256。

引用由此成为报告契约的一部分，而不是正文末尾临时补上的格式。

## 7. 失败、恢复与错误所有权

工具执行失败是运行失败，不是分析结论。空间结果 ID 不存在、文档读取失败、模型输出不符合 schema 或外部服务超时，都必须停在真实失败位置并保存原因；系统不能继续生成一段“由于证据不足，建议降低项目等级”的文字。

同一 run 的恢复规则是：

1. 已完成章节直接复用；
2. 失败章节不视为完成，修复后单独重跑；
3. 下游尚未开始的章节继续按依赖执行；
4. 11 章已经完成时，图件或报告装配失败只恢复报告尾段；
5. 恢复继续使用原 `run_id`，不复制一套历史章节。

`analysis_runs` 负责运行状态、当前步骤和租约；`analysis_step_outputs` 负责章节状态和章节产物；`analysis_reports` 负责最终报告和文件清单。n8n 管理这些业务状态，Harness 继续拥有模型与工具协议。

单个 n8n 执行的总保护边界为 4 小时。该边界只用于阻止异常运行无限扩大，不是性能优化，也不能替代对死循环、无效重试或错误引用的根因修复。

## 9. 项目相对现有基座的真正增量

Codex Harness 已经负责模型上下文、工具调用、结构化参数、调用 ID、重试和内部消息。本项目不把这些通用能力作为方法创新，也不在 n8n 中重新模拟 Agent 工具循环。

本项目实现的领域增量有五项：

1. **项目空间语境契约**：把 history、项目范围、网络等时圈、数据年份和项目材料绑定为同一任务上下文。
2. **语义化空间问题契约**：让决策 Agent 提交完整问题，并把事实域、空间操作、指标绑定和结果读取隐藏在领域边界内；当前关系选择仍由规则计划完成，空间工具 Agent 的增量尚未进入正式链路。
3. **具有判断所有权的决策链**：11 章分别拥有不可替代的新增判断，并通过依赖关系把事实、定位、产品、空间、运营和分期连接起来。
4. **稳定领域结果与同 run 恢复**：下游读取业务结果，不继承 Harness 原始历史；失败停在单章并复用已完成工作。
5. **证据到交付的一致性契约**：正文、图件、数字引用、来源表、Markdown 和 DOCX 使用同一批稳定章节结果。

这些是已经实现的工程事实。它们是否提高工具正确率、空间一致性、证据支持度、决策连贯性或专家可用性，仍需实验回答。

## 10. 论文主线与待验证假设

论文可以围绕一个核心问题展开：

> 在相同项目输入、模型和预算条件下，以项目空间语境约束任务，通过语义化领域工具按需取得多源证据，并用可恢复的判断链组织复杂决策，能否提高城市空间智能体的工具执行正确性、空间一致性、证据可追溯性、决策连贯性和成果可用性？

对应假设为：

- **H1 领域工具增量**：相较一次性文本注入，按需调用受控空间工具能够提高事实与计算的正确性和可追溯性。
- **H2 空间语境增量**：相较圆形缓冲区或未声明的混合范围，网络等时圈和统一项目范围能够提高跨数据源空间一致性。
- **H3 语义接口增量**：相较让通用 Agent 直接选择底层数据集和指标，空间问题入口能够减少无效调用与错误计算顺序。
- **H4 判断链增量**：相较单次综合或无状态多阶段生成，具有判断所有权和稳定结果读取的 11 章链能够减少重复与跨章节冲突。
- **H5 恢复增量**：相较整链重跑，同 run 单章恢复能够降低失败成本，并保持已完成结果一致。

建议评价任务覆盖：连续空间问答、证据查询与核验、可执行空间分析、综合决策和多形态成果生成。完整报告是综合压力任务，不能代替对工具执行和单项空间判断的独立评价。

| 评价维度 | 可操作指标 |
| --- | --- |
| 任务完成 | 无需人工补写执行步骤即可完成目标任务的比例 |
| 工具正确性 | 工具选择、参数、调用顺序和结果消费正确率 |
| 空间一致性 | 事实与判断遵守范围、坐标、年份和聚合口径的比例 |
| 数值正确性 | 报告数字与数据库重算结果在容差内一致的比例 |
| 证据支持度 | 事实性主张能够定位且被来源真实支持的比例 |
| 决策连贯性 | 重复判断、前后矛盾和未经依赖支持的结论数量 |
| 边界纪律 | 把代理指标写成需求、客流、因果或收益的次数 |
| 恢复正确性 | 失败恢复后已完成章节是否保持不变、失败章是否正确重跑 |
| 成本 | 完成时间、模型调用、token、工具调用和失败重跑成本 |
| 专家可用性 | 规划专家对可信度、解释力、可复核性和决策价值的盲评分 |

基线至少应包括通用模型、静态证据智能体、使用相同工具的通用 Agent、无稳定领域结果的多阶段 Agent，以及完整方法。所有条件需要匹配模型、项目输入和预算，不能用报告长度、节点数或 Agent 数量代替效果。

## 11. 当前不能声称的结论

现阶段可以声称系统具备正常对话、空间工具、11 章决策、图件、引用、DOCX 和失败恢复的完整工程链路，也可以陈述具体 run 的验收事实。

现阶段不能声称：

- 11 章一定优于单次综合、其他章节结构或人工分析；
- Codex Harness 本身提高了空间判断正确率；
- POI、人口、夜光或路网能够证明真实需求、客流、消费、合作或财务可行性；
- 年龄结构已经证明某类人会在特定时段参与或付费；
- 一次成功运行代表系统稳定性、跨城市泛化或专家认可；
- 工作流节点数、章节数、工具数量和报告长度构成研究创新；
- 当前成果可以替代现场调查、公众参与、工程核验或法定规划程序。

这些边界不是报告的保守措辞，而是论文能否区分工程事实、方法假设和实验结论的基本条件。

## 12. 当前剩余问题

### 12.1 空间问题入口存在双重行为

`analyze_spatial_question` 在是否传入 `evidence_executor` 时具有两套实现：一套运行两轮 Harness，一套运行 `_deterministic_plan()`。正式 MCP 永远传入 executor，因此工具名称、docstring、测试中的 Harness 行为和生产行为并不一致。这增加了维护者必须记住的隐藏条件，也使论文难以界定“空间工具 Agent”究竟是否参与。

需要收敛为一个契约：如果正式方法需要空间工具 Agent，就让 MCP 真实调用 Harness 并解决嵌套调用的时间成本；如果策略问题本来就是固定规则，则应把工具明确命名为规则计划执行器，不再声称自主拆题。

### 12.2 当前规则计划不足以执行依赖式空间分析

规则计划只识别步行圈、方向、供给、人口、邻域等少量词。没有命中时默认返回 POI、人口和路网 `scope`。它不能从前序结果取得 `record_ref`，所以不能真正执行 `rank → inspect` 或 `rank → neighborhood`；遇到“邻域”时当前直接改成跨域 `relationship`。这会让空间落位章节得到总体错位，而不是所要求的重点单元邻域连续性。

### 12.3 `project_context` 仍在重复扫描重数据

每个章节都必须调用 `project_context`。该工具目前会为五类数据重新加载全部公开记录并计算 checksum，还会遍历历史 spatial-business-analyst run，读取其中的持久化指标结果。项目历史较多时，这正是“反复读取并解析同一批 analysis artifact”的来源之一。工具最终只向章节暴露目录和少量引用，却在内部承担了超出目录查询所需的工作。

正确边界应是直接读取已保存的数据集元数据、checksum 和稳定结果索引；人口汇总等确有消费者的对象单独持久化。目录调用不应为了重新证明目录而扫描全部记录和历史 run。

### 12.4 工具注册与报告消费不一致

网页搜索与页面读取已经注册，却没有任何策略章节获准使用。反过来，区域角色和供给章节会产生需要核实的具名候选，但无法在同一任务中核对官方名称、职能或开放状态。应根据真实消费者决定：给明确章节开放成对的 search/fetch，或者从当前报告能力描述中移除网页核验。

### 12.5 当前验收没有覆盖正式入口的语义质量

现有测试分别覆盖 Harness 分支、规则计划、确定性计算和 MCP schema，但一次成功报告只能证明链路可运行。还缺少从章节 `spatial_questions` 进入正式 MCP 后，对子问题是否正确、是否取得预期具名对象、是否执行依赖调用、是否减少重复读取以及结果是否真正改变章节判断的端到端测试。

## 13. 下一阶段工作

下一阶段不应继续增加章节、提示词或审计层，而应完成三项可验证工作：

1. 收敛 `analyze_spatial_question` 的单一生产语义，并为正式入口补齐 `rank → inspect/neighborhood` 依赖链；
2. 把 `project_context` 改为读取稳定目录与索引，停止每章重复加载全部记录和历史指标 run；
3. 冻结正常对话、空间取证、综合决策和报告任务集，建立可重算的正确答案与错误类型；
4. 在匹配模型、输入和预算的条件下完成基线与消融，分别检验范围、语义空间工具、判断链和恢复机制的增量；
5. 扩展到不同城市形态和数据缺失条件，结合自动检查、重复运行和规划专家盲评报告有效性与失效边界。

只有当这些实验完成后，论文才能从“系统已经实现什么”推进到“哪一项方法在什么条件下有效”。

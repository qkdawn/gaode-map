# 空间项目 Agent 开发方案

## 1. 目的与范围

本方案把“空间项目 Agent 最终目标”和“空间项目 Agent 目标架构”转化为开发顺序、领域边界、数据契约和验收条件。

首期要完成一条可用链路：人员在 `/analysis` 准备项目数据并锁定快照，Codex 或 ChatGPT 通过 MCP 查询该快照，Agent 可以基于同一事实来源完成专业分析。商业报告、空间单元策划和甲方 PPT 在后续阶段接入这条链路。

`/analysis` 的职责收敛为项目数据准备与地图质量控制。它负责范围、数据、空间单元和人工核验，不再承担后续 Agent 的事实来源或运行依赖。

## 2. 固定设计决策

| 决策 | 采用方式 | 原因 |
| --- | --- | --- |
| AI 调用入口 | MCP | Codex、ChatGPT 和后续客户端通过同一工具目录读取项目数据和成果。 |
| 项目事实来源 | 项目数据快照 | 报告、策划和 PPT 固定引用同一范围、版本和质量说明。 |
| 非结构化资料 | RAG 与 EvidenceNode | 文档、图片、网页和外部资料需要语义检索与来源定位。 |
| 空间数据读取 | 结构化查询工具 | POI、人口、夜光、路网、格网和空间单元需要分页、聚合和单条读取。 |
| 复杂任务方法 | Skill | Skill 约束商业分析、空间策划和 PPT 的步骤、证据要求与禁止推断。 |
| 人工工作台 | `/analysis` | 人员在地图上准备数据、核验空间对象、审定草稿和查看成果。 |
| 文件交付 | 成果库与项目数据包 | 运行中的 Agent 读取服务端快照；导出包服务于离线复现、备份和交接。 |

新项目运行只使用项目快照契约。历史记录和旧的 PPT 来源导出只能作为一次性导入来源，不能在新运行中继续作为并列事实来源。

## 3. 目标领域模型

### 3.1 项目与快照

`Project` 表示一个委托任务，保存名称、项目范围、任务书、参与者和项目状态。

`ProjectDataSnapshot` 表示一次锁定的分析事实。它引用项目范围、数据集版本、空间单元集、资料索引和质量报告。任何正式运行必须绑定一个 `snapshot_id`。

快照状态使用：

- `draft`：人员仍在准备范围、数据或空间单元；
- `ready`：系统已完成数据检查，允许人员核验；
- `locked`：允许 Agent 生成正式草稿；
- `superseded`：存在更新快照，旧成果保留审计价值。

范围、年份、来源、空间单元或关键资料发生变化时，系统创建新快照，不修改已锁定快照。

### 3.2 数据集目录

每个快照必须包含 `DatasetManifest`。目录记录：

- `dataset_id`、数据类型、范围和坐标参考；
- 来源、采集时间、数据年份、版本和许可说明；
- 记录数、覆盖情况、缺失、重复、截断和异常诊断；
- 分析方法、主要参数、单位和可查询字段；
- 可用状态与警告。

项目服务以 WGS84 保存权威几何。地图展示和供应商调用在边界处完成坐标转换。范围、空间单元和数据集使用稳定 ID，避免依赖前端数组位置或显示名称。

### 3.3 空间单元

`SpatialUnitSet` 是项目经过确认的策划对象清单。首期支持由项目 GeoJSON 导入地块、建筑、庭院、街区或节点。H3、共享格网和道路片段作为分析证据层；项目需要时可以显式选用它们作为空间单元来源。

`SpatialUnit` 至少包含稳定 ID、名称、类型、几何、来源、父级关系和状态。系统检查重复 ID、无效几何、范围外对象和重叠冲突，并将无法使用的对象记录为诊断。

### 3.4 证据、运行与成果

`EvidenceNode` 继续表示可定位的证据。它必须带有项目、快照、来源、时间、定位信息和证据类型。

`ProjectRun` 表示一次商业报告、空间单元策划或 PPT 生成。它固定输入快照、任务配置、Skill 版本、运行日志和输出成果。

`ProjectArtifact` 表示版本化成果，例如报告 JSON、报告文件、单元矩阵、PPTX、预览、地图和证据附录。成果状态使用 `draft`、`needs_review`、`approved`、`failed`、`stale`。只有 `approved` 成果可以成为甲方汇报输入。

## 4. 项目数据包

项目数据包是快照的可携带导出物。日常 Agent 运行从项目服务读取快照，不要求人工先导出文件。人员在离线分析、备份、跨环境复现或交给外部团队时导出数据包。

数据包目录如下：

```text
project-package/
  manifest.json
  scope.geojson
  spatial-units.geojson
  datasets/
  evidence/
  documents/
  assets/
  artifacts/
```

`manifest.json` 是入口文件，包含项目标识、快照标识、创建时间、范围、数据集目录、文件校验值、质量报告和成果引用。向量数据以 GeoJSON 或带清晰元数据的结构化文件导出；栅格和大文件以文件引用及校验值登记；项目原始资料保留原始文件和来源说明；证据索引导出为 JSONL。

数据包不替代服务端存储，也不承担增量写入。导入数据包时，系统创建新的项目快照并执行完整性检查。

## 5. RAG 收敛方案

RAG 保留为项目资料检索层，负责文档、图片 OCR、网页、政策、案例和外部参考的语义召回与证据定位。

RAG 不负责读取 POI、人口、夜光、路网、格网和空间单元明细。Agent 通过结构化数据工具获取这些数据，通过 RAG 获取解释性资料和可引用文本。

| 内容 | 读取方式 | 产物 |
| --- | --- | --- |
| POI、人口、夜光、路网、格网、空间单元 | 项目数据查询与聚合 | 结构化记录、统计、地图要素和定位信息 |
| 项目任务书、规划资料、调研报告 | RAG 检索与读取 | EvidenceNode、页码或段落定位 |
| 图片、图纸、扫描件 | 图像解析与 RAG | OCR、图像描述和来源定位 |
| 网页、政策和案例 | 网页采集与 RAG | 已选来源、文本片段和链接 |
| 报告、策划矩阵和 PPT | 成果库读取 | 版本、文件、引用和审批状态 |

现有 `modules/documents`、`modules/evidence_index` 和 `modules/retrieval` 继续拥有解析、索引和召回。新项目服务只向它们传递 `project_id` 和 `snapshot_id` 范围，不复制检索规则。

## 6. 后端职责边界

新增 `modules/spatial_projects/` 作为项目快照深模块。它拥有项目、快照、数据集目录、空间单元、数据包导入导出和面向 Agent 的数据读取服务。调用方不需要理解历史记录、分析 artifact 或前端临时状态。

该模块至少提供以下领域能力：

- 创建项目并维护范围、任务书和参与者；
- 从已有分析结果、资料和导入包构建快照；
- 检查并锁定快照；
- 列出数据集、分页查询记录、执行受控聚合；
- 导入和管理空间单元；
- 导出和导入项目数据包；
- 创建、读取和比较项目运行与成果。

已有模块的职责保持清楚：

- `modules/poi`、`modules/population`、`modules/nightlight`、`modules/road` 和 `modules/h3` 继续计算领域数据；
- `modules/scope_datasets` 的归一化和受控查询逻辑迁入或复用为快照数据读取的底层能力；
- `modules/business_analyst` 继续拥有商业模型路径和边界；
- `modules/agent/skills/urban_strategy_stage1` 继续拥有城市更新策划方法；
- `modules/ppt_planning` 继续拥有资料组织、叙事、页面指令和视觉资产；
- `store/` 只保存模型和仓储访问，不处理分析规则、快照选择或成果编排。

路由层只做请求校验、依赖注入和响应编排。项目快照、数据选择、证据关系、运行恢复和导出规则都留在领域模块内。

## 7. MCP 服务

MCP 以 Streamable HTTP 方式接入现有 FastAPI 服务，并使用项目级或部署级认证。MCP 适配层调用 `modules/spatial_projects`，不在工具 handler 中实现数据选择和分析规则。

第一批 MCP 工具全部只读：

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| `list_history_projects` | 历史记录数量 | 历史记录 ID、名称和时间 |
| `read_history_project` | `history_id` | 项目范围、绑定文档、数据集和版本状态 |
| `list_history_project_documents` | `history_id` | 文档角色、解析状态和文件信息 |
| `list_history_project_datasets` | `history_id` | 数据集目录、年份、来源、数量和警告 |
| `query_history_project_dataset` | `history_id`、数据集、过滤、排序、分页 | 当前页记录、总量、定位和警告 |
| `aggregate_history_project_dataset` | `history_id`、数据集、分组、指标和过滤 | 受控统计和范围说明 |
| `read_history_project_dataset_record` | `history_id`、数据集、记录 ID | 单条数据记录、定位和警告 |
| `search_project_evidence` | 查询词和证据类型 | EvidenceNode 摘要 |
| `read_project_evidence` | 证据 ID | 可引用的完整证据内容 |

第二批工具启动异步成果任务：

| 工具 | 前置条件 | 输出 |
| --- | --- | --- |
| `start_business_analyst_report` | 锁定快照和明确分析范围 | `run_id`、就绪检查和缺失输入 |
| `start_spatial_unit_planning` | 锁定快照和确认的空间单元集 | `run_id`、单元覆盖目标和诊断 |
| `start_client_deck` | 已审定报告或策划成果 | `run_id`、汇报输入和成果目标 |
| `read_project_run` | `run_id` | 进度、诊断、输入版本和成果引用 |
| `list_project_artifacts` | 项目、快照或运行 | 文件、审批状态和证据关系 |

读取工具标记为只读。启动任务的工具创建受限项目内任务，要求调用方确认项目和快照。MCP 返回紧凑的结构化内容；大文件、地图、完整数据包和 PPT 使用文件引用返回。

## 8. 专业成果任务

### 8.1 ESRI 风格商业报告

商业报告任务消费锁定快照、分析范围、问题类型、目标业态和候选点。它首先生成模型就绪度，再读取项目数据和证据，最后输出带证据的报告对象和交付文件。

报告必须输出 Trade Area、Market Potential、Retail Gap、Opportunity Screening、Competition、Customer Fit、Site Suitability 的状态、信号、置信度、缺失输入和验证计划。缺少消费基准时，任务不能量化 leakage 或 surplus；缺少候选点、竞品和通行条件时，竞争与选址任务保持受限。

### 8.2 全空间单元策划

空间单元策划任务先形成项目级定位、功能组合和实施原则，再为每个合格空间单元构建证据包。任务按批次输出单元策划，并在结束前执行组合校验。

完成门槛为：

```text
accepted_unit_count = planned_unit_count + excluded_unit_count + blocked_unit_count
eligible_unit_count = planned_unit_count
```

任务因资料不足而无法处理的单元必须记录为 `blocked`，并说明缺少资料、责任人和验证动作。任务可以完成并带警告，但不能将未处理单元伪装成已完成。

### 8.3 甲方汇报 PPT

PPT 任务只消费已审定成果和已选资料。它按叙事结构生成逐页 brief、地图与图表资产、可编辑 PPTX、预览和证据附录。页面上的关键指标和结论必须引用项目成果或项目资料。

现有 PPT 规划能力负责目录、叙事、逐页指令和视觉资产。新增渲染器负责生成实际 PPTX，并在交付前检查每页文字溢出、遮挡、缺失素材和图表数据。

## 9. `/analysis` 调整

`/analysis` 保留以下职责：

- 创建或选择项目范围；
- 获取、查看和检查空间数据；
- 查看数据集目录、年份、覆盖和异常；
- 导入、调整和确认空间单元；
- 锁定项目数据快照；
- 在地图上核验证据、单元结果和需要人工判断的问题；
- 审定商业报告、空间策划和 PPT 的输入成果。

`/analysis` 不保存另一份 Agent 专用数据，也不要求后续 Agent 依赖浏览器状态。人员完成数据准备后，可以直接在 Codex 或 ChatGPT 中继续工作；需要空间核验或审批时再回到工作台。

## 10. 开发顺序

### 阶段 A：项目快照与数据包

1. 建立项目、快照、数据集目录和空间单元的 schema、仓储与领域服务。
2. 从现有范围分析、项目资料和导入文件构建快照。
3. 将数据质量、年份、来源、覆盖和诊断写入目录。
4. 实现项目数据包导出、导入和完整性检查。
5. 让 `/analysis` 能创建快照并查看数据目录。

验收：一个真实项目可以导出数据包、重新导入为新快照，并保留相同范围、数据目录、空间单元和证据索引。

### 阶段 B：只读 MCP

1. 实现项目、快照、数据集、空间单元和证据的只读 MCP 工具。
2. 使用项目配置让 Codex 连接本地 MCP 服务。
3. 为工具补充认证、项目权限、调用日志、分页和聚合限制。
4. 用 MCP Inspector 与 Codex 验证工具 schema、返回内容和错误状态。

验收：不打开 `/analysis` 时，Codex 可以识别项目、列出数据、查询 POI 或空间单元、读取证据并明确数据缺口。

### 阶段 C：RAG 项目化

1. 为文档、图片和网页证据绑定项目与快照范围。
2. 让证据检索结果带稳定定位和来源状态。
3. 从新运行链路移除将空间明细写入 RAG 的做法。
4. 将旧 PPT 来源导出收敛为项目数据包导入适配器。

验收：Agent 能同时回答“某类空间数据的统计结果”和“项目资料中对该问题的说明”，两种答案分别引用结构化数据和证据节点。

### 阶段 D：成果任务

1. 将商业分析骨架扩展为版本化报告任务。
2. 将 Stage 1 方法接入项目快照和空间单元任务。
3. 实现单元覆盖门槛、断点恢复和组合校验。
4. 让 PPT 任务只消费已审定成果，并完成 PPTX 渲染与文件交付。

验收：同一锁定快照可以生成商业报告、全空间单元策划和甲方 PPT；每项成果都能显示输入版本、证据和审批状态。

### 阶段 E：工作台收敛

1. 将 `/analysis` 页面调整为数据准备、地图核验和成果审定界面。
2. 隐藏或移除依赖浏览器临时状态的 Agent 入口。
3. 增加项目快照、空间单元、任务状态、成果库和审批入口。

验收：人员可在工作台完成数据准备后离开页面，Agent 仍可通过 MCP 完成后续工作。

## 11. 测试与质量门

- 项目快照测试覆盖范围、年份、来源、坐标、数据集版本和质量诊断；
- 数据包测试覆盖导出、导入、文件校验值和证据索引一致性；
- MCP 测试覆盖工具发现、认证、分页、聚合、项目隔离和文件引用；
- RAG 测试覆盖项目范围隔离、证据定位和结构化数据不进入语义检索；
- 商业报告测试覆盖模型降级、禁止伪精确结论和证据引用；
- 空间单元测试覆盖稳定 ID、几何校验、全量覆盖、受阻记录和组合校验；
- PPT 测试覆盖审定输入、逐页来源、PPTX 可打开、预览可生成和版面检查；
- 端到端测试使用真实项目样本，从快照构建到 MCP 查询再到成果下载。

## 12. 非目标

首期不提供官方 ESRI 数据承诺、真实消费或经营预测、自动替甲方批准成果、建筑施工设计或公开多租户运营。

首期不保留新旧数据契约并行运行。新项目使用项目快照和项目数据包；历史数据通过显式导入进入新契约。

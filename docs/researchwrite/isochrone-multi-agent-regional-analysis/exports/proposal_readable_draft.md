# 基于等时圈与多源空间数据的多智能体区域分析报告生成方法

- 文档类型：研究 proposal
- 版本：v2 可读版
- 日期：2026-08-15
- 状态：导师讨论稿

## 一句话说明

给定一个项目位置和“步行 15 分钟能到哪里”，本研究让多个分工明确的智能体调用 POI（点位及其栅格化结果）、人口、路网、夜光等多源空间数据和项目文档，并在共同栅格上进行必要的空间对齐，先查数据、再作判断、最后形成一份每项重要结论都能回到原始证据的区域分析报告。

## 摘要

假设规划人员需要分析一个城市更新项目。真正需要了解的并不只是项目周围一公里有什么，而是人在 15 分钟内沿道路能够到达哪些地方，这个范围内有哪些公共服务和商业设施，可能分布着哪些人，道路是否便于步行，夜间活动可能集中在哪里，以及项目受到哪些政策、权属、建筑和运营条件约束。

这些问题分别对应不同数据。兴趣点（POI）反映附近有什么设施，既可以保留点位，也可以按统一栅格聚合；人口网格描述人口的空间分布；路网反映如何到达以及道路是否连通；夜间灯光可作为活动强度的间接信号；栅格化结果是跨数据源比较的共同空间表达；H3 若继续保留，只用于 POI 的一种六边形聚合分析，不能代表全部数据的栅格底座；项目文档提供地图数据无法表达的政策和建设条件。它们的年份、坐标、精度和覆盖范围并不相同，不能直接拼在一起使用。

大语言模型可以快速写出流畅文本，但流畅不等于正确。模型可能把行政边界、直线距离和真实道路可达范围混在一起，也可能把 POI 数量直接写成消费需求，把夜光强度写成客流。如果报告没有记录每个数字来自哪里，使用者也很难复核。

本研究将建立一种以网络等时圈为统一分析范围的多智能体报告生成方法。系统先划定真实道路上的时间可达范围，再从多源数据库中提取并校验数据。不同智能体分别处理设施、客群、交通、项目条件和综合策略，最后通过范围核对、数值重算、证据检查和跨章节冲突检查形成报告。

研究将设置单智能体、静态证据包、无状态多智能体等对照，并结合重复运行和规划专家盲评，检验这种方法是否真正提高报告的空间一致性、数值正确性、证据可追溯性、分析完整性和使用价值。

当前参考工作流已经完成一次端到端运行，说明这条技术链路能够工作。但一次成功运行不能证明该方法优于其他方式。本 proposal 要回答的正是：哪些模块真的有用、改善有多大、在什么条件下会失效。

## 1. 研究背景

### 1.1 为什么不能只画一个圆

区域分析通常从“项目周边”开始，但“周边”并不是一个不言自明的范围。直径相同的圆，可能同时覆盖河流两岸、高速公路两侧或被封闭街区隔开的区域；地图上距离很近的设施，实际步行可能无法快速到达。行政边界虽然便于统计，也未必对应项目的真实服务范围。

等时圈是从一个起点出发，在规定时间内沿真实交通网络能够到达的范围。例如，“从项目入口步行 15 分钟”形成的边界会受到道路连通、过街条件和入口位置影响。既有研究表明，入口和网络结构的变化会改变可达人口和就业机会[1]。因此，等时圈比固定半径更适合回答“项目在时间上能够联系到哪里”。但它只表示潜在可达，不代表这些人一定会来，也不等于真实客流或市场需求。

### 1.2 数据分别回答什么

| 数据 | 它能帮助回答的问题 | 不能直接推出的结论 |
|---|---|---|
| POI | 附近有哪些学校、医院、商业、文体等设施，供给如何分布 | 有多少真实消费者、设施经营是否良好 |
| 人口网格 | 人口大致集中在哪里，不同片区的人口规模有何差异 | 具体人群偏好、即时在场人数 |
| 路网 | 人如何到达项目，道路是否连通，哪些方向可能形成阻隔 | 实际交通流量、步行体验的全部细节 |
| 夜间灯光 | 哪些区域在夜间可能更活跃，可用于比较活动强弱 | 精确客流、消费额或因果关系 |
| 统一栅格（含 POI 栅格化结果） | 将人口、夜光以及按规则聚合的 POI、路网指标放到共同空间单元中，便于局部比较 | 栅格值本身不代表客流、需求或唯一正确尺度 |
| H3（可选，POI 专项） | 为 POI 提供一种六边形聚合分析单元 | 不是全部数据的统一栅格底座，也不代表唯一正确尺度 |
| 项目文档 | 政策目标、权属、建筑现状、保护要求和运营条件 | 已经落实的建设或经营结果 |

多源数据整合不是简单地把文件放进同一个数据库。数据还需要统一坐标、统计范围和时间口径，并记录缺失情况。全球城市中心数据库的相关研究采用栅格对齐、分区统计和空间连接整合人口、夜光、可达性等信息[2]，说明“如何对齐”本身就是研究方法的一部分。

### 1.3 为什么需要受控的智能体工作流

CityGPT 和 PlanGPT 等研究表明，城市空间任务需要专门的城市知识、数据库检索和工具能力[3][4]。

Spatial-Agent 进一步指出，地理空间智能体即使给出看似合理的回答，也可能采用错误的计算顺序，因此需要把空间问题转化为可执行、可检查的工作流[5]。MapAgent 则说明，可以把总体规划与具体地图工具的执行分开，以降低复杂工具调用的负担[6]。

长篇报告还有一个额外风险：系统可能先形成结论，再寻找材料为结论补充引用。证据优先的报告生成研究将“查找证据、固定事实、生成文字”分成不同阶段[7]。对于区域分析，这种控制还必须加入地理范围、数据年份和统计方式，否则一句有来源的话也可能使用了错误的空间口径。

现有研究分别解决了可达范围、多源数据整合、规划语言模型、地图工具调用和证据控制问题，但尚未充分回答：如何把这些能力组织在同一个项目级流程中，并对最终区域分析报告的空间正确性和规划可用性进行完整评价。

## 2. 研究问题与假设

### 2.1 核心研究问题

在项目输入、语言模型和计算预算相同的条件下，以网络等时圈限定分析范围，让多个专业智能体通过受控工具查询多源空间数据库，能否比普通文本生成或单智能体生成得到更可靠的区域分析报告？如果能够，改善来自数据库、等时圈、多智能体分工还是质量检查；如果不能，主要在哪些环节失效？

这里的“更可靠”不凭阅读印象判断，而拆成可以检查的指标：空间范围是否一致，数字是否正确，事实能否找到出处，重要问题是否覆盖，章节之间是否矛盾，以及规划人员是否认为报告便于复核和使用。

### 2.2 待验证假设

- H1：与只向模型提供项目文字摘要相比，允许模型受控查询空间数据库，可提高报告的数值正确性和证据可追溯性。
- H2：与圆形缓冲区或边界不明确的分析相比，使用网络等时圈可提高不同数据之间的空间一致性；这一优势可能因入口错误或路网不完整而减弱。
- H3：与使用同一证据的单智能体相比，专业多智能体分工可覆盖更多有效分析问题；同时也可能带来重复、冲突和更高成本。
- H4：保存中间状态并设置质量检查可提高重复运行和失败恢复的稳定性，但不能保证规划判断本身一定正确。

### 2.3 研究目标

1. 建立一套以等时圈为共同范围的多源数据整理方法，使 POI（点位及栅格化结果）、人口、路网和夜光等数据能够按统一栅格和明确口径被共同使用；H3 仅作为可选的 POI 专项分析单元。
2. 建立一套“先计算事实、后进行解释”的多智能体分析方法，保存各阶段使用的数据、形成的判断和待核验问题。
3. 建立一套区域分析报告评价方法，用自动重算、对照实验、重复运行和专家盲评判断系统是否有效，并识别适用边界。

## 3. 研究方法

### 3.1 系统具体怎样工作

整个过程分为五步。

第一步是划定范围。系统接收项目位置、实际入口、出行方式和时间阈值，例如“从主入口步行 15 分钟”，沿路网生成等时圈。

第二步是准备证据。系统只在该等时圈内查询 POI、人口、路网和夜光数据，并按统一栅格进行局部对齐；POI 同时保留点位统计和栅格化结果。若启用 H3，仅用于 POI 专项空间结构分析；同时读取项目文档中的政策、权属、建筑和运营信息。每项结果保留数据年份、来源、查询条件和完整性说明。

第三步是分工分析。不同智能体分别检查数据范围、设施供给、潜在人群、交通联系、项目约束和综合策略。智能体不直接接收一份无法核验的长摘要，而是按任务调用工具取得所需证据。

第四步是交叉核对。系统区分数据库事实、文档事实、模型推断和待核验事项，并检查不同智能体之间是否使用了相同范围、年份和对象。出现证据冲突时，系统保留冲突，不强行合并成确定结论。

第五步是生成和审查报告。系统装配正文、图件、指标表和证据索引，再重算报告中的数字，检查章节矛盾，并标记把人口、夜光或 POI 过度解释为需求、客流和因果关系的句子。

```mermaid
flowchart LR
    A[项目位置与出行时间] --> B[生成网络等时圈]
    B --> C[查询多源数据]
    C --> D[专业智能体分工分析]
    D --> E[核对范围、数字与证据]
    E --> F[生成报告、图件与证据索引]
    F --> G[自动重算与专家评价]
```

### 3.2 怎样保证不同数据可比较

系统为每个案例生成一个固定的数据快照。所有查询都绑定同一个等时圈，并记录起点、入口、路网版本、速度假设、时间阈值和几何修复过程。入口不确定时，系统比较多个候选入口产生的范围差异，不把临时地图点当成真实入口。

POI 按类别和位置统计，并可按统一栅格聚合；人口和夜光栅格按与等时圈重叠的面积汇总；路网裁切到等时圈后计算连通与结构指标，并按需要聚合到栅格；统一栅格用于跨数据源的局部比较；若启用 H3，仅用于 POI 专项空间结构分析；项目文档按原文位置引用。无法对齐或年份不明的数据进入诊断清单，不用默认值悄悄补齐。

这里所说的“数据契约”，就是每项数据必须共同遵守的一组规则：属于哪个空间范围、采用什么坐标和年份、怎样统计、缺失到什么程度，以及如何找到原始记录。该规则由数据模块统一处理，避免每个智能体自行猜测。

### 3.3 多智能体如何分工

多智能体不是简单让多个模型各写一段。其作用是把需要不同证据和判断标准的任务分开：

- 范围与数据智能体检查等时圈、数据覆盖和统计口径。
- 设施与客群智能体分析具名设施、供给结构和可能服务的人群，但不把设施数量直接写成需求。
- 交通与空间智能体分析道路联系、入口、阻隔和局部差异。
- 项目文档智能体提取政策、权属、建筑与运营约束，并保留原文位置。
- 综合智能体比较不同判断，处理定位、产品、空间、运营和分期之间的矛盾。

每个智能体输出同一类结构化结果：使用了哪些证据、得到什么事实、作出什么推断、有哪些限制、下一步需要核验什么。后续智能体读取这些结构化状态，而不是反复压缩前文。这既便于追踪，也能测试“分工”本身是否带来增益。

### 3.4 报告如何接受检查

系统对成文结果执行四类核心检查：

1. 范围检查：报告中的空间事实是否确实来自目标等时圈。
2. 数值检查：报告数字能否由数据库查询重新计算出来。
3. 一致性检查：不同章节的对象、年份、定位和建议是否互相冲突。
4. 边界检查：是否把代理指标误写成需求、客流、收益或因果事实。

未通过检查的内容被退回修订或标记为“证据不足”。质量检查的目标不是让文字更长，而是让读者知道哪些结论可靠、哪些只是推断、哪些仍需现场调查。

## 4. 实验设计

### 4.1 案例与控制条件

长沙县政府旧址作为种子案例，用来固定任务定义、数据格式和错误类型。正式评价将选择不同城市形态、设施密度、路网连通性、数据完整度和项目类型的案例，至少覆盖中心城区、一般建成区和边缘区，并保留未参与调试的独立测试案例。

每个案例固定项目材料、数据库版本、模型版本、提示词和计算预算。步行等时圈是主要设置，并比较不同时间阈值。正式案例数和重复次数将在预实验取得运行方差和专家评分方差后确定，避免在没有依据时预设样本量。

### 4.2 比较哪些方法

研究采用基线和消融实验。“基线”是用于比较的较简单方法；“消融”是逐项移除某个模块，观察报告质量怎样变化，从而判断改善来自哪里。

| 编号与条件 | 可以使用的证据 | 智能体形式 | 要回答的问题 |
|---|---|---|---|
| B0 文本生成基线 | 只有项目文字摘要 | 单智能体 | 纯语言模型能做到什么程度 |
| B1 静态证据包 | 一次性提供相同数据的文字或表格摘要 | 单智能体 | 改善是否只来自提供了更多信息 |
| B2 数据库工具版 | 可使用与完整方法相同的查询工具 | 单智能体 | 专业分工是否有额外作用 |
| B3 无状态多智能体 | 可使用相同工具，但不保存阶段状态，不设质量检查 | 多智能体 | 状态保存和质量检查是否有作用 |
| M 完整方法 | 等时圈、多源数据库、阶段状态和质量检查 | 专业多智能体 | 检验目标方法的整体表现 |

所有条件尽量使用相同模型、输入和预算。MultiCa 只有在模型、工具权限、输入和预算均可匹配时，才可作为 B3 的一个实现；否则只作为探索性案例讨论，不能用其一次较弱产出来证明某类多智能体方法无效。N8N 也只是当前参考实现，不是论文贡献本身。

研究还将比较网络等时圈、等面积圆形缓冲区和行政单元，以观察范围选择怎样改变统计结果和报告判断。

### 4.3 如何判断报告更好

| 评价维度 | 具体检查方法 |
|---|---|
| 空间一致性 | 报告中的空间事实是否遵守目标范围、坐标、年份和统计口径 |
| 数值正确性 | 可审计数字与数据库重算结果在允许误差内一致的比例 |
| 证据可追溯性 | 事实性主张能够定位到查询结果、项目文档或计算记录的比例 |
| 分析完整性 | 预先定义的重要问题被有效回答的比例，排除重复和无证据扩写 |
| 跨章节一致性 | 对象、范围、年份、判断和建议之间的矛盾数量及严重程度 |
| 边界纪律 | 把代理指标误写成需求、客流、因果或财务事实的次数 |
| 重复稳定性 | 相同条件多次运行时，事实、排序和关键判断的一致程度 |
| 专家可用性 | 规划专家对可信度、解释力、可复核性和决策价值的盲评分 |
| 成本与恢复 | 运行时间、模型调用、token、失败率和恢复后的状态正确性 |

自动检查结果将抽样人工复核。专家评审隐藏报告来源，原则上由不少于 3 名具有城市规划或空间分析经验的评审者独立完成。预实验后再固定正式量表、样本量和一致性指标。统计分析优先报告差异大小和置信区间，并控制案例和重复运行带来的差异，不以一次结果或单一显著性检验代替实际效果解释。

### 4.4 主动测试哪些失败情况

研究将设置四类困难条件：POI 分类缺失或过密，人口与夜光年份不一致，路网断裂或入口错误，项目文档互相冲突。系统在这些条件下不一定要给出完整答案，更重要的是能否发现问题、降低结论强度、停止无效分析或明确要求人工核验。

## 5. 预期贡献

本研究预期形成四项可检验的方法贡献。

1. 以等时圈作为整份报告的共同空间边界，使数据、指标和文字判断使用同一可达范围。
2. 将数据库计算与规划解释分开，明确区分数据事实、文档事实、模型推断和待核验事项。
3. 建立面向区域分析的多智能体协作方式，使各专业任务共享可追踪的阶段结果，而不是只交换长篇文本。
4. 建立同时关注空间正确性、证据来源和规划使用价值的报告评价协议，并通过对照与消融识别各模块的实际作用。

这些都是需要实验检验的预期贡献，不是已经得到证明的优势。方法也不绑定 N8N、MultiCa 或某一模型品牌，只要其他平台实现相同的数据规则、工具接口、阶段状态和评价协议，就可以参加复现和比较。

## 6. 前期基础与现状边界

项目已经具备等时圈、POI、统一栅格结果、路网、人口、夜光、项目文档读取和报告导出能力。当前 N8N 参考工作流包含 90 个节点，可保存步骤状态、证据、诊断和最终报告，也支持失败后的状态恢复。

2026 年 8 月 14 日，运行 `825d012f-3585-4acf-babf-2e26bc94b80e`（执行编号 `2039`）完成了 12 个分析步骤，生成约 59,218 字符的报告和 4 张图件。

该案例使用的项目上下文包括 2,635 个 POI、1,294 个路网节点、1,354 条路网边、439 个人口网格、439 个夜光网格和多份项目文档。

这次运行说明从数据库查询、分步分析到报告装配的链路可以工作，也暴露了不同数据年份、坐标、覆盖完整度和缺失原因不一致的问题。它不能证明报告质量已经提高，更不能支持跨城市结论。后续研究的重点正是建立公平对照、重复实验和独立评价。

## 7. 风险与替代路线

| 风险 | 可能影响 | 处理方式 |
|---|---|---|
| 不同案例的数据覆盖差异过大 | 无法公平比较报告 | 设定最低数据准入标准，并把缺失数据作为单独压力测试 |
| 入口或路网错误 | 错误范围会传导到全文 | 比较候选入口、记录路网版本；无法确认时只作探索性分析 |
| 模型或提示词差异 | 无法判断改善来自哪个模块 | 固定模型、输入和预算，采用逐项消融 |
| 多智能体只增加篇幅 | 完整性分数可能虚高 | 按有效问题和可核验主张计分，同时统计重复与矛盾 |
| 专家评分主观 | 评价结果不稳定 | 隐藏系统来源、统一量表、使用多名评审并报告一致性 |
| 自动检查遗漏语义错误 | 数字正确但解释错误 | 自动检查与专家审查并行，抽样回查证据链 |
| 完整方法未优于单智能体 | 核心假设不成立 | 如实报告无增益结果，保留有效模块，收缩为数据库增强单智能体方法 |

研究结论只适用于具有可用路网、明确范围参数和最低数据覆盖的项目级区域分析。系统不验证真实客流、商业收益、政策合法性或最终设计效果，也不能替代现场调查、公众参与和法定规划程序。

## 8. 研究计划

| 阶段 | 月份 | 主要工作 | 阶段完成标准 |
|---|---:|---|---|
| 方法固定 | 1-2 | 固定任务、数据规则、术语、错误类型和评价量表 | 同一案例可重复生成并接受自动检查 |
| 基线与消融实现 | 3-4 | 建立 B0-B3 和完整方法，匹配模型、输入与预算 | 每个条件均可独立复现 |
| 预实验 | 5-6 | 重复运行种子案例，开展专家试评，修订指标 | 指标可操作，专家评分具有基本一致性 |
| 跨案例评价 | 7-9 | 测试异质案例、不同范围和缺失数据条件 | 获得完整实验矩阵和失败记录 |
| 分析与复核 | 10-11 | 数据库重算、统计分析、错误归因和专家复核 | 每个主要结论可回到实验结果 |
| 论文与发布 | 12 | 完成论文、方法文档、评价集说明和复现材料 | 删除未验证主张，复现实验通过 |

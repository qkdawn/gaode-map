# 面向城市空间决策的多源空间证据驱动智能体方法研究

- 文档类型：研究 proposal
- 版本：v1
- 日期：2026-08-21
- 状态：导师讨论稿

## 摘要

区域分析需要在明确的可达范围内综合设施供给、人口分布、道路结构、活动强度和项目材料，并将不同数据转化为能够被规划人员复核的判断。现有大语言模型能够生成流畅的回答和规划文本，但如果空间范围、数据版本、计算顺序和证据来源没有被显式控制，各类成果都可能混用行政边界、圆形缓冲区和真实网络可达范围，也可能把 POI 数量、人口估算或夜光强度直接解释为需求和客流。

本研究拟提出一种面向城市空间决策的多源空间证据驱动智能体方法。该方法将保存的项目范围与网络等时圈作为空间语境约束，通过受控领域工具按需查询 POI、人口、路网、夜光、项目文档和公共知识，并把任务理解、空间计算、证据核验、专业判断和成果交付组织为可追溯、可恢复的任务链。系统既支持围绕地图项目的连续问答，也支持由专业决策单元完成复杂分析并生成备忘录、图件和完整报告。研究将通过匹配模型、输入和计算预算的任务集比较、模块消融、重复运行与规划专家盲评，检验该方法是否改善工具执行正确性、空间一致性、证据支持度、决策连贯性、交互质量和成果可用性。

当前系统已具备正常对话入口，并完成一次包含 12 个分析步骤、图件和正式报告的复杂任务端到端运行。这证明系统具备开展智能体研究的工程基础，但不构成方法有效性或跨城市泛化证据。本 proposal 的目标是建立可复现的城市空间智能体方法、任务集与评价协议，而不是预设智能体能够替代规划师。

## 1. 研究背景与问题

区域分析的首要问题不是生成多少指标，而是确定哪些对象处于同一可比较范围。传统行政边界便于统计，却未必对应项目的真实到达条件；固定半径缓冲区忽略道路连通、入口位置、过街条件和出行方式差异。等时圈以交通网络上的旅行时间界定可达范围，能够显式表达入口和路网结构对服务范围的影响。Lahoorpoor 与 Levinson 通过 5、10、15 分钟步行等时圈研究车站入口调整，证明入口和网络结构会改变可达人口与就业机会[1]。因此，等时圈适合成为项目级区域分析的空间入口，但它仍只是潜在可达范围，不能直接代表真实到访或需求。

在空间范围确定后，区域判断还依赖异构数据的对齐。POI 描述设施分布，人口网格提供居住或人口代理，路网反映通行结构，夜光可作为活动强度代理，项目文档则包含权属、政策、建筑和运营约束。这些数据具有不同的坐标系、分辨率、年份、几何类型和缺失模式。全球城市中心数据库的建设经验表明，多源城市数据必须经过栅格对齐、分区统计和空间连接，才能形成可比较的城市属性[2]。如果这些处理被隐藏在一次性文本摘要中，生成模型无法判断指标是否来自同一范围，也无法识别边界效应和数据缺失。

智能体技术为城市空间分析提供了新的交互与执行方式，但空间任务对模型提出了不同于一般问答和文本生成的要求。CityGPT 通过城市指令数据与专门基准增强并评价模型的城市空间认知[3]；PlanGPT 将本地数据库检索、领域数据和工具能力引入规划语言任务[4]；Spatial-Agent 指出地理空间智能体可能产生直觉合理但计算顺序错误的工作流，并以可执行概念转换图约束空间分析[5]；MapAgent 则通过层级规划与地图工具执行分离降低复杂 API 的选择负担[6]。这些工作共同说明，规划语言能力、空间计算能力、证据检索和工具执行需要被共同设计，但它们尚未直接回答项目级智能体如何在持续对话与复杂决策中共享空间语境、稳定领域状态和可核验证据。

本研究据此提出一个可检验问题：在相同项目输入和模型条件下，以项目范围和网络等时圈约束空间语境，通过受控领域工具持续获取多源空间证据，并以可恢复的决策状态组织复杂任务，能否提高城市空间决策智能体的工具执行正确性、空间一致性、证据可追溯性、决策连贯性和成果可用性？

## 2. 相关研究与研究缺口

### 2.1 从几何邻近到网络时间可达范围

可达性研究已形成从固定距离、累计机会到网络旅行时间等多种测度。等时圈的优势在于把道路网络、出行方式和时间阈值纳入范围构建[1]，但其结果依赖起点、入口、速度、网络完整性和时段条件。现有工作多将等时圈用于设施可达性或交通服务评价，较少研究等时圈如何成为项目级智能体在连续问答、工具查询、决策判断和成果生成中的统一空间语境契约。

### 2.2 多源城市数据整合

人口、夜光、POI、道路与环境数据已广泛用于城市功能、活力、可达性和发展状态分析。相关数据库通常使用统一空间实体、栅格对齐、分区统计和空间连接完成多源整合[2]。这一研究线提供了可靠的数据处理基础，但通常输出指标或地图，不直接研究语言模型如何在保留数据来源、年份和完整性诊断的条件下调用这些结果并形成规划解释。

### 2.3 规划大模型与地理空间智能体

PlanGPT 表明领域数据库检索和专门工具能够改善规划语言任务适配[4]；CityGPT 将城市空间理解拆解为城市意象、城市语义、空间推理和综合任务[3]。地理空间智能体研究进一步把自然语言问题转化为可执行工作流。Spatial-Agent 使用空间科学概念约束转换顺序[5]，MapAgent 将高层规划与地图工具执行分离，以降低复杂 API 选择负担[6]。这些工作侧重问答、空间推理、地图工具或单类规划任务，仍缺少覆盖项目级连续问答、空间取证、综合决策和多形态成果交付的统一评价协议。

### 2.4 证据控制与长篇成果生成

检索增强生成能够把外部知识引入模型，但智能体回答与长篇成果仍可能先形成叙事，再为既有结论补充引用。EFSG 将证据检索、事实固定和成文分成明确阶段，并用句子支持度与信息覆盖度评价报告[7]。城市空间任务比一般文本任务多了一层空间约束：回答与成果不仅需要来源支持，还必须使用正确的地理范围、数据版本、计算顺序和聚合方法。因此，本研究的缺口不是简单增加 RAG 或报告模板，而是建立“任务理解—空间范围—领域工具—证据核验—专业决策—多成果交付—能力评价”的完整智能体方法链。

## 3. 科学问题、假设与研究目标

### 3.1 核心科学问题

多源空间证据驱动智能体如何围绕项目范围完成可执行、可追溯且具有规划解释力的连续问答与复杂决策，其能力增益分别来自哪些方法模块，又在哪些数据与任务条件下失效？

### 3.2 待验证假设

- H1：相较只提供项目文本摘要的通用模型，受控领域工具能够提高空间任务执行正确性和证据可追溯性。
- H2：相较圆形缓冲区或未声明的混合范围，网络等时圈能够提高跨数据源的空间一致性，但其优势会受到入口与路网数据质量影响。
- H3：相较一次性静态证据注入，按需取证与证据核验能够提高对话回答和决策主张的支持度。
- H4：专业决策单元、领域结果持久化和统一蓝图能够提高复杂任务覆盖、决策连贯性与成果复用能力，但不保证规划结论本身正确。

### 3.3 研究目标

1. 建立以等时圈为范围契约的多源空间数据库整合方法，明确数据版本、坐标、聚合单元、完整性和边界诊断。
2. 建立多源空间证据驱动的城市空间决策智能体方法，将任务理解、空间计算、证据核验、专业判断和成果交付分层，并保留稳定领域状态。
3. 建立覆盖连续问答、工具执行、空间分析、综合决策和多形态成果的评价任务集，通过自动重算、消融实验、重复运行和专家盲评检验方法有效性、成本和适用边界。

## 4. 研究内容与方法

### 4.1 任务定义

研究输入由项目范围与锚点、出行方式、时间阈值、空间数据库、项目文档和用户任务构成。系统在保存范围内形成带版本的数据快照，并按任务决定是否生成网络等时圈。输出可以是连续对话答案、证据核验结果、空间分析、决策备忘录、图件或完整报告，而不是法定规划方案。所有成果中的事实性主张必须能够回溯到项目文档、数据库查询或计算结果；推断性主张必须标记条件与替代解释。

### 4.2 等时圈范围与数据契约

该模块接收起点、真实入口、出行方式和时间阈值，通过路网引擎生成等时圈几何。为识别范围定义带来的影响，系统同时保存输入坐标、路网版本、速度模型、时间阈值和几何修复记录。对于入口不确定的项目，采用候选入口敏感性分析，而不是将临时参照点当作真实入口。

所有数据查询均绑定等时圈与同一项目快照。POI 同时保留点落区、类别统计和按共同栅格聚合的结果；人口与夜光栅格按覆盖比例聚合；路网按等时圈裁切并计算网络结构指标，再按需要汇总到共同栅格；共同栅格用于跨数据源对齐和局部比较；H3 若启用，仅用于 POI 专项六边形聚合；项目文档按原文位置读取。每个结果保存数据集 ID、年份、坐标类型、记录数、查询参数、完整性状态和校验和。无法对齐的数据不做静默填补，而进入诊断清单。

面向业务智能体的空间入口不直接暴露表名、任意 SQL、原始 geometry、GIS 库操作、指标目录、证据域或计算模式。决策与写作 Agent 只提交需要回答的完整空间问题；可复用空间工具 Agent 使用空间知识拆分子问题，选择 POI、人口、夜光、路网、可达性、局部空间关系或具名对象等证据域，以及范围、真实时间可达性、八方向、邻域、排序、跨域关系和具名记录展开等空间关系，并综合多次工具结果。底层确定性计算入口不接收问题，也不返回问题复述或自然语言结论；当前参考实现内部连接的 57 个指标绑定或指标策略只是取得具体度量的实现基础。具体指标由领域模块按证据域和空间关系确定，并在结果中披露供复核。该设计需要分别评价空间工具 Agent 的任务分解、工具选择与综合质量，以及底层计算的数值正确性和可复现性。

### 4.3 多源空间证据驱动的智能体任务链

智能体不直接接收全部原始数据，而通过受控领域工具按任务读取。短周期对话根据当前问题选择范围、结果、POI、数据集或证据节点；复杂任务则由专业决策单元处理区域角色、使用者、供给、定位、产品、空间、运营、投入和分期问题。两种任务都必须区分数据库事实、文档事实、模型推断和待核验项，并在证据足够时停止继续取证。

当前完整报告链以 N8N 作为业务阶段的参考编排，负责触发、排队、阶段保存、恢复和交付；Codex Harness 负责模型上下文、工具调用和结构化输出；项目领域模块负责空间工具、决策结果、引用和产品状态。具体平台不写入方法定义，只要其他实现遵守相同的空间范围、领域工具、稳定结果和评价协议，也应能够复现研究方法。

### 4.4 领域状态与多成果交付

短周期对话保存 canonical assistant message、引用和必要会话状态；复杂任务保存稳定的领域决策与统一蓝图，后续阶段通过 Harness 按需读取，而不是继承完整工具正文和内部消息。成果可以被投影为自然回答、决策备忘录、图件、Markdown 或 DOCX。交付前执行范围、数值、证据支持、一致性和边界检查；未通过检查的内容进入修订、降级或失败状态，不能通过增加文字掩盖缺口。

## 5. 实验设计与评价方案

### 5.1 案例与数据组织

长沙县政府旧址作为种子案例，用于冻结任务定义、数据契约和错误类型。后续评价集按城市形态、设施密度、路网连通性、数据完整性和项目类型选择异质案例。正式案例数量不在 proposal 阶段凭经验指定，将在预实验获得运行方差和专家评分方差后确定；原则上评价集至少覆盖中心城区、一般建成区和边缘区三类空间条件，并保留独立案例作为测试集。

每个案例固定项目材料、数据库版本、模型版本、提示词版本和计算预算。步行等时圈作为主设置，并选择不同时间阈值进行敏感性分析。只有数据许可和网络参数充分时才扩展至骑行或驾车模式。

### 5.2 智能体任务集

评价集按同一项目事实设计五类任务。T1 连续空间问答检验问题理解、必要澄清、追问连续性和回答支持度；T2 证据查询与核验检验工具选择、参数、引用和缺口诊断；T3 可执行空间分析检验等时圈、方向、邻域、排序和关系分析的调用顺序与结果消费；T4 综合决策任务检验定位、产品、空间、运营和分期等问题的覆盖与连贯性；T5 多形态成果生成检验对话答案、决策备忘录、图件和完整报告之间的一致性与可用性。完整报告是 T4 与 T5 的综合压力任务，不能替代 T1 至 T3 的独立评价。

### 5.3 基线与消融

| Condition | Evidence access | Agent structure | Purpose |
|---|---|---|---|
| B0 通用模型基线 | 项目摘要，无结构化空间查询 | 单轮或普通对话模型 | 检验纯语言能力 |
| B1 静态证据智能体 | 相同数据被压缩为一次性文本或表格 | 通用智能体 | 区分按需查询与静态信息注入 |
| B2 通用工具智能体 | 与完整方法相同的领域工具 | 通用 ReAct/Harness 智能体 | 检验领域任务组织的增量 |
| B3 无持久化复杂任务 | 相同工具和专业决策单元，不保存稳定领域结果 | 多阶段智能体 | 检验持久化和按需读取的增量 |
| M 目标方法 | 范围约束、领域工具、证据核验和持久化决策 | 城市空间决策智能体 | 目标方法 |

如果 MultiCa 能够在相同模型、输入、工具权限和预算下运行，可作为 B3 的一个实现；若条件不匹配，其结果只进入定性案例讨论。范围消融另行比较网络等时圈、等面积圆形缓冲区和行政单元，观察边界选择对问答事实、空间分析结果、综合决策和长篇成果的影响。

T2 与 T3 另设工具接口消融：在底层空间计算、数据版本和模型保持一致的条件下，比较低层 dataset query/aggregate 工具与七类语义化空间证据入口。评价工具选择、必需参数正确率、无效调用次数、空间计算顺序、证据消费正确率、token 和完成时长，用于识别语义工具本身的增量。

### 5.4 评价指标

| Dimension | Operational measure |
|---|---|
| 任务完成率 | 无需人工补写执行步骤即可完成目标任务的比例 |
| 工具执行正确性 | 工具选择、参数、调用顺序和结果消费正确的比例 |
| 空间一致性 | 空间事实遵守目标范围、坐标、年份与聚合口径的比例 |
| 数值正确性 | 可审计数字与数据库重算结果在容差内一致的比例 |
| 证据支持度 | 事实性主张可定位且确实被数据查询、项目文档或计算结果支持的比例 |
| 分析完整性 | 预定义有效分析维度的覆盖率，排除重复段落与无证据扩写 |
| 决策与跨产物一致性 | 对象、范围、数据和判断在回答、备忘录、图件与报告中的矛盾数量及严重度 |
| 交互质量 | 澄清是否必要、追问是否继承有效上下文、运行状态是否可理解 |
| 边界纪律 | 将代理指标误写为需求、客流、因果或财务事实的次数 |
| 重复稳定性 | 相同条件重复运行时事实、排序和关键判断的一致程度 |
| 专家可用性 | 规划专家对可信度、解释力、可复核性和决策支持价值的盲评分 |
| 成本与恢复 | 时间、模型调用、token、失败率和恢复后状态正确性 |

自动指标由数据库查询和规则校验生成，并抽样人工复核。专家评审隐藏系统来源，原则上由不少于 3 名具有城市规划或空间分析经验的评审者独立完成；预实验后确定正式样本量、评分量表与一致性指标。统计分析优先报告效应量和置信区间，并使用能够控制案例差异和重复运行差异的分层或混合效应模型；不以单一显著性检验代替实际差异解释。

### 5.5 压力测试与失败模式

研究将主动测试四类困难条件：POI 分类缺失或过密、人口与夜光年份不一致、路网断裂或入口错误、项目文档相互冲突。每类条件分别观察系统是否拒绝无效查询、暴露诊断、降低主张强度或错误地产生确定性建议。方法成功不仅表现为完成任务，也包括在证据不足时停止、降级或明确请求核验。

## 6. 预期方法贡献

1. 建立以保存项目范围和网络等时圈约束智能体空间语境的方法，使对话、工具查询和复杂决策遵守共同空间边界。
2. 建立领域工具执行先于规划解释的分层结构，区分空间计算、事实提取、模型推断和用户可见成果。
3. 建立面向城市空间复杂任务的稳定领域状态模型，使对话、决策、图件和报告复用领域结果，而不是反复压缩工具正文。
4. 建立覆盖任务完成、工具执行、空间正确性、证据支持、决策连贯、交互质量和成果可用性的智能体评价协议。

这些贡献均为研究目标，不在实验完成前写成已证实优势。创新边界也不依赖 N8N、MultiCa 或某一特定模型品牌，而取决于方法接口和评价协议能否被复现。

## 7. 前期基础与可行性

当前项目已经具备正常对话、等时圈、POI、路网、人口、夜光、项目文档、空间证据工具和报告导出等能力。正常对话能够围绕当前地图连续追问、按需调用工具并通过 SSE 返回回答；正式报告参考工作流当前由 68 个 N8N 节点组成，通用模型与 MCP 通讯已交由 Codex Harness。2026-08-21 的运行 `b8a2df1a-0e36-48a3-8f63-877b0014686f` 完成 12 个专业决策单元、统一蓝图、9 个章节和 5 张数据图件，并生成有效的 Markdown 与 DOCX。相关领域测试覆盖对话请求与恢复、工作流节点、工具契约、领域结果读取、失败恢复和报告装配。

这些基础降低了从零建设系统的风险，使研究可以把资源集中到方法冻结、任务集建设、基线控制、自动评价和专家实验。但当前证据仍有三个限制：只有一个主案例；复杂任务运行时间较长；T1 至 T5 的智能体能力尚未经过匹配基线、盲评和系统审计。因此，前期基础证明的是“可以开展研究”，不是“研究假设已经成立”。

## 8. 风险、边界与替代路线

| Risk | Impact | Mitigation / fallback |
|---|---|---|
| 不同案例数据覆盖差异过大 | 无法公平比较任务成果 | 建立最低数据准入标准，并单独报告缺失数据压力测试 |
| 等时圈入口或路网不可靠 | 范围错误传导至下游任务 | 入口敏感性分析、路网版本记录和范围诊断；无法确认时降级为探索性范围 |
| 模型和提示词差异混淆方法效果 | 无法归因数据库或多智能体贡献 | 固定模型与预算，采用模块消融而非平台品牌比较 |
| 专业决策单元增加篇幅但不增加有效分析 | 完整性指标被虚高 | 按有效问题和可核验主张计分，同时记录重复与矛盾 |
| 专家评分主观 | 方法评价不稳定 | 盲评、统一量表、培训样例与评审一致性分析 |
| 自动校验遗漏语义错误 | 数值正确但判断错误 | 自动指标与专家评审并行，抽样复核证据链 |
| 完整方法未优于通用工具智能体 | 核心假设不成立 | 如实报告无增益结果，识别有效模块并收缩为范围约束或领域工具方法 |

研究结论只适用于具备可用路网、明确范围参数和最低数据覆盖的项目级区域分析。它不验证真实客流、商业收益、政策合法性或最终设计效果，也不替代现场调查、公众参与和法定规划程序。

## 9. 研究计划

| Phase | Months | Main work | Gate |
|---|---:|---|---|
| 方法冻结 | 1-2 | 固定 T1-T5 任务、数据契约、术语、错误类型和评价量表 | 同一案例各类任务可重复执行并完成自动检查 |
| 基线与消融实现 | 3-4 | 建立 B0-B3 与完整方法，匹配模型、输入和预算 | 每个条件可独立复现 |
| 预实验 | 5-6 | 种子案例重复运行、专家试评、修订指标 | 指标可操作，专家评分具有基本一致性 |
| 跨案例评价 | 7-9 | 异质案例、范围敏感性和缺失数据压力测试 | 获得完整实验矩阵与失败记录 |
| 分析与复核 | 10-11 | 数据库重算、统计分析、错误归因和专家复核 | 每个主张可追溯到实验结果 |
| 论文与发布 | 12 | 完成论文、方法文档、评价集说明和可复现材料 | 不含未验证主张，复现实验通过 |

## 10. 预期成果

1. 一套多源空间证据驱动的城市空间决策智能体方法及参考实现。
2. 一套覆盖对话、工具执行、空间分析、复杂决策和成果生成的任务集与评价协议。
3. 关于空间范围、领域工具、按需取证、决策状态和专业任务分解各自作用的实验结果，包括无增益或失败结果。
4. 一篇面向城市计算、GeoAI、规划支持系统或智能体应用方向的方法论文。
5. 可供后续项目复用的数据契约、领域成果契约和诊断规范。

# 面向等时圈区域分析报告生成的多源空间数据库增强多智能体方法

- 文档类型：研究 proposal
- 版本：v1
- 日期：2026-08-15
- 状态：导师讨论稿

## 摘要

区域分析需要在明确的可达范围内综合设施供给、人口分布、道路结构、活动强度和项目材料，并将不同数据转化为能够被规划人员复核的判断。现有大语言模型能够生成流畅的规划文本，但如果空间范围、数据版本、计算顺序和证据来源没有被显式控制，报告可能混用行政边界、圆形缓冲区和真实网络可达范围，也可能把 POI 数量、人口估算或夜光强度直接解释为需求和客流。

本研究拟提出一种面向等时圈区域分析报告生成的多源空间数据库增强多智能体方法。该方法先根据起点、出行方式和时间阈值构建网络等时圈，在统一坐标和共同栅格口径下查询 POI（点位及栅格化结果）、人口、路网、夜光等数据和项目文档；H3 若启用，仅用于 POI 专项六边形聚合分析。随后由边界明确的专业智能体完成数据诊断、空间解释、交叉检验和报告装配。研究将通过匹配模型、输入和计算预算的基线比较、模块消融、重复运行与规划专家盲评，检验该方法是否改善报告的空间一致性、数值正确性、证据可追溯性、分析完整性、跨章节一致性和专家可用性。

当前 90 节点参考工作流已完成一次包含 12 个分析步骤、4 张图件和约 5.9 万字符报告的端到端运行。这证明系统链路具备工程可行性，但不构成方法有效性或跨城市泛化证据。本 proposal 的目标是建立可复现的方法与评价协议，并明确其适用边界，而不是预设自动生成报告必然优于规划师或其他智能体系统。

## 1. 研究背景与问题

区域分析的首要问题不是生成多少指标，而是确定哪些对象处于同一可比较范围。传统行政边界便于统计，却未必对应项目的真实到达条件；固定半径缓冲区忽略道路连通、入口位置、过街条件和出行方式差异。等时圈以交通网络上的旅行时间界定可达范围，能够显式表达入口和路网结构对服务范围的影响。Lahoorpoor 与 Levinson 通过 5、10、15 分钟步行等时圈研究车站入口调整，证明入口和网络结构会改变可达人口与就业机会[1]。因此，等时圈适合成为项目级区域分析的空间入口，但它仍只是潜在可达范围，不能直接代表真实到访或需求。

在空间范围确定后，区域判断还依赖异构数据的对齐。POI 描述设施分布，人口网格提供居住或人口代理，路网反映通行结构，夜光可作为活动强度代理，项目文档则包含权属、政策、建筑和运营约束。这些数据具有不同的坐标系、分辨率、年份、几何类型和缺失模式。全球城市中心数据库的建设经验表明，多源城市数据必须经过栅格对齐、分区统计和空间连接，才能形成可比较的城市属性[2]。如果这些处理被隐藏在一次性文本摘要中，生成模型无法判断指标是否来自同一范围，也无法识别边界效应和数据缺失。

大语言模型为复杂报告生成提供了新的技术路径，但城市空间任务对模型提出了不同于一般文本生成的要求。CityGPT 通过城市指令数据与专门基准增强并评价模型的城市空间认知[3]；PlanGPT 将本地数据库检索、领域数据和工具能力引入规划语言任务[4]；Spatial-Agent 则指出地理空间智能体可能产生直觉合理但计算顺序错误的工作流，并以可执行概念转换图约束空间分析[5]。这些工作共同说明，规划语言能力、空间计算能力和数据库检索能力需要被共同设计，但它们尚未直接回答项目级长篇区域分析报告如何在一个统一等时圈内持续调用多源数据库、形成跨章节判断并保留完整证据链。

本研究据此提出一个可检验问题：在相同项目输入和模型条件下，以等时圈作为统一空间范围、通过受控工具接入多源空间数据库并采用专业多智能体工作流，是否能够提高区域分析报告的空间一致性、数值正确性、证据可追溯性、分析完整性、跨章节一致性和专家可用性？

## 2. 相关研究与研究缺口

### 2.1 从几何邻近到网络时间可达范围

可达性研究已形成从固定距离、累计机会到网络旅行时间等多种测度。等时圈的优势在于把道路网络、出行方式和时间阈值纳入范围构建[1]，但其结果依赖起点、入口、速度、网络完整性和时段条件。现有工作多将等时圈用于设施可达性或交通服务评价，较少研究等时圈如何作为长篇区域分析报告中所有数据库查询、指标计算和叙事判断的统一范围契约。

### 2.2 多源城市数据整合

人口、夜光、POI、道路与环境数据已广泛用于城市功能、活力、可达性和发展状态分析。相关数据库通常使用统一空间实体、栅格对齐、分区统计和空间连接完成多源整合[2]。这一研究线提供了可靠的数据处理基础，但通常输出指标或地图，不直接研究语言模型如何在保留数据来源、年份和完整性诊断的条件下调用这些结果并形成规划解释。

### 2.3 规划大模型与地理空间智能体

PlanGPT 表明领域数据库检索和专门工具能够改善规划语言任务适配[4]；CityGPT 将城市空间理解拆解为城市意象、城市语义、空间推理和综合任务[3]。地理空间智能体研究进一步把自然语言问题转化为可执行工作流。Spatial-Agent 使用空间科学概念约束转换顺序[5]，MapAgent 将高层规划与地图工具执行分离，以降低复杂 API 选择负担[6]。这些工作侧重问答、空间推理、地图工具或规划任务，仍缺少针对“多源空间数据库到长篇区域分析报告”全过程的评价协议。

### 2.4 长篇报告生成与证据控制

检索增强生成能够把外部知识引入模型，但报告生成仍可能先形成叙事，再为既有结论补充引用。EFSG 将证据检索、事实固定和成文分成明确阶段，并用句子支持度与信息覆盖度评价报告[7]。规划报告比一般技术报告多了一层空间约束：句子不仅需要文献支持，还必须使用正确的地理范围、数据版本和聚合方法。因此，本研究的缺口不是简单增加 RAG，而是建立“等时圈范围—空间查询—指标计算—专业解释—报告装配—质量评价”的完整方法链。

## 3. 科学问题、假设与研究目标

### 3.1 核心科学问题

多源空间数据库与专业多智能体如何围绕同一等时圈形成可计算、可追溯且具有规划解释力的区域分析报告，其质量增益分别来自哪些方法模块，又在哪些数据与任务条件下失效？

### 3.2 待验证假设

- H1：相较只提供项目文本摘要的生成方式，受控空间数据库查询能够提高报告的数值正确性和证据可追溯性。
- H2：相较圆形缓冲区或未声明的混合范围，网络等时圈能够提高跨数据源的空间一致性，但其优势会受到入口与路网数据质量影响。
- H3：相较使用同一证据包的单智能体生成，专业多智能体分工能够提高有效分析维度覆盖率，但可能增加重复、矛盾和计算成本。
- H4：状态持久化、质量门槛和报告装配规则能够提高重复运行稳定性与失败恢复能力，但不保证规划结论本身正确。

### 3.3 研究目标

1. 建立以等时圈为范围契约的多源空间数据库整合方法，明确数据版本、坐标、聚合单元、完整性和边界诊断。
2. 建立数据库增强的专业多智能体分析与报告生成方法，将空间计算、规划解释和报告装配分层，并保留可追溯的中间状态。
3. 建立区域分析报告评价基准，通过自动重算、消融实验、重复运行和专家盲评检验方法有效性、成本和适用边界。

## 4. 研究内容与方法

### 4.1 任务定义

研究输入由项目起点、出行方式、时间阈值、空间数据库集合、项目文档和分析问题构成。系统先生成等时圈，再在该范围内形成带版本的数据快照。输出不是法定规划方案，而是一份区域分析报告及其证据索引、指标表、诊断记录、图件和运行清单。报告中的事实性主张必须能够回溯到项目文档、数据库查询或计算结果；推断性主张必须标记条件与替代解释。

### 4.2 等时圈范围与数据契约

该模块接收起点、真实入口、出行方式和时间阈值，通过路网引擎生成等时圈几何。为识别范围定义带来的影响，系统同时保存输入坐标、路网版本、速度模型、时间阈值和几何修复记录。对于入口不确定的项目，采用候选入口敏感性分析，而不是将临时参照点当作真实入口。

所有数据查询均绑定等时圈与同一项目快照。POI 同时保留点落区、类别统计和按共同栅格聚合的结果；人口与夜光栅格按覆盖比例聚合；路网按等时圈裁切并计算网络结构指标，再按需要汇总到共同栅格；共同栅格用于跨数据源对齐和局部比较；H3 若启用，仅用于 POI 专项六边形聚合；项目文档按原文位置读取。每个结果保存数据集 ID、年份、坐标类型、记录数、查询参数、完整性状态和校验和。无法对齐的数据不做静默填补，而进入诊断清单。

### 4.3 数据库增强的多智能体分析

多智能体层不直接接收全部原始数据，而通过受控工具按任务读取。范围与数据智能体负责检查等时圈、数据可用性和口径；供给与客群智能体分析设施结构、潜在使用者和替代供给；交通与空间智能体分析路网、入口、步行联系和空间异质性；项目文档智能体读取政策、权属、建筑和运营约束；综合智能体处理定位、产品、空间、运营、财务和分期之间的冲突。智能体输出区分数据库事实、文档事实、模型推断和待核验项。

当前 N8N 工作流作为参考实现，保存任务状态、章节输出、引用、诊断和质量门槛，并支持失败恢复。MultiCa 可用于探索另一种编排方式，但不被写入方法定义。只要其他平台实现相同的数据契约、工具接口、状态模型和评价协议，也应能够复现研究方法。

### 4.4 报告装配与质量控制

报告生成分为证据准备、章节分析、跨章节综合、图件设计和最终装配。章节生成前固定可用的数据与文档证据，成文后执行四类检查：范围检查验证指标是否属于目标等时圈；数值检查将报告数字与数据库结果重算比对；一致性检查识别章节之间的定位、对象、年份和建议冲突；边界检查识别把代理变量写成需求、客流或因果机制的表述。未通过检查的章节进入修订或标记为证据不足，不能通过增加文字掩盖缺口。

```mermaid
    A[项目位置、入口与出行参数] --> B[网络等时圈与范围诊断]
    B --> C[多源空间数据库查询]
    C --> D[坐标、网格、年份与统计口径对齐]

```

## 5. 实验设计与评价方案

### 5.1 案例与数据组织

长沙县政府旧址作为种子案例，用于冻结任务定义、数据契约和错误类型。后续评价集按城市形态、设施密度、路网连通性、数据完整性和项目类型选择异质案例。正式案例数量不在 proposal 阶段凭经验指定，将在预实验获得运行方差和专家评分方差后确定；原则上评价集至少覆盖中心城区、一般建成区和边缘区三类空间条件，并保留独立案例作为测试集。

每个案例固定项目材料、数据库版本、模型版本、提示词版本和计算预算。步行等时圈作为主设置，并选择不同时间阈值进行敏感性分析。只有数据许可和网络参数充分时才扩展至骑行或驾车模式。

### 5.2 基线与消融

| Condition | Evidence access | Agent structure | Purpose |
|---|---|---|---|
| B0 文本生成基线 | 项目摘要，无结构化空间查询 | 单智能体 | 检验纯语言生成能力 |
| B1 静态证据包 | 相同数据被压缩为一次性文本或表格 | 单智能体 | 区分数据库实时查询与信息注入 |
| B2 单智能体工具版 | 与完整方法相同的数据库工具 | 单智能体 | 检验专业分工的增量 |
| B3 无状态多智能体 | 相同工具，无持久化状态与质量门槛 | 多智能体 | 检验状态与治理机制 |
| M 完整方法 | 等时圈、多源数据库、持久化状态、质量门槛 | 专业多智能体 | 目标方法 |

如果 MultiCa 能够在相同模型、输入、工具权限和预算下运行，可作为 B3 的一个实现；若条件不匹配，其结果只进入定性案例讨论。范围消融另行比较网络等时圈、等面积圆形缓冲区和行政单元，观察边界选择对数据统计与报告结论的影响。

### 5.3 评价指标

| Dimension | Operational measure |
|---|---|
| 空间一致性 | 空间事实遵守目标范围、坐标、年份与聚合口径的比例 |
| 数值正确性 | 可审计数字与数据库重算结果在容差内一致的比例 |
| 证据可追溯性 | 事实性主张能够定位到数据查询、项目文档或计算结果的比例 |
| 分析完整性 | 预定义有效分析维度的覆盖率，排除重复段落与无证据扩写 |
| 跨章节一致性 | 对象、范围、数据和核心判断的矛盾数量及严重度 |
| 边界纪律 | 将代理指标误写为需求、客流、因果或财务事实的次数 |
| 重复稳定性 | 相同条件重复运行时事实、排序和关键判断的一致程度 |
| 专家可用性 | 规划专家对可信度、解释力、可复核性和决策支持价值的盲评分 |
| 成本与恢复 | 时间、模型调用、token、失败率和恢复后状态正确性 |

自动指标由数据库查询和规则校验生成，并抽样人工复核。专家评审隐藏系统来源，原则上由不少于 3 名具有城市规划或空间分析经验的评审者独立完成；预实验后确定正式样本量、评分量表与一致性指标。统计分析优先报告效应量和置信区间，并使用能够控制案例差异和重复运行差异的分层或混合效应模型；不以单一显著性检验代替实际差异解释。

### 5.4 压力测试与失败模式

研究将主动测试四类困难条件：POI 分类缺失或过密、人口与夜光年份不一致、路网断裂或入口错误、项目文档相互冲突。每类条件分别观察系统是否拒绝无效查询、暴露诊断、降低主张强度或错误地产生确定性建议。方法成功不仅表现为生成正确报告，也包括在证据不足时停止、降级或明确请求核验。

## 6. 预期方法贡献

1. 建立以等时圈为统一范围契约的报告生成方法，使所有空间数据、指标和叙事判断能够追溯到同一可达范围。
2. 建立数据库查询先于规划解释的分层结构，区分空间计算、事实提取、模型推断和最终成文。
3. 建立面向区域分析的专业多智能体状态模型，使不同章节共享结构化阶段结论而不是反复压缩长文本。
4. 建立兼顾空间正确性、证据可追溯性与规划可用性的报告评价协议，并通过基线与消融识别各模块贡献。

这些贡献均为研究目标，不在实验完成前写成已证实优势。创新边界也不依赖 N8N、MultiCa 或某一特定模型品牌，而取决于方法接口和评价协议能否被复现。

## 7. 前期基础与可行性

当前项目已经具备等时圈、POI、H3、路网、人口、夜光、项目文档与报告导出等分析能力，并建立了 N8N、PostgreSQL、空间工具和模型调用之间的工作流。参考工作流包含 90 个节点，能够保存步骤状态、证据、诊断、租约和最终报告。2026-08-14 的运行 `825d012f-3585-4acf-babf-2e26bc94b80e` 完成 12 个分析步骤，生成约 59,218 字符的数据库报告、Word/Markdown 文件和 4 张项目数据图件。相关领域测试能够检查工作流节点连接、代码节点编译、工具契约、状态恢复和报告装配。

这些基础降低了从零建设系统的风险，使研究可以把资源集中到方法冻结、基线控制、自动评价和专家实验。但当前证据仍有三个限制：只有一个主案例；成功运行时间较长；报告质量尚未经过盲评和数据库级系统审计。因此，前期基础证明的是“可以开展研究”，不是“研究假设已经成立”。

## 8. 风险、边界与替代路线

| Risk | Impact | Mitigation / fallback |
|---|---|---|
| 不同案例数据覆盖差异过大 | 无法公平比较报告 | 建立最低数据准入标准，并单独报告缺失数据压力测试 |
| 等时圈入口或路网不可靠 | 范围错误传导至全文 | 入口敏感性分析、路网版本记录和范围诊断；无法确认时降级为探索性范围 |
| 模型和提示词差异混淆方法效果 | 无法归因数据库或多智能体贡献 | 固定模型与预算，采用模块消融而非平台品牌比较 |
| 多智能体增加篇幅但不增加有效分析 | 完整性指标被虚高 | 按有效问题和可核验主张计分，同时记录重复与矛盾 |
| 专家评分主观 | 方法评价不稳定 | 盲评、统一量表、培训样例与评审一致性分析 |
| 自动校验遗漏语义错误 | 数值正确但判断错误 | 自动指标与专家评审并行，抽样复核证据链 |
| 完整方法未优于单智能体 | 核心假设不成立 | 报告无增益结果，识别有效模块并收缩为数据库增强单智能体方法 |

研究结论只适用于具备可用路网、明确范围参数和最低数据覆盖的项目级区域分析。它不验证真实客流、商业收益、政策合法性或最终设计效果，也不替代现场调查、公众参与和法定规划程序。

## 9. 研究计划

| Phase | Months | Main work | Gate |
|---|---:|---|---|
| 方法冻结 | 1-2 | 固定任务定义、数据契约、术语、错误类型和评价量表 | 同一案例可重复生成并完成自动审计 |
| 基线与消融实现 | 3-4 | 建立 B0-B3 与完整方法，匹配模型、输入和预算 | 每个条件可独立复现 |
| 预实验 | 5-6 | 种子案例重复运行、专家试评、修订指标 | 指标可操作，专家评分具有基本一致性 |
| 跨案例评价 | 7-9 | 异质案例、范围敏感性和缺失数据压力测试 | 获得完整实验矩阵与失败记录 |
| 分析与复核 | 10-11 | 数据库重算、统计分析、错误归因和专家复核 | 每个主张可追溯到实验结果 |
| 论文与发布 | 12 | 完成论文、方法文档、评价集说明和可复现材料 | 不含未验证主张，复现实验通过 |

## 10. 预期成果

1. 一套多源空间数据库增强的等时圈区域分析方法及参考实现。
2. 一套包含案例输入、运行清单、自动指标、专家量表和失败类型的评价协议。
3. 关于等时圈、数据库工具、多智能体分工和质量门槛各自作用的实验结果，包括无增益或失败结果。
4. 一篇面向城市计算、GeoAI、规划支持系统或智能体应用方向的方法论文。
5. 可供后续项目复用的数据契约、报告契约和诊断规范。

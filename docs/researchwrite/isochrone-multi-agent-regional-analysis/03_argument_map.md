# Argument map

## Scientific tension

- What is known: 等时圈能够表达网络时间可达范围，多源空间数据能够刻画城市设施、人口、道路结构和活动代理；规划领域模型和地理空间智能体也已证明数据库检索、专门工具与工作流表示具有价值。
- What is unknown: 现有研究尚不能回答，项目级城市空间智能体如何在持续对话和复杂决策任务中约束空间范围，按需查询、校验和综合多源空间证据，并把稳定判断复用于多种成果。
- Why the gap matters: 如果空间范围、工具执行、数据口径和证据到判断的转换不受控制，智能体可能给出语言流畅但空间关系、计算顺序或决策依据错误的答案与成果。

## Central research question

在相同项目输入和模型条件下，以项目范围和网络等时圈约束空间语境，通过受控领域工具持续获取多源空间证据，并以可恢复的决策状态组织复杂任务，能否提高城市空间决策智能体的工具执行正确性、空间一致性、证据可追溯性、决策连贯性和成果可用性？

## Central thesis

本研究假设，城市空间智能体的有效性不在于增加生成篇幅、提示词或智能体数量，而在于把任务理解、空间范围构建、领域工具执行、证据核验、专业判断和成果交付组织为可追溯、可恢复的任务链；该假设需要通过多类型任务集、匹配基线、模块消融、重复运行和专家盲评验证。

## Supporting arguments

### Argument 1: 等时圈提供可计算的共同空间边界

- Claim: 真实网络等时圈能够把设施、人口、道路和夜光数据约束在同一可达范围内，并暴露入口、路网和阈值对结果的影响。
- Evidence: [1] 及当前项目的等时圈分析链路。
- Limitation: 等时圈仍依赖起点、入口、出行方式、速度和路网数据质量，不代表真实到访。

### Argument 2: 数据库工具能够把空间事实与语言解释分开

- Claim: 先完成结构化查询与指标计算，再由智能体解释结果，有望降低数值漂移、范围混用和无来源判断。
- Evidence: [2]、[5]、[7] 及当前工作流中分离的 `analyze_spatial_question` 空间认知编排层、`compute_spatial_evidence` 确定性计算层、项目文档分页读取、决策备忘录与最小来源持久化能力。
- Limitation: 工具存在不等于模型会正确调用，必须评估调用正确率和静默错误。

### Argument 3: 专业决策单元能够组织复杂城市空间任务

- Claim: 将供给、客群、交通、空间、运营和风险等问题组织为边界明确的专业决策单元，并保存稳定领域状态，有望提高复杂任务覆盖、决策连续性和多成果复用能力。
- Evidence: [6] 与当前 12 步工作流的端到端成功运行。
- Limitation: 分工可能引入重复、冲突和成本，必须与单智能体及无状态版本比较。

### Argument 4: 城市空间智能体能力可以被拆解并测量

- Claim: 城市空间智能体不应只由“回答像不像专家”或“报告是否完整”评价，而应通过任务完成率、工具执行正确率、空间范围符合率、证据支持度、决策矛盾率、交互质量和专家盲评共同评价。
- Evidence: [3]、[5]、[7] 提供了基准化和证据级评价先例。
- Limitation: 专家可用性仍包含主观判断，需要预先定义量表并报告评审一致性。

## Counterarguments / alternative explanations

1. 产出改善可能主要来自更长提示词、更高模型预算或更多生成轮次，而非数据库和多智能体结构。研究将匹配模型、输入、预算并记录调用成本。
2. 报告更长可能被误判为更完整。评价将以覆盖的有效问题、可核验事实和矛盾数量为单位，而非字符数。
3. 单一长沙案例可能对系统有利。研究将加入不同城市形态、不同等时圈阈值和数据缺失条件下的压力测试。
4. 规划专家偏好可能影响盲评。研究将使用多名评审、隐藏系统来源并报告一致性。
5. MultiCa 产出较弱可能来自实现配置差异。其结果只能作为探索性基线，不能支撑普遍方法结论。

## Final move

proposal 请求批准的不是“城市空间智能体已经能够自主规划”这一既定结论，而是一套检验其空间取证、工具执行、决策组织和成果交付能力的方法、任务集与评价协议。

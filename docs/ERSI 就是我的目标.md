# ESRI / MAPC 式区域深度画像报告：当前目标与数据应用方案

## 1. 目标重定义

当前目标不是让 AI 做一份能力边界审计报告，而是：

```text
用现有地理、人口、POI、夜光、路网、文档和图片证据，
尽可能完整地描绘一个区域，
生成类似 Esri Business Analyst / MAPC 的区域深度画像报告。
```

也就是说，报告的主叙事应该是正向的区域画像：

- 这个区域是什么类型。
- 它的空间边界和活动腹地是什么。
- 人口与活动基础如何。
- 商业供给结构如何。
- 热点、轴线、机会区在哪里。
- 更适合发展哪些商业方向。
- 对应的策略、落位和实施资源如何组织。

证据边界仍然重要，但它不应该占据主报告。边界和限制应放在：

- 方法说明。
- 附录。
- 模型状态表。
- 数据质量说明。

最终报告应读起来像一份正常的区域研究报告：先讲区域是什么、商业如何组织、机会在哪里，再把方法口径放到报告后部。

## 2. 产品目标

项目目标应表述为：

> 本项目要做一个 AI-native Business Analyst / MAPC 区域深度画像报告生成器。系统先定义分析范围，再对当前范围进行数据增强，随后用商业地理模型组织 POI、H3、人口、夜光、路网和外部来源证据，最终生成可汇报、可导出、可继续追问的区域画像报告。

核心不是“AI 自由写总结”，而是：

```text
Define Area
-> Data Enrichment
-> Regional Profile Models
-> Opportunity Category Screening
-> Report Spec
-> PPT / PDF / Web Report
```

## 3. 报告应长什么样

主报告建议采用以下结构：

```text
1. Executive Summary
2. Analysis Scope / Trade Area
3. Regional Context and Activity Base
4. Commercial Supply Structure
5. Spatial Pattern and Hotspots
6. Population and Customer Proxy
7. Opportunity Category Screening
8. Priority Directions
9. Strategy Application / Implementation Resources
10. References / Method Notes / Data Appendix
```

注意：

- 正文要尽量描述区域。
- 主体段落避免反复讨论证据边界。
- 限制只在必要处轻提示，集中放到 Method Notes。
- 如果证据只能支持 proxy，就在措辞上使用“活动基础、需求 proxy、客群线索、预筛方向”。
- 不把报告结尾写成“下一步清单”。完整报告应以结论、策略应用、资源线索、方法和附录闭合。

## 3.1 MAPC 完整报告给本项目的启发

`Pocket-Parks_Revere-REPORT_072219_FINAL.pdf` 的价值不在于它的主题是公园，而在于它的报告形态非常接近本项目目标。它不是一段 AI 回答，也不是一个“还需要什么数据”的说明，而是一份完整的专业技术报告。

该报告的结构是：

```text
Cover
Acknowledgements
Contents
Introduction
Project Overview
Guiding Framework
Alignment with Municipal / Regional Goals
Literature Review
Methods
Results of Analysis
Funding Sources
References
Appendices
```

这说明 MAPC 式报告的完成感来自四件事：

| 报告部件 | 作用 | 本项目对应 |
| --- | --- | --- |
| Introduction / Project Overview | 先定义研究对象和任务边界 | 区域背景、分析范围、报告目的 |
| Guiding Framework | 建立判断价值框架 | 商业活力、空间结构、客群基础、更新潜力 |
| Methods | 把指标、权重、模型讲清楚 | Trade Area、POI/H3/人口/夜光/路网模型 |
| Results of Analysis | 给出排序、地图、表格和解释 | 商业画像、热点格、机会方向、优先级 |
| Funding / Resources | 把结果接到现实可执行资源 | 招商方向、更新资源、政策/规划/运营抓手 |
| References / Appendices | 承载来源、口径和补充材料 | EvidenceNode、数据字典、方法说明、图表附录 |

因此，本项目的报告不应以“下一步执行路线”作为主体结尾。更好的收束方式是：

```text
结果应用
-> 适合发展的方向
-> 优先级与空间落位
-> 可利用的政策、规划、招商或运营资源
-> 方法说明
-> 数据附录
```

如果需要保留扩展动作，也应写在方法说明或实施建议里，作为报告应用的一部分，而不是让读者感觉报告还没有完成。

## 4. 标准五步工作流

### Step 1：Define the Area

目的：确定报告分析对象。

本项目可用数据：

| 数据 / 能力 | 当前基础 | 报告用途 |
| --- | --- | --- |
| 等时圈 | `modules/isochrone/` | 定义步行 / 车行可达范围 |
| 自定义范围 | 前端选区、历史 `scope_polygon` | 定义 user-defined trade area |
| 当前范围数据源 | `modules/scope_datasets/` | 保证所有分析指标限定在当前范围 |
| 地图快照 | `visual_snapshots` | 报告封面、范围图、专题图 |

主报告表达：

```text
本报告以当前选定范围作为分析 trade area，用于观察区域内商业供给、人口活动基础、空间热点和潜在业态方向。
```

方法附录再说明范围是否经过 primary / secondary trade area 校准。

### Step 2：Data Enrichment

目的：把范围从一个几何图形变成一个可分析的区域。

本项目已有的数据增强来源：

| 数据 | 可描绘的区域特征 |
| --- | --- |
| POI | 商业供给、功能结构、业态 mix、锚点设施 |
| H3 / 栅格 | 商业密度、热点、机会格、空间集聚 |
| 人口 | 居住基础、需求基底、客群 proxy |
| 夜光 | 夜间活动、活力 proxy、晚间场景线索 |
| 路网 | 可达性、动线、过境/停留关系 |
| 文档 / 网页 | 规划、政策、项目背景、品牌和外部资料 |
| 图片 / 地图快照 | 可见空间结构、图层状态、视觉证据 |

报告中应把这些数据写成区域画像语言：

```text
POI 描绘供给结构。
H3 描绘空间分布。
人口描绘需求基底。
夜光描绘活动节奏。
路网描绘到达与串联能力。
外部来源描绘背景和约束。
```

### Step 3：Regional Profile Models

目的：把数据组织成分析模块。

建议使用这些模型：

| 模型 | 作用 | 输出 |
| --- | --- | --- |
| `TradeAreaModel` | 定义分析范围和覆盖口径 | 区域边界、范围类型、覆盖状态 |
| `MarketPotentialModel` | 描绘人口和活动基础 | 需求 proxy、活力基础、活动强度 |
| `CommercialSupplyModel` | 描绘商业供给结构 | 业态 mix、强势业态、弱势业态 |
| `SpatialPatternModel` | 描绘空间结构 | 热点、机会格、轴线、组团 |
| `CustomerProxyModel` | 描绘潜在人群场景 | 学生、社区、办公、游客等 proxy |
| `OpportunityCategoryScreeningModel` | 回答“适合做什么” | 候选业态方向、适配理由、优先级 |
| `SiteSuitabilityModel` | 点位适宜性筛选 | 候选点 / 候选格排序 |

这里的关键是：开放式区域报告不应先要求用户指定目标业态。系统应该先通过 `OpportunityCategoryScreeningModel` 生成候选方向。

### Step 4：Custom Report Building

目的：把模型结果组装成可汇报报告。

本项目已有基础：

| 报告资产 | 当前基础 | 应用方式 |
| --- | --- | --- |
| 地图 | 前端地图、H3、人口、夜光、路网图层 | 范围图、热点图、专题图 |
| 图表 | ECharts、H3 histogram、category distribution | 业态结构、密度分布、趋势说明 |
| 表格 | scoped dataset aggregation | 业态表、机会方向表、数据附录 |
| 证据 | EvidenceNode | 引用来源、支撑判断 |
| PPT | `modules/ppt_planning/` | 生成可汇报页面 |
| 导出 | `modules/export/` | PDF / 数据附录 / Web report |

报告生成不应是：

```text
AI answer -> 直接转 PPT
```

而应是：

```text
EvidenceNode / scoped datasets
-> Model Results
-> Report Spec
-> PPT / PDF / Web Report
```

### Step 5：Export & Share

最终输出形态：

| 输出 | 用途 |
| --- | --- |
| Markdown Report | 快速查看、追问、迭代 |
| PPT | 汇报、课程展示、人工调整 |
| PDF | MAPC 式正式报告 |
| Web Report / Dashboard | 可交互展示 |
| Excel / Data Appendix | 指标复核和底层数据 |

## 5. 现有数据如何用于描绘区域

### 5.1 POI：描绘商业供给

POI 是当前最重要的商业供给数据。

它可以用于：

- 业态结构。
- 头部业态。
- 功能混合度。
- 商业锚点。
- 同类供给密度。
- 机会业态初筛。

报告表达重点：

```text
这个区域由哪些功能构成？
哪些业态塑造了区域气质？
哪些业态已经强，哪些业态相对轻？
```

### 5.2 H3 / 栅格：描绘空间结构

H3 是区域内部结构的核心表达。

它可以用于：

- 商业热点。
- 机会格。
- 局部熵。
- 密度梯度。
- 多核心 / 单核心 / 弱中心结构。
- POI、人口、夜光、路网的同格分析。

报告表达重点：

```text
商业活动是集中在少数核心，还是均匀铺开？
哪些格子是高密度高混合？
哪些地方可能是机会区？
```

### 5.3 人口：描绘需求基底

人口用于描绘区域的基础需求。

它可以用于：

- 常住人口规模。
- 人口密度。
- 性别 / 年龄结构。
- 居住支撑。
- 社区型商业基础。

报告表达重点：

```text
这个区域有没有足够的日常消费基底？
它更像社区型、校园型、办公型，还是混合型？
```

### 5.4 夜光：描绘活动节奏

夜光用于描绘夜间活动 proxy。

它可以用于：

- 夜间活跃程度。
- 夜间热点。
- 白天 / 夜间场景差异。
- 夜间轻休闲机会。

报告表达重点：

```text
这个区域是否有晚间活动基础？
夜间活力是全域铺开，还是少数热点集聚？
```

### 5.5 路网：描绘可达与动线

路网用于描绘区域的连接和承载能力。

它可以用于：

- 集成度。
- 选择度。
- 连通度。
- 主轴 / 支路。
- 过境型道路和停留型界面。

报告表达重点：

```text
商业是否被道路有效串联？
是过境流量强，还是内部停留强？
哪些路径适合形成连续消费界面？
```

### 5.6 EvidenceNode / 外部来源：描绘背景

文档、网页、图片和资料包用于补充系统数据之外的背景。

它可以用于：

- 政策和规划背景。
- 项目定位。
- 周边竞品资料。
- 现场图片。
- 报告中的引用和解释。

报告表达重点：

```text
区域为什么会形成现在的结构？
未来有哪些规划或项目会改变它？
外部资料如何解释系统指标？
```

## 6. 当前历史区域的正向画像示例

当前历史资料显示：

- POI 总量约 3991。
- H3 网格 645。
- 平均 POI 密度约 448.4/km2。
- 餐饮 1431。
- 科教文化 586。
- 购物 525。
- 住宿 317。
- 公司 263。
- 交通 247。
- 人口约 9.1 万。
- 夜光均值约 31，峰值约 52。
- 路网节点 6386，边段 7100。
- 平均集成度约 0.678。
- 结构信号点 177，机会区 127。

这组数据可以描绘出一个比较清晰的区域画像：

```text
这是一个高密度、文教属性明显、餐饮供给强、生活消费基础稳定的混合型片区。
它的商业不是空白状态，而是已经形成较成熟的日常消费网络。
机会不在于泛泛增加商业面积，而在于围绕文教、青年、社区生活和轻量夜间活动做细分业态组合。
```

### 6.1 商业供给画像

餐饮数量最高，说明区域的日常消费和即时消费基础很强。科教文化和购物构成第二层供给，说明区域不只是生活服务区，也有文教、学习、轻休闲和文化消费基础。

这类区域适合发展“小尺度、高频、复合”的商业，而不是依赖单一大型商业锚点。

### 6.2 空间结构画像

H3 网格数量较多，POI 密度高，同时存在结构信号点和机会区，说明商业不是单点孤立，而是在多个局部单元中形成活动簇。

报告中可以把它描述为：

```text
多组团、局部热点、可继续筛选机会格的商业片区。
```

### 6.3 人群和活动画像

人口约 9.1 万，为社区和日常消费提供基础。科教文化供给较强，叠加夜光活动 proxy，说明学生、青年、社区居民和轻社交场景值得重点关注。

这类区域的机会不是高客单奢侈消费，而是：

- 高频。
- 停留。
- 复合。
- 社区化。
- 文教关联。

### 6.4 适合发展的方向

| 方向 | 适配度 | 依据 | 报告表达 |
| --- | --- | --- | --- |
| 学生 / 青年轻餐饮细分 | 高 | 餐饮强、文教强、人口稳定 | 做细分，不做泛餐饮 |
| 咖啡 / 茶饮 / 自习复合空间 | 高 | 文教、夜光、停留场景 | 适合作为轻社交和学习延伸 |
| 文创零售 / 书店 / 展陈消费 | 中高 | 科教文化强、购物有基础 | 适合承接文教人群 |
| 社区生活服务 | 中 | 人口基础稳定 | 适合补充高频生活服务 |
| 轻运动 / 健康管理 | 中 | 体育供给相对轻 | 可作为细分机会验证 |
| 夜间轻休闲 | 中 | 夜光有活动基础 | 适合轻量导入和验证 |

### 6.5 主报告表达规范

系统需要保留证据边界，但主报告的表达应采用专业报告口径：

| 写作位置 | 表达方式 | 示例 |
| --- | --- | --- |
| 主报告正文 | 描述区域现象和商业判断 | `区域呈现高频生活消费与文教场景叠加特征。` |
| 模型解释 | 使用 proxy 语言连接证据和判断 | `夜光与餐饮集聚共同指向晚间轻休闲基础。` |
| 机会建议 | 给出适合方向和空间落位 | `优先布局轻餐饮、自习复合空间和社区服务业态。` |
| 方法说明 | 说明数据口径和适用范围 | `本报告用于区域画像、商业方向判断和空间机会识别。` |

统一的方法说明可以写成：

```text
本报告基于 POI、人口、夜光、路网和空间网格数据形成区域画像，主要用于商业方向判断、空间结构识别和机会筛选。租金、经营表现、客流监测和投资测算属于经营测算模块，可作为独立专题报告接入。
```

## 7. MVP 报告生成目标

MVP 应优先实现：

```text
区域范围图
数据增强摘要
商业供给画像
空间热点和机会区
人口与活动画像
机会业态筛选
推荐方向
方法说明和数据附录
```

MVP 应默认生成正常报告，只在附录和方法说明中保留数据口径。

## 8. 最终目标表述

最终目标可以写成：

> 本项目要做一个 AI-native Business Analyst / MAPC 区域画像报告生成器。它不是用 AI 泛泛解释地图指标，而是把当前范围内的 POI、H3、人口、夜光、路网、文档、网页和图片证据转化成一份结构化区域深度报告。报告主线是描绘区域、解释商业结构、识别机会方向和组织可汇报成果；数据边界和限制保留在方法说明与附录中，不干扰主报告的正常阅读体验。

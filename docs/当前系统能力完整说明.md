# N8N 项目分析链路交接说明

更新日期：2026-08-18

本文记录当前正式链路。内容以仓库实现为准，不包含早期 `project_context`、`query_data`、前置 GraphRAG 和固定十二章方案。

## 1. 当前结论

正式链路位于 `n8n/workflow-generators/urban-renewal-agent.workflow.mjs`，主流程如下：

```text
项目输入
-> 规划 Agent 生成 decision_units
-> 逐单元运行证据路由和工具批次
-> 研究 Agent 生成 decision_memo
-> 综合 Agent 生成 report_blueprint
-> 写作 Agent 逐节生成报告
-> 图件、编辑、报告装配和投递
```

当前约束：

- `decision_units` 由规划 Agent 根据项目问题生成。数量不固定，32 是异常保护上限。
- 模型侧只注册 5 个证据工具。`history_id` 由 N8N 注入。
- 证据路由 Agent 每批返回 1 至 3 个独立请求。依赖调用跨轮执行。
- 每个决策单元最多执行 12 个工具请求。该限制不作用于研究、综合和写作 Agent 的推理。
- 空间距离分带已删除。可达性统一使用 Valhalla 时间等时圈。
- 完整工具结果只在执行期保存。成功状态不持久化工具正文和模型对话。

## 3. 数据和派生结果

### 3.1 项目空间事实

| 数据 | 事实源 | 主要字段或内容 | 运行依赖 |
| --- | --- | --- | --- |
| POI | 当前项目保存的高德或本地记录 | 名称、类别、子类、类型编码、地址、位置、年份、来源 | 当前项目已保存 POI 快照 |
| 人口 | WorldPop 100 米栅格 | 总人口和项目契约选取的年龄结构 | `POPULATION_DATA_DIR` 下存在对应年份文件 |
| 路网 | OSM/Overpass | 道路名称、等级、长度、节点和几何 | 采集阶段需要 Overpass；工具查询读取项目已保存结果 |
| 夜光 | 本地夜光栅格 | 辐亮度、热点、梯度、方向和年份 | `NIGHTLIGHT_DATA_DIR` 及有效 `manifest.json` |
| 项目范围 | 当前 history 记录 | 锚点、出行方式、时间阈值和保存等时圈 | 项目范围和中心点有效 |

所有查询绑定当前 `history_id` 和保存范围。模型不能提交数据库表、任意 Polygon、坐标系或原始字段名。

### 3.2 空间派生结果

| 派生结果 | 来源 | 用途 |
| --- | --- | --- |
| Valhalla contour | 项目锚点、出行方式和时间阈值 | `accessibility` 时间分带 |
| H3 | 项目范围和 POI | POI 密度、混合熵、邻域、Gi* 和 LISA |
| 共同规则栅格 | POI、人口、夜光和路网 | 跨数据源对齐和 `relationship` |
| 路网句法 | depthmapX 处理后的道路网络 | integration、choice、connectivity、control 和 depth |
| GraphRAG 索引 | 18 份登记 PDF | 文献 focused 检索和 synthesis |

派生结果可以重建，不是第二份事实源。完整几何留在后端计算和制图链路，不进入模型响应。

### 3.3 非空间资料

| 资料 | 当前处理方式 | 备注 |
| --- | --- | --- |
| 项目文档 | Docling 解析后由 `read_project_document` 分页读取 | 不进入 GraphRAG |
| 公共文献 | 12 篇开放论文和 6 份 UNESCO/ICOMOS 文件 | 原始 PDF 是事实源 |
| 实时网页 | AnySearch/Exa 搜索后读取正文 | 搜索结果只用于发现 URL |

GraphRAG 和互联网使用不同语料和检索链路。研究 Agent 可以在同一份 `decision_memo` 中使用两类结果。

## 4. 模型可见工具

`modules/spatial_projects/mcp_server.py` 当前只注册以下 5 个 `@mcp.tool()`：

| 工具 | 必填参数 | 主要返回 | 外部依赖 |
| --- | --- | --- | --- |
| `analyze_spatial_evidence` | `analysis` | 空间汇总、分组、高亮、具名记录、覆盖和限制 | 项目数据库；`accessibility` 依赖 Valhalla |
| `read_project_document` | `document_id` | Docling blocks、分页状态和正文 | 项目文档解析结果 |
| `search_literature_evidence` | `question` | 文献答案、原文证据和覆盖状态 | 本地 embedding/GraphRAG；synthesis 依赖完成模型 |
| `search_public_web` | `query` | 候选搜索结果 | AnySearch 或 Exa |
| `fetch_public_web_page` | `urls` | 网页正文、成功项和失败项 | AnySearch 或 Exa |

模型不能提交 `history_id`、`call_id` 或 `batch_index`。N8N 在执行前补齐这些字段。

## 5. 空间工具

### 5.1 七种模式

| 模式 | 参数要求 | 返回内容 |
| --- | --- | --- |
| `scope` | `metric_ids=[]` 用于目录发现；也可指定 1 至 4 个指标 | 数据状态、年份、支持模式或范围级结果 |
| `accessibility` | 1 至 4 个指标 | Valhalla 时间分带和各带指标 |
| `direction` | 1 至 4 个指标 | 八方向分组和代表记录 |
| `neighborhood` | 1 至 4 个指标及 `record_refs` | 邻域指标、连续性和邻接结果 |
| `rank` | 1 个指标 | Top K 或 Bottom K 记录 |
| `relationship` | 2 至 4 个指标 | P25/P75、共同高值、共同低值和冲突单元 |
| `inspect` | `record_refs`；指标可省略 | 具名 POI、道路、类别、地址和记录关系 |

`neighborhood` 返回邻域数值和结构。`inspect` 返回面向报告的具名对象和可读属性。不要用 `neighborhood` 代替记录展开。

### 5.2 Valhalla 口径

`accessibility` 使用项目锚点、出行方式和最大时间阈值。最大阈值为 15 分钟时，默认分为：

```text
0-5 分钟
5-10 分钟
10-15 分钟
```

空间服务在一次 Valhalla 请求中获取嵌套 contour。空间单元按代表点落入的最小 contour 归类。返回字段为：

- `travel_time_band_min`
- `travel_time_upper_bound_min`
- `travel_time_source=valhalla_isochrone_contour`

这些字段表示时间区间。`straight_line_distance_m` 只用于位置和方向识别。Valhalla 请求失败或 contour 不完整时返回 `unavailable`，不使用圆形 buffer 或直线距离回退。

### 5.3 关系分析

`relationship` 至少需要 20 个共同有效空间单元。当前实现只输出：

- 各指标 P25 和 P75。
- 共同高值单元。
- 共同低值单元。
- 指标信号冲突单元。

当前不计算相关系数、因果关系或综合机会分。缺失值不按零处理。

### 5.4 输出投影

空间服务统一返回：

```text
schema_version, status, analysis, scope, metrics, summary,
groups, highlights, relationship, coverage, evidence,
limitations, method, provenance
```

模型响应限制：

- 总字符数约 8,000。
- `groups` 最多 12 项。
- `highlights` 最多 20 项。
- `evidence` 最多 20 项。
- 递归删除 geometry、coordinates、features、数据库连接和本地路径。
- 字符串形式的 GeoJSON、WKT 和连接串同样删除。

N8N 在写入工作简报前再次压缩空间结果。具名记录单独保留名称、类别、地址、道路、`record_ref`、方向、时间带和指标值。

## 6. 其他证据工具

### 6.1 项目文档

`read_project_document` 参数：

| 参数 | 当前限制 |
| --- | --- |
| `document_id` | 必填，只能读取当前项目文档 |
| `start_block` | 从 0 开始 |
| `max_blocks` | 1 至 40，默认 20 |
| `page_start/page_end` | 可选，使用文档页码 |

单次字符预算为 10,000。工具保持 Docling block 原子性，不从段落或表格中间截断。返回 `complete=false` 时，下一轮使用 `next_start_block` 继续读取。

### 6.2 文献

`search_literature_evidence` 参数：

| 参数 | 当前限制 |
| --- | --- |
| `question` | 必填，最长 2,000 字符；不要包含未公开项目细节 |
| `mode` | `focused` 或 `synthesis`，默认 `focused` |
| `top_k` | 1 至 10，默认 6 |

`focused` 使用本地 Jina 768 维 embedding 和 GraphRAG LanceDB，直接返回 PDF 原文，不调用完成模型。`synthesis` 执行 GraphRAG 跨文档综合，并返回对应原文。两种模式不自动互相降级。

### 6.3 互联网

`search_public_web` 支持 `anysearch` 和 `exa`，返回候选结果。`limit` 为 1 至 10，默认 5。

`fetch_public_web_page` 一次最多读取 5 个 URL。`max_characters` 为 500 至 20,000，默认 5,000。AnySearch 返回逐页成功和失败项；部分页面成功时状态为 `partial`。

固定依赖关系：

```text
search_public_web -> fetch_public_web_page
```

路由 Agent 需要先取得真实 URL，再构造正文读取请求。

## 7. Agent 和状态

### 7.1 规划

规划 Agent 输出：

```text
research_frame
decision_units[]
```

每个 `decision_unit` 包含 `unit_id`、`title`、`question`、`depends_on`、`decision_output` 和 `evidence_focus`。工作流校验字段、ID 和依赖顺序，不修改单元语义和数量。

### 7.2 证据路由

路由 Agent 输入当前单元、依赖备忘录、项目资料目录、工作简报、最近结果和剩余预算。输出：

```json
{
  "decision": "continue",
  "reason": "...",
  "next_tools": [
    {"name": "analyze_spatial_evidence", "arguments": {"analysis": "scope", "metric_ids": []}}
  ]
}
```

`continue` 必须包含 1 至 3 个请求。`finish` 必须返回空数组。代码只校验工具名、参数、权限、重复请求、并行数量和预算。

同批可并行：

- 参数已经确定的不同空间查询。
- 空间查询、项目文档首段和 focused 文献检索。
- 不同主题的互联网搜索。

需要跨轮：

- `scope(metric_ids=[]) -> 具体空间查询`
- `rank -> inspect`
- 当前文档块 -> `next_start_block`
- `search_public_web -> fetch_public_web_page`

### 7.3 研究

工具循环结束后，研究 Agent 生成当前单元的 `decision_memo`：

```text
decision
alternatives_considered
reasoning
key_facts
named_entities
implications
```

研究 Agent 不调用工具，不写正式章节。依赖单元已经成立的结论作为输入使用，不在当前单元重复证明。证据不足时，备忘录记录无法判断的部分和停止原因。

### 7.4 综合和写作

所有单元完成后，综合 Agent 根据 `decision_units` 和 `decision_memos` 生成 `report_blueprint`。报告节数由综合结果决定，可以合并或拆分决策单元。

写作 Agent 每次只接收当前报告节、相关备忘录、必须保留的事实和具名对象。它不接收完整工具历史，也不重新调用工具。

图件和最终编辑位于报告完成之后。图件生成取决于空间结果和渲染条件；飞书投递取决于请求参数和运行配置。

## 8. 工具批次和上下文

| 项目 | 当前值 |
| --- | --- |
| 单批并行请求 | 最多 3 个 |
| 每个决策单元工具请求总数 | 12 个 |
| 工具 HTTP 超时 | 180 秒 |
| 章节上下文预算 | 24,000 token |
| 成稿预留 | 6,000 token |
| `working_research_brief` | 约 14,000 字符，最多 16 张卡片 |
| `named_spatial_records` | 最多 20 条，约 4,200 字符 |
| `research_result_store` | 运行期最近 24 个去重完整结果 |

每批结果按 `batch_index` 排序后合并。一项失败不丢弃同批成功项。整批失败才增加连续失败计数。

跨轮重复请求返回 `duplicate_request`。旧 `function_call_output` 不继续进入模型对话；下一轮只接收初始上下文、工作简报和最近结果。

停止条件：

- 上下文接近 24,000 token，保留 6,000 token 给研究输出。
- 当前单元达到 12 次工具调用。
- 连续整批工具错误达到限制。
- 连续没有新证据达到限制。

停止取证后仍执行研究 Agent。现有证据不足时，`decision_memo` 记录限制，不补造结论。

## 9. 持久化和清理

成功执行长期保留：

- `research_frame`
- `decision_units`
- `decision_memos`
- 最小来源元数据
- `report_blueprint`
- 报告节、最终报告和图件状态
- 飞书投递状态

成功执行不长期保留：

- 完整工具正文
- 路由模型对话
- 旧 `function_call_output`
- 嵌套执行状态

失败执行保留排障所需诊断。N8N execution history 按运行环境的清理策略删除。不要手工清空 `runtime/`、`tmp/` 或 `.codex-tmp/`，这些目录可能包含仍需保留的运行结果。

## 12. 修改联动

### 12.1 修改工具参数

按以下顺序检查：

1. 领域服务请求模型和校验。
2. `mcp_server.py` 工具签名。
3. N8N tool schema、允许字段和路由校验。
4. 工具结果压缩和工作简报投影。
5. MCP、领域、N8N 生成测试。
6. 重新生成并导入正式 workflow。

Demo 阶段直接收敛到单一契约。除非明确要求，不保留旧字段、双字段读取和模型侧兼容入口。

### 12.2 增加空间指标

需要同时补齐：

1. 指标语义和单位。
2. 数据源绑定、数值字段、聚合规则和支持模式。
3. 缺失值和覆盖处理。
4. 模型响应投影。
5. 指标发现、模式执行和输出安全测试。

不要把新指标直接塞进路由提示词。路由 Agent 通过空指标 `scope` 读取当前目录和运行状态。

### 12.3 增加数据源

先确定唯一事实源和重建路径，再增加适配器。空间数据需要明确几何类型、坐标、年份、稳定 `record_ref`、对齐策略和可用模式。文献资料继续进入现有 GraphRAG corpus，不建立第二套检索链路。

# Codex 原生分析编排

本文件只定义正式报告的时序和每个波次的可核验产物；字段、版本限制、接受依赖、审校内容、章节长度、装配和视觉前置条件以 `report-contract.md` 为唯一事实来源。这里不复制索引 schema 或质量门槛。

正式综合报告使用“问题驱动研究 -> 六段方案推导 -> 专业章节纵向循环 -> 全稿分析审校 -> 总编裁决与出版装配”。专业 Subagent 对自己的章节及其中决策负责，主 Agent 负责语义、逻辑依赖和总编裁决。专项研究只为当前推导节点提供证据，不能自行确定报告目录或先行锁定方案。

## 波次 0：事实底稿、问题地图与逻辑图容器

读取授权原件、范围、数据集目录和指标目录，以及项目类型适用的前置事实底稿；文旅相关项目同时读取 `cultural-tourism-theme-research.md`。将结果写入项目语义模型、问题地图、决策逻辑图、决策与证据空容器以及 manifest。项目语义模型和问题地图记录材料冲突、口径修正、选择、候选解释、证据和反证；决策逻辑图保留待填充的规则容器。调研底稿只提供事实、候选关系、约束和待验证项；主题、场景和运营设想在问题地图确认后进入决策比较。

以自然 Markdown 展示“项目理解 -> 需要共同确认的问题地图 -> 拟开展的证据研究 -> 请确认或修订上述问题地图”，并以用户确认作为专项指标、工具调用和 Subagent 分派的解锁信号。

**完成条件：** 五项状态工件和 `state/manifest.json` 已使用同一快照建立；项目语义模型与问题地图已完成，决策逻辑图、决策与证据容器为空；问题地图状态为 `awaiting_confirmation`，用户已看到完整问题地图。

## 波次 1-3：问题驱动的专项研究

确认后先按 `value-path.md` 建立一条候选价值路径，再按 `decision-rulebook.md` 建立候选规则节点。主 Agent 先锁定 R1 的目标结果与核心矛盾，并以其结果限制 R2 的项目角色与关键能力；R2 再限制 R3 的价值承诺，R3 依次限制 R4 部署样板、R5 空间运行边界和 R6 一期部署与学习闭环。研究备忘录和报告直接引用项目材料或原始公开页面及访问日期，不要求导入外部来源体系。规则节点只记录上游判断、事实、条件、候选与反例、当前动作、下游问题和验证条件，共同服务于该价值路径；空间指标仅在改变节点动作时作为带有推断边界的 `metric_refs` 写入。

### 波次 1：市场、客群与内部空间

完整读取并以 `market_discovery` 执行 `$spatial-market-audience-research`。它先建立项目条件和候选客群，再并行验证市场母体、客源圈与流向，竞争供给与市场缺口，以及需求与支付/履约，最后由目标客群与行为综合师形成唯一的目标客群、排除项、行为断点和产品任务。稳定结果保存为 `report/research/spatial-market-audience-research.md`。

市场公开检索覆盖统计、政策规划、文保档案、片区供给、直接及区域竞品、文化机构或机构采购、公开价格与活动。每类先检索原始查询；页面失效、摘要为空或无结果时，继续执行行政区与主题重组查询及机构/来源替代查询。三轮仍无可用来源才登记 `searched_no_usable_source`，并把缺失的项目级记录转成参数和校准动作，不能提前退为观察计划。

空间结构分析师与市场研究并行处理项目内部入口、连接、停留、流线、承载和现场断点。外部客源圈、游客或使用者流向和市场到达频率由市场 Skill 拥有，空间结构分析师不重复判断。

### 波次 2：定位与产品策略

定位与产品策略师只消费已确认问题、资源主题底稿、完成的市场客群报告和内部空间结构研究，以“资源主题 × 已验证目标客群 × 内部空间承载”比较真实候选路径。目标客群、行为断点和产品任务作为上游结论，不在本波次重新猜测。

### 波次 3：空间、运营与市场再校核

空间功能策划师和运营与分期策略师并行形成具体空间产品与运营方案初稿。随后完整读取并以 `product_recheck` 再次执行 `$spatial-market-audience-research`，逐产品校核客群覆盖、容量、价格或价值交换、收入成本、运营主体和分期，保存 `report/research/spatial-product-market-recheck.md`。

首次校核要求调整时，将意见分别退回定位、空间或运营所有者形成新版本，再进行第二次且最后一次校核。仍不成立的内容转为条件性验证、远期保留或退出。市场 Skill提供成立、缩减、验证后实施或退出建议；主 Agent 在波次 4 作最终裁决。

**完成条件：** 每个已确认问题均有研究备忘录、可追溯的项目材料或公开来源、比较基准和反证结果；两份市场研究稳定报告已形成；所有进入波次 4 的产品已有成立、缩减、验证或退出建议。无法由项目材料回答的问题先完成公开检索；仍无直接记录时，将其转成带参数范围、失效条件和校准动作的条件性建议，而不是中止正式报告。

## 波次 4：决策底稿与章节责任

主 Agent先完成 `report/state/decision-logic-map.json` 的 `value_path`，按 R1 至 R6 裁定每个规则节点为 `supported`、`conditional` 或 `excluded`，再处理市场再校核建议。所有能改变项目路径的节点均进入 `report/state/decision-inventory.json`，并在证据摘要中记录每项判断使用的来源和标签：直接证据、公开检索证据、代理推断、情景假设或待验证。`supported` 形成当前建议；`conditional` 形成条件性建议，附参数、验证和退出条件；`excluded` 或证据不足而不可比较的路径形成暂不建议和取证动作。R2 的角色选择登记其对部署样板的能力后果。R6 必须登记一个目标使用者、触发、服务、承接空间、运营主体、资源优先级和真实记录相互匹配的部署样板，并将即时产出、近期结果、观察窗口和复制/调整条件写回价值路径。每项重要决策只有一个章节所有者；章节边界按决策关系组织，数据类型进入拥有相应决策的证据包。责任图写入 `report/chapter-index.json`，其具体字段遵守 `report-contract.md`。

**完成条件：** `value_path` 覆盖受益者、基线、目标结果、部署样板、输出、结果、影响、假设、时间窗口和复制/停止记录；每个规则节点都有条件、结论、候选或反例、行动、证据、推断边界和改判条件；每项重要决策都有唯一所有者、候选取舍、证据 ID、反例、能力要求和改判条件；每张条件性建议卡都有事实输入、参数范围、推演规则、输出范围、失效信号和校准记录；manifest 中的状态摘要与实际文件一致。

## 波次 5：专业章节纵向循环

章节所有者沿用自己的证据包生成 v1，依次经过反方审查、分析深度审校和定向返写。每个版本分别生成 `.adversarial.md` 与 `.depth.md` 审校文件，按 `report-contract.md` 的 frontmatter 契约记录 verdict；单行 `accepted` 不是有效审校。初稿加最多两次返写，版本文件不覆盖旧稿。

**完成条件：** 每个接受章节的最新版本同时通过反方和深度门槛，`chapter-index.json` 的状态、版本、依赖和字符审计可由校验器复核。

## 波次 6：全稿审校与定向返写

所有章节接受后，反方审查员和分析深度审校员读取全部接受版本、已确认的 `problem-map.json`、`decision-logic-map.json`、`decision-inventory.json` 与证据摘要，检查跨章冲突、隐藏前提、代价、失败场景和改判路径。意见路由到拥有相应决策的章节作者，由作者以新版本闭合。

**完成条件：** 全稿意见逐项裁定并闭合；受影响章节生成新版本并重新通过逐章门槛，超过 v3 或仍有重大问题即停止交付。

## 波次 7：总编裁决与出版装配

总编读取 `publication-editorial.md`、全部接受章节、`decision-logic-map`、`decision_inventory` 与证据摘要，完成该文件定义的出版核对与定向返写循环。出版层完成后，按 `report-contract.md` 装配 `report/project-report.md` 与 `report/decision-logic-map.md` 并运行：

正文必须让读者顺序读出“目标结果与核心矛盾 → 项目角色与关键能力 → 定位与价值承诺 → 部署样板工作流 → 空间运行边界 → 一期部署与学习闭环 → 复制与扩展决策门”。内部研究底稿服务于该链路，不形成第二读者出口。授权、消防、居民协商、成本、许可和退出条件只在改变部署样板、资源优先级或复制决策处出现，并在相关章末与最终实施验证门追溯。

```text
python skills/spatial-business-analyst/scripts/validate_chapter_assembly.py --report-dir <report-directory>
```

装配校验通过后进入视觉渲染和导出。

**完成条件：** `publication-editorial.md` 的出版核对完成，`report-contract.md` 的装配校验通过。

## 波次 8：独立视觉证据编辑

装配通过后，每次正式报告都启动独立视觉证据编辑 Subagent。它只读取通过验收的报告、状态文件、接受章节索引、本轮同一项目、范围和年份的真实持久化指标及视觉清单；主 Agent、章节作者与渲染器都不兼任视觉策划。视觉、锚点和题注只能出现在章节标记之外，生成后重新运行装配验证和视觉来源校验；具体视觉规则遵守 `report-visual-workflow.md`。不得复制历史报告资产；零视觉只在所有候选均无当前数据、批准模板、有效锚点或决策价值时成立。

**完成条件：** 所有 planned 项均已生成、插入并通过来源和校验和验收；所有 omitted 项均有具体原因；Markdown、manifest 与实际文件双向一致，视觉资产可追溯且不改变接受正文。

## 简单任务边界

简单问答、单项诊断和局部分析直接完成，不创建正式报告状态、章节版本或审校目录。只有用户要求完整项目报告、正式综合报告或同等深度成果时才进入上述波次。

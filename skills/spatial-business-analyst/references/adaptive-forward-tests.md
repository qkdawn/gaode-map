# 自适应报告前向测试

每次修改报告契约后，用以下五类最小材料包分别运行 Skill。测试材料中的名称应每次替换，避免模型记忆示例词汇。

| 场景 | 最小输入 | 应自然展开 | 不应出现 |
| --- | --- | --- | --- |
| 单体商业选址 | 单一铺位、候选商圈、POI、步行范围 | 选址判断、供给关系、店型/服务和验证 | 多建筑组团、居民或文旅模板 |
| 多对象历史更新 | 多个具名载体、保护条件、使用冲突 | 原名对象关系、定位比较、分对象承载和阶段 | 未提供的院落或花园 |
| 开放式滨水空间 | 线性边界、公共活动、生态与到达条件 | 线性关系、使用时段、生态/运营协同 | 强行生成建筑再利用章节 |
| 产业或办公园区 | 企业、员工服务、通勤、配套和分期 | 生产/办公支持、服务缺口、组织与实施机制 | 强行套用游客或文化展陈定位 |
| 社区服务或小型文旅 | 服务对象、空间资源、内容和运营条件 | 实际使用者、服务/内容组合、可逆试验 | 固定四阶段或不存在的交易指标 |

统一验收：

- 首次输出是待用户确认的问题地图，不是正式大纲或当前定位；确认前不启动专项研究；
- 问题地图按决策问题组织，包含候选解释、所需证据和反证，不出现人口分析、POI 分析或路网分析等预设章节；
- 多对象且存在共存约束的项目覆盖定位选择、替代路径、共存冲突、空间系统、运营承接和推翻条件；简单项目不机械补齐六项；
- “文化生活”等方向只能作为候选假设；当反证成立时，能够降级为条件性方向或被真实替代方案取代；
- 章节责任只在专项研究和 `decision_inventory` 完成后生成，并围绕定位、取舍、空间系统、运营能力和实施条件等实际决策组织；最终标题、顺序和目录随接受章节自然形成；
- 所有对象来自材料并在正文保留原始名称；
- 内部语义角色没有替换项目名称；
- 不同场景产生不同章节深度、对象层级和视觉选择；
- 每项关键决策解释项目特有机制、相对优势，以及会改变判断的反例或失败条件；
- 空间、产品和运营建议说明实际代价、承接能力缺口、路径依赖与改向或退出方式；
- “判断、证据、方案、动作和验证”形成真实推理关系，不以字段齐全代替分析；
- 正式综合报告为每个专业章节保存独立 Markdown 初稿、对应审校文件和 `chapter-index.json`；简单任务不产生这些产物；
- 每个重要决策只有一个章节所有者，共享证据不产生重复所有权；下游章节只消费上游接受版本；
- 每个影响决策的实质章节都经过反方挑战，重大意见回到原作者定向返写并生成新版本，不覆盖旧稿；
- 初稿加最多两次返写；v3 仍不合格时阻止交付，不由主 Agent 接管正文；
- 专业章节通常为 1,500-3,000 个中文内容字符，长度越界只告警，分析义务决定接受；
- 最终报告吸收成立的反例和改判逻辑，但不展示反方审查原文或内部裁定；
- `project-report.md` 使用章节边界标记逐字完整包含所有接受版本，主 Agent 只增加摘要、过渡和综合结论；
- 主 Agent 删除段落、改写论证或压缩接受章节时，装配验收必须失败；
- 正文没有通用免责声明、重复限制或为凑篇幅生成的段落；
- 没有固定页数、图数或章节完成条件，PDF 自然分页且不按每个标题强制一章一页；
- 删除任一主要章节时，可以指出因此丢失的决策闭环；
- 视觉只使用目录当前批准且有真实数据支撑的模板。

## 对抗性深度测试

以下草稿即使事实、年份、范围和代理边界全部正确，章节也完整，仍必须退修：

> 周边生活设施成熟，项目具有特色空间，因此推荐文化生活方向，不建议通用商业。三个空间分别安排展示、活动和服务。首期开展活动并记录参与情况，效果不佳时及时调整。

退修原因不是缺字段，而是没有解释文化生活为何相对更优、空间选择各自代价、方向失败条件、内容与现场运营能力缺口，以及调整会停止什么、保留什么、付出什么成本。审校员必须把问题退回定位、空间和运营分析，不能通过补充“存在风险”或“建议专业运营”判为合格。

以下类型的分析可以通过深度门槛，且不需要编造数值阈值：

> 推荐方向由核心资产需要持续解释、周边通用供给已成熟和项目需要重复使用三项条件共同成立。若内容无法持续更新或重复使用只由无关消费支撑，则收缩为预约展示，不继续扩张内容空间。首期只开放可独立运行的空间与产品，因为现有团队缺少多空间排期和现场协调能力；固定改造与长期合作延后，保留缩减开放范围和终止扩张的能力。

通过原因是分析给出了项目条件之间的机制、可推翻结论的反例、能力约束对顺序的影响以及可执行的改向路径，而不是因为段落更长。

## 反方审查对抗测试

面对以下结构完整但单边论证的章节，反方审查不能返回“无重大反方意见”：

> 推荐文化生活方向，因为核心资产具有文化特色，周边也有稳定生活人群。首期设置展示、活动和服务空间，通过持续运营形成复合体验。

有效的反方意见至少应指出：同一事实也可能支持低频展示加日常服务，而不必支持持续内容运营；章节把“具有文化特色”直接等同于“能够持续生产可重复内容”；展示、活动和服务同时开放依赖尚未证明的排期、履约与现场协调能力。这些问题可能降级定位并缩小首开范围，必须由定位、空间和运营分析共同回应。

以下章节已经实质回应反方意见，可以通过反方审查，不得为凑数量继续制造反对：

> 核心资产只有在能够转成可重复内容时才支持文化生活方向；若它只能一次性观看，则定位收缩为预约展示加日常服务。首期不同时开放全部空间，只运行一条可独立履约的内容路径，并记录内容更新与重复参与；在团队具备多空间排期和现场协调能力前，不增加固定设施或长期合作。若重复使用主要来自与核心内容无关的消费，则停止扩张内容空间并重新判断服务应作为配套还是独立业务。

通过原因是章节回应了替代定位、隐藏假设和能力障碍，并让反方意见实际改变首开范围与改判逻辑。原始反方意见和裁定仍只保留在内部审校中。

## 章节纵向循环对抗测试

将开头的浅显草稿放入一个 1,500 字以上章节，即使事实、来源和格式全部正确，深度审校仍必须返回 `revision_required`。字数不能掩盖以下缺口：证据没有形成项目特有机制、没有与真实候选方案同口径比较、空间动作没有代价、运营动作没有能力前提、失败后没有缩减或退出路径。

返写验收必须同时观察文件和责任连续性：

- v1 审校不通过后，由同一章节所有者基于原证据包生成 `chapters/<id>.v2.md`；
- `chapter-reviews/<id>.v1.md` 与 v1 原稿保留，索引记录两版及各自状态；
- 下游角色在 v2 接受前保持等待，不读取 v1 摘要继续写作；
- 若 v2 仍有定向问题，可生成 v3；不得生成 v4 或由主 Agent 代写接受稿。

## 主编压缩对抗测试

准备一个已经接受、包含机制、反例、代价和退出条件的章节。主 Agent 合编时分别尝试删除一段、改写一句、用两段摘要替代全文或把章节拆散重组。四种情况都必须由 `validate_chapter_assembly.py` 判为失败。只调整章节顺序、在边界标记外添加过渡、执行摘要和综合结论，并逐字保留接受正文时才能通过。

## 模式边界测试

对同一材料分别提出“附近供给有什么缺口”和“生成完整项目综合报告”。前者应直接回答问题，不创建 `chapter-index.json`、章节版本或 1,500-3,000 字符要求；后者必须执行章节所有权、纵向返写、全稿审校和低损耗装配。不能因 Skill 支持正式报告，就把所有简单任务扩张成长报告。

# 主题提示词完整性契约

每次运行必须完成以下十个阶段，不得以资料不足、省略某类资源或未形成主题为由跳过。证据不足的事实写“待验证 + 原因 + 验证动作”；主题、场景和运营仍须作为合理推断或策划假设提出，不补造事实。

## 补充研究工件

项目范围或用户问题涉及周边、网页或档案研究时，可建立 `research-coverage-ledger.md`、查询日志、分层周边对象表和主张登记表，作为补充证据工件。它们不替代项目资料资源表，也不是进入任何提示词阶段的前置门槛；未闭合项在最终报告中标“待验证”，但不能阻断后续十阶段。

| 阶段 | 强制产物 | 最低验收 |
| --- | --- | --- |
| 1. 资源全面收集 | 八类资源表 | 每行包含编号、名称、类别、位置、时期、人物/群体、内容、资料名称与页码/网页原文定位、保存状态、当前使用、独特性、可体验性、待验证问题 |
| 2. 核心资源筛选 | 五维评分表和核心/支撑/背景/谨慎清单 | 真实性、独特性、关联性、转译性、延续性逐项 1-5 分；说明评分证据而非只给总分 |
| 3. 五类共同关系 | 历史、空间、社会、生产生活、地方价值五个分析单 | 历史写因果/时间链；空间写节点、路径、历史与当代流线、断裂及序列；社会写群体—机制—空间；生产生活区分历史/传统/当代/可转化/不可表演化；价值写资源来源、形成机制与可感知空间行为 |
| 4. 资源关系网络 | 关系边表和节点角色表 | 每条边有起点、终点、类型、方向、时期、机制、证据强度、当代意义；明确核心、枢纽、起源、结果、断裂和可重建关系 |
| 5. 主题候选 | 3-5 个候选主题 | 每项写名称、叙事命题、资源支撑、共同机制、独特性、现实意义、适用边界、证据等级与待验证事项 |
| 6. 主题评价与选择 | 十维评分和主/次/专题/不建议分类 | 资源覆盖、历史真实性、关系解释、独特性、空间转译、游客理解、活动产品、当代价值、运营延展、保护一致性逐项评分；无法选主叙事必须说明原因 |
| 7. 叙事体系与故事线 | 主叙事→次叙事→故事线→片区主题→空间节点→场景类型，以及每个主/次叙事的故事线卡 | 每条故事线必须单独写明起点、发展、转折、高潮、延续、当代回应、时间范围、人物/群体、核心空间、核心事件、主要冲突、情感基调、游客理解价值；不可只给年表或把这些字段隐含在段落中 |
| 8. 叙事空间结构 | 总体结构、序列、节点、路径和层级 | 明确叙事类型及理由；每个节点必须单列主题、资源、叙事内容、游客行为、空间类型、展示/体验、昼夜差异、活动、运营主体；主/次/居民/夜游/节庆/雨天淡季路径逐条设计，或逐条裁定不适用并说明替代安排、原因和验证动作；说明路径交叉与分散客流方式 |
| 9. 核心场景 | 8-12 个完整场景卡 | 一场景对应一个可识别节点，逐项覆盖提示词的 20 个字段；第 9 项分别写视觉、听觉、触觉、嗅觉、味觉，不能以“氛围”或笼统词替代；缺少资源或约束时填“待验证”、风险和验证动作，不把假设写成事实 |
| 10. 运营转化 | 逐场景的叙事主题—空间场景—活动—业态—运营关系表与运营判断 | 每场景一行，不合并场景或压缩必填列；列出上位主题、子主题、故事线、空间节点、游客行为、活动内容、对应业态、运营主体、收益方式、更新周期、保护风险、实施优先级；另逐项判断功能、常设/周期、付费、专业团队、居民/商户/传承人/企业参与、淡季夜间、维护成本与安全、真实性和过度商业化 |

## 最终输出纪律

严格使用提示词规定的十二部分和顺序。将检索日志及来源主张登记表作为研究工件链接到相应主张，不插入或替换这十二部分。主题、场景和运营必须提出；上游关系与保护约束尚未确认时，将其写为策划假设，附证据等级、待验证事项、风险与验证动作。

1. 核心结论用 300-500 字说明核心资源、共同机制、最适合的主叙事和可形成的叙事空间体系。
2. 资源清单与分级同时列出核心、支撑、背景和待验证资源。
3. 五类共同关系分析覆盖历史过程、空间关系、社会机制、生产生活方式和地方价值观。
4. 资源关系网络输出关键关系链及最重要的资源组织机制。
5. 候选上位叙事主题输出 3-5 个候选及其完整证据。
6. 主题评价与最终选择确定 1 个主叙事、2-4 个次叙事和若干专题叙事；无法形成单一主叙事时说明原因，不伪装为已选定。
7. 叙事体系输出主叙事、次叙事、故事线、片区主题、空间节点和场景类型的层级关系。
8. 叙事空间结构输出总体结构、游线和空间节点体系。
9. 核心叙事空间场景至少提出 8-12 个，并逐项覆盖提示词的 20 个场景字段。
10. 场景与运营转化表说明每个场景如何形成活动、业态、产品和运营机制。

第十一部分必须逐项指出：证据充分的历史关系、合理推断、策划假设、待补资料、主题过度包装风险，以及可能破坏真实性或影响居民的场景。第十二部分必须按“项目资源 → 核心资源筛选 → 资源关系 → 共同历史或社会机制 → 上位叙事主题 → 子主题和故事线 → 空间结构 → 叙事场景 → 活动和业态 → 运营与传播”闭合逻辑链。

交付前逐项检查：主叙事是否解释多数核心资源，是否强行纳入资源，主题是否来自真实关系，历史过程和机制是否清楚，子主题与节点是否分工，场景是否可感知参与并可长期运营，事实/推断/策划创意是否区分，以及是否考虑文保、生态、消防、居民和运营约束。任一项不满足时，修正后再输出。

## 后半段字段模板与硬性检查

第七至十阶段不能仅因标题、编号或表格存在而视为完成。将每个空缺写为“待验证 + 原因 + 验证动作”，但不得省略字段或使用“同上”“见总述”“按实际情况”代替。

若原始项目材料正文未取得或项目本体身份未识别，第一部分、资源表和主题选择必须将“项目本体身份待验证”作为前提；外部网页与 POI 仅可形成范围背景候选。此情形下不得用周边对象替代项目本体、形成项目级主叙事或承诺项目实施；仍输出完整后半段，但所有主题、节点、场景和运营均标为范围背景的 `H/V`，并列出取得原始材料、权属/文保建档或现场核验的前置动作。

### 故事线卡

在第七部分以 `### 故事线卡` 输出表格。对主叙事和每个次叙事各输出一张卡：`叙事层级｜名称｜起点｜发展｜转折｜高潮｜延续｜当代回应｜时间范围｜人物/群体｜核心空间｜核心事件｜主要冲突｜情感基调｜游客理解价值｜证据/边界`。专题叙事若进入场景或运营，也必须有同样的卡。

### 节点与路径清单

在第八部分以 `### 节点与路径清单` 输出两张表。为所有场景建立节点表：`节点｜对应主题/故事线｜资源依据｜叙事任务｜游客行为｜空间类型｜展示/体验方式｜日间｜夜间｜活动｜运营主体｜证据/边界`。另为主游线、次游线、居民日常、夜游、节庆、雨天/淡季各建立一行：`路径｜适用条件｜起点—节点—终点｜交叉/分流方式｜开放与安全边界｜不适用时的替代安排｜验证动作`。

### 场景卡

严格保留 20 个编号字段。第 9 项以 `视觉｜听觉｜触觉｜嗅觉｜味觉` 分项填写；没有合理的感官内容时写“无新增设计，保留现状 + 原因”，不得虚构。第 10、11、12、16—19 项必须说明真实依据或标为策划假设与验证动作。

### 逐场景运营判断

第十部分先以 `### 场景与运营关系表` 输出 12 列：`上位主题｜子主题｜故事线｜空间节点｜游客行为｜活动内容｜对应业态｜运营主体｜收益方式｜更新周期｜保护风险｜实施优先级`；每个场景一行。再以 `### 逐场景运营判断` 为每个场景补一行：`场景｜主要功能｜常设/周期/节庆｜付费可能｜专业团队需求｜可参与主体｜更新周期｜淡季/夜间适用性｜维护成本与安全｜真实性风险｜过度商业化风险｜前置验证`。不得将这些判断只写在表后总述。

以下任一情况视为第七至十阶段未完成：故事线遗漏核心字段；节点表未逐节点展开；六类路径未设计或未逐条裁定；场景卡未分列五感；运营表合并多个场景、缺少必填列，或仅作全局运营判断。

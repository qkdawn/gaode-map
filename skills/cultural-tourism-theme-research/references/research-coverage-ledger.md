# 研究覆盖台账

## 目的

覆盖台账是项目周边与外部网页调研的辅助记录，用于说明检索范围与证据缺口；它不替代提示词规定的八类资源表，也不控制主题、场景或运营是否可以提出。

## 建账

当本轮涉及项目周边或外部网页调研时，按实际问题选择八类资源与项目本体、周边、城市关联背景的适用组合建立台账。直接周边优先由保存的项目边界、等时圈、服务范围、道路可达关系或项目材料说明界定；范围尚未成立时，标记为背景范围或“待验证”，不伪造红线或步行关系。

每个纳入台账的单元标注以下状态之一：

- `in_scope`：与项目问题、保护、空间、主题或运营判断相关，记录已采用的检索与核验动作。
- `out_of_scope`：项目已有明确范围或问题证明其不相关；记录理由和引用的项目约束。
- `not_applicable`：该资源类别在该圈层没有合理对象；记录为何不适用，不能使用“暂未搜到”。

`out_of_scope` 和 `not_applicable` 不是快速结束标记。项目资料不足以作出该裁定时，标为“待验证”并说明尚缺何种信息。

## 行格式

每个 `in_scope` 单元至少记录：

| 字段 | 要求 |
| --- | --- |
| 资源类别与圈层 | 八类之一与本体/步行周边/城市网络之一 |
| 研究问题 | 要验证的对象、关系或约束，不写泛化口号 |
| 空间与材料入口 | 地址、范围、别名、时间或 POI 类别；没有则明确缺口 |
| 发现检索 | 已使用的查询与候选来源池；外部检索可用时优先采用语义不同的查询 |
| 同源追溯 | `search_public_web` 返回的来源链接、已核验的名称/文号/附件，或无法读取原因 |
| 交叉追溯 | 使用新发现实体检索的来源类型、页面与比较结果 |
| 结案状态 | `confirmed`、`context_only`、`no_result_after_rounds`、`page_unreachable` 或 `claim_refuted` |
| 证据与边界 | URL、原文定位、来源等级、可说明范围 |
| 下一步 | 未闭合时的具体馆藏、机构、现场或访谈动作 |

## 关键主张

下列主张必须在覆盖台账之外进入主张登记表，并记录可定位的来源及证据等级：本体身份与年代、文保或历史建筑身份及范围、历史事件或人物关系、社区/机构合作、持续活动、游客需求、产权开放、消防与运营能力。优先以 `primary_source` 交叉核验；项目原始材料可支持其明确记载的内容，但不能外推其未记载的事实。

检索到媒体、百科或 POI 时，可将实体加入候选池，但不能单独提升为 `confirmed_relation`。项目原始材料须按其明确表述和引用定位分级，不因来源为项目材料而自动降为线索。

## 证据边界

覆盖台账仅用于说明外部补充研究的证据边界。每项主张依其实际来源写为“已有资料支持”“合理推断”“策划假设”或“待验证”，不建立会影响后续阶段的二元研究状态。

无论外部补充范围如何，都必须完成主题提示词的十个阶段和十二部分。后续主题、故事线、场景和运营可作为“合理推断”或“策划假设”提出；每项注明资源依据、缺口、验证动作和不可当作事实的边界。

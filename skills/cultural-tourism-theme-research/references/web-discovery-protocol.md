# 网页发现与追溯协议

本协议把“像网页端一样检索”定义为可执行流程。发现线索与确认事实必须分开：搜索结果、摘要、百科、媒体转述和地图页面可以发现别名与来源，但不能单独支撑主题、历史关系、人物、活动、居民认同或运营结论。

## 1. 检索轮次

对于需要外部核验的关键主张，记录查询词、渠道、结果池、实际读取页面和下一步。使用已注册的 `search_public_web` 建立候选来源池；其返回的标题、链接和摘要用于发现和交叉检索，摘要不能替代可核验原页内容。检索深度服务证据需要，不作为提示词后续阶段的门槛。

1. **广泛发现**：用 `search_public_web` 搜索项目全名、旧称、建筑组成、地址/街道、机构全称、可能年代和“文物/旧址/档案/地方志/馆藏”等自然语言组合；每个项目至少使用两种语义不同的查询。
2. **同源追溯**：对排名靠前且可能支撑关键主张的 URL，记录返回链接、发布主体、日期和摘要可支持的边界；原页、PDF、Word 或扫描件无法取得可核验内容时记为待人工追溯。
3. **交叉追溯**：以首次检索得到的准确名称、文号、人物、事件、机构和地址再用 `search_public_web` 检索政府、档案馆、地方志、博物馆、学术机构和经营主体页面，比较时间、地点和主张边界。

首轮没有可靠命中时，换用全称、简称、旧称、地址、建筑单体、文号或不同来源类型等查询，并记录已覆盖范围。页面打不开、需登录或无法核验时标为“待验证”，不能把搜索摘要当作已确认事实。

## 2. 浏览动作

先通过 Exa 的正文读取完成页面核验。浏览器只处理 Exa 无法读取而确有必要的搜索结果页、站内搜索、相关链接、附件、锚点、发布日期、下载或分页；终端 HTTP 请求仅作辅助。每个进入主张登记表的页面记录标题、URL、发布/更新日期、访问日期、原文定位、空间范围和可说明边界。

## 3. 来源池与分级

先保存候选来源池，再逐项判断：

- `discovery_lead`：摘要、搜索结果、百科、媒体、POI；只提供别名、线索或待追溯链接。
- `context_source`：同城规划、机构介绍、行业资料；可说明背景，不证明项目直接关系。
- `primary_source`：政府公告、文物建档、档案/地方志/馆藏原页、机构原始项目页、现场或授权访谈；可在原文范围内支撑事实。
- `contradictory`：与其他来源冲突或被原始来源否定；保留冲突，不自行择一。

页面打不开、正文缺失或只能看到摘要时，不能转成已确认事实。可读取且直接支持主张的项目材料、原始来源、现场或授权访谈可作为事实依据；背景资料和线索应按其能说明的范围使用，不能外推为项目直接关系。

## 4. 未命中分类与停止条件

检索日志记录尚未检索、未发现可核验资料、页面无法打开或主张被反证等不同情况；任何未核验主张均标“待验证”，不得把未检索或未命中写成事实不存在。

停止条件不是“找到一条官方页”，而是已完成本轮问题所需的合理核验，或明确记录仍未闭合的主张及下一次取证动作。无论哪种结果，都应保留来源与未命中项；它们不阻断主题、场景和运营的提出。

## 5. 与外部补充研究的连接

网页发现、主张登记和周边对象表可并行建立、持续更新。一个周边对象的空间依据和关系证据分别记录；仅有距离、名称或同类设施密度时，只能作为待验证的空间线索，不写成已确认的历史、社会或运营关系。

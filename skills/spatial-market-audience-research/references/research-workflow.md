## 研究原则与证据等级

严格沿用以下推导链：

```text
项目条件
→ 候选客群假设
→ 市场验证
→ 目标客群确定
→ 客群深度分析
→ 产品任务与候选业态
→ 产品市场再校核
```

每一步说明决策问题、数据用途、数据边界、阶段结论、下一步影响以及已证实与仍为假设的内容。项目资源只能提出客群假设；行业趋势只能说明值得研究；城市人口或游客总量不能直接等同于项目客流；一般兴趣不能替代真实使用、采购、支付或复购。

核心结论至少由两类独立证据交叉支持。优先使用近 3-5 年资料；特殊事件、节假日和异常期间单独说明。证据等级为：

| 等级 | 含义 |
| --- | --- |
| A | 两类以上独立直接证据一致，支持近期行动 |
| B | 直接证据与支持证据一致，仍需项目级验证 |
| C | 机制合理但关键直接证据缺失，仅作方向性假设 |
| D | 当前证据不足，不进入近期方案 |
| E | 直接证据与假设相反，排除当前路径 |

人口表达居住背景，POI 表达设施供给，夜光表达辐亮度，路网表达模型可达性。搜索热度、平台评价和标杆案例只提供线索或机制参照，不单独证明需求、经营表现或项目转化。

公开资料在本次研究中打开原始页面，引用标题、链接、发布或更新日期、访问日期和适用范围。外部网页保留为本次调研的直接证据，不导入项目数据库，也不要求转成 `SourceRecord` 或 `EvidenceNode`。

正式综合报告的桌面研究至少覆盖统计、政策规划、文保档案、片区供给、直接及区域竞品、文化机构或机构采购、公开价格与活动七类来源。每个类别按“原始查询 → 行政区与主题重组查询 → 机构或来源替代查询”最多执行三轮。单个页面 404、失效、正文为空或一次查询无结果时继续下一轮；三轮后仍无可用来源才记录 `searched_no_usable_source`，同时保留查询词、尝试状态和不可取得的项目级字段。

无法公开取得的项目级客流、订单、支付、许可、成本、容量或运营记录不阻止完成候选比较。它们进入显式参数、范围、推演规则、结果范围、反证、停止条件和校准记录；不得用城市总量、POI、人口、夜光、模型可达性或标杆案例替代这些记录。

## 第一步：项目条件识别

联合项目原件、主题底稿、空间范围和可用指标，建立条件矩阵：

- 区位与交通：城市和区域位置、真实交通时间、公共交通、自驾、末端接驳、拥堵和既有流线。
- 空间与用地：面积、建筑、室内外与全天候空间、停车后勤、生态文保消防和建设强度。
- 资源与供给：自然、文化、产业、社区、品牌、周边目的地和现有服务。
- 政策与任务：上位规划、公共服务、产业、保护、投资和指定服务对象。
- 运营基础：现有使用者、到访与停留、收入成本、运营主体、招商、内容和履约能力。

每项条件说明对客群的支持和限制、可能频率、停留、产品、价格或价值交换以及运营后果。阶段结论给出可能的服务半径、使用频率、活动类型、不适合方向和当前未知项。

## 第二步：候选客群假设

只从项目条件提出候选，不直接命名目标客群。按空间来源、同行或组织结构、使用动机和经营/服务作用交叉形成长名单；候选数量跟随项目复杂度，不为凑数补齐标签。

每项记录：候选客群、提出依据、可能来源、交通时间、停留时间、核心任务、可能消费或价值交换、项目匹配条件、反证和待验证问题。按高、中、低和暂不验证排序。

## 第三步：市场验证

围绕候选客群并行完成三路验证。

### 市场母体、客源圈与流向

先按项目类型验证所在城市、区县或服务区域的市场母体。选择会改变当前客群判断的人口或组织规模、游客或使用量、收入与相关支出、平均消费、一日/过夜或短时/持续使用结构、停留时间、季节性以及工作日/周末/节假日差异，判断流量池、消费或采购能力、居民/游客/组织市场主导关系、住宿或夜间基础和旺淡季依赖。宏观母体只能限定市场上限和结构，不能直接等同于项目客流。

再按项目实际尺度选择 30、60、90、120 分钟或更长圈层，验证常住/工作人口、家庭或组织数量、交通方式、真实时间、拥堵、到访频率、既有流线、集散节点和自然经过条件。时间圈只能说明可能到达，不能直接说明选择本项目。

### 竞争供给与市场缺口

比较近端直接竞品、区域竞品和仅作机制参照的标杆。记录距离、车程、服务对象、产品、价格、容量、经营状态、评价与差评、更新频率、空置/停业、竞争或互补关系。机会同时要求客群存在、供给缺口、项目差异、可达、价值交换和运营承接成立。

### 需求与支付/履约

区分真实使用或消费、订单/预订/采购、付费测试、明确意愿、一般到访意愿和兴趣表达。验证频率、最近行为、交通时间、同行结构、偏好、预算或采购条件、价格、住宿/持续使用、复购/复访和拒绝原因。没有直接证据时设计小规模验证，不用搜索指数替代。

## 第四步：目标客群确定

目标客群准入同时检查：规模或服务对象真实存在、可以到达、有明确任务、当前供给未充分满足、与项目资源匹配、具备支付/采购/使用依据、项目可以承接、承担明确经营或服务作用。

用同一尺度比较规模、可达、频率、停留、支付或价值、任务强度、资源匹配、竞争、稳定性和运营可获取性。将通过者分为基本盘、增长盘、稳定使用盘、传播/战略盘；未通过者进入排除项，并说明是市场、距离、竞争、承载、支付还是运营原因。

## 第五步：目标客群与行为链

避免宽泛标签。对每类目标客群说明人口/组织阶段、同行结构、来源、交通方式、时间预算、到访时段、频率、动机、消费或价值交换、障碍和持续使用条件。

按实际项目建立行为链：

```text
需求产生 → 信息/组织决策 → 到达 → 进入 → 核心使用
→ 休息或配套 → 二次使用/消费 → 离开 → 分享/复访
```

逐环节识别需要、项目缺口、流失点、价值形成点和复访条件，形成客群决策卡与行为断点。

## 第六步：产品任务与候选业态

先由行为断点定义产品任务，如引流、进入识别、解释、参与、休息、餐饮、服务、夜间、住宿、复访、产业收益或社区收益。每项任务说明服务客群、解决断点、时间、空间、季节、重复使用和验证条件。

独立使用本 Skill 时，可以把通过验证的产品任务转成候选产品和业态，并说明经营主体、收费或价值交换、收入/资金来源、成本、空间、容量门槛、风险和阶段。作为 `$spatial-business-analyst` 的输入时，只交付产品任务；具体定位、产品和空间由主分析综合裁决。

## 第七步：产品市场再校核

只校核已经形成的具体产品、空间和运营草案：

1. 客群与组合覆盖：明确每项产品服务谁、覆盖哪些时段和是否承担复访；检查多个产品是否争夺同一小客群、产品之间是否互补，以及适用的工作日/周末/节假日、白天/夜间和旺季/淡季是否存在结构性缺口。没有明确客群的产品降级或退出。
2. 市场容量：仅在参数有来源时计算保守、基准、乐观情景；否则给出范围、记录方法和验证门槛。
3. 空间容量：比较交通、停车、服务设施、体验场地、住宿、生态、安全、居民和后勤承载。
4. 价格与价值：区分愿意体验、愿意支付/采购、按拟定条件支付和重复购买/使用。
5. 单位经济：在存在依据时核算收入或资金来源以及人工、材料、能耗、维护、营销、渠道、更新、管理和税费。
6. 分期：分为近期成立、缩减测试、验证后扩展、远期战略和退出。

定位草案先返回完整 `product_inventory`：`status=draft`，每项含稳定的 `product_id` 与 `name`。输出每项产品的成立条件、失败信号、改判触发器以及对定位、空间、产品或运营所有者的定向返写要求。第一次校核使用相同的完整 `product_id` 集合，并返回 `first_product_recheck`：`status=first`，每项含 `product_id`、`verdict`、`rationale`、`revision_required` 和 `owner_roles`。`owner_roles` 为空时不得返写；非空时只返写列出的责任角色。

唯一一次定向返写后执行第二次校核，返回 `final_product_recheck`：`status=final`，每项含 `product_id`、`verdict`、`rationale` 和 `conditions`。第二次的产品 ID 集合必须与第一次完全一致；仍不成立的产品直接缩减、条件化、延后或退出，不启动第三次返写。

首次校核要求调整时，将问题分别退回定位、空间或运营所有者；修订后进行第二次且最后一次校核。第二次校核仍不成立的内容进入条件性验证、远期保留或退出，不启动第三次校核。产品市场再校核分析师提出建议，主 Agent 作最终裁决并写入 `decision_inventory`。

## 项目类型适配

- 文旅/休闲：使用游客、OTA、锚点景区、住宿、季节和旅游线路；城市游客量逐层验证到项目转化。
- 商业：使用常住与工作人口、商圈、直接竞品、价格、订单、转化和复购。
- 社区/公共服务：使用服务人口、真实使用、政策任务、机构采购和服务履约，不强制商业支付或住宿指标。
- 园区/办公：使用企业、员工、通勤、采购、工作日需求、配套缺口和组织承接，不套用游客标签。

只启用会改变当前决策的验证项。项目跨类型时并列适用机制，不把所有指标机械填满。

## 输出与自检

`market_discovery` 按以下结构输出：项目条件、候选客群、市场母体、客源圈与流向、竞争与缺口、需求与支付、目标及排除客群、客群决策卡、行为断点、产品任务、风险和验证缺口。

`product_recheck` 按以下结构输出：产品清单、客群覆盖、容量情景、空间承载、价格/价值交换、收入成本、成立/缩减/验证/退出建议、定向返写、分期和改判触发器。

当调用方要求情景推演且直接市场数据不足时，输出不得止于“缺数据”：使用已确认事实构造可比较的情景卡。每张卡至少包含服务对象、空间和运营安排、事实输入、可调参数及其范围、推演规则、结果范围、反证或停止条件、下一轮校准数据。人口、POI、夜光和路网只可作为空间条件或参数边界，不能直接转成客流、支付、收入或 ROI。

交付前检查候选与目标是否区分，市场验证是否围绕候选展开，目标是否具备可达、需求和价值依据，产品是否对应行为断点，规模是否经过容量与成本校核，事实与假设是否区分，是否存在先有答案后找证据的确认偏差。
